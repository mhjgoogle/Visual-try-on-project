# Target Workflow Walkthrough — 在 LibTV 上做出一个视频，实际需要哪些步骤

**日期** 2026-08-16 · **方式** 用用户自己的登录态真实点进每一个 tab / 节点 / 面板，
逐个记录它提供什么。截图 T-001…T-065，登记见
[screenshots.md](../manifests/screenshots.md)。

这份文件回答两个问题：

1. LibTV 上「做出一个视频」的**真实步骤链**是什么；
2. 同一条链在 **motv Studio** 上是什么样子，差在哪。

---

## 1. LibTV 的产品公式

> **工作区 → 多块画布 → 节点。**
> **每个节点自己就是一个完整的生成器：Prompt + 参考 + 模型 + 规格 + 价格 + 提交。**
> **节点之间连线 = 上游产物喂给下游。**
> **Agent 是一个常驻会话，用 `/skill` 调能力、用 `@` 引用节点 / 分组 / 模型。**
> **同一份数据有两个视图：`工作流`（画布，制作面）⇄ `故事板`（清单，审阅面）。**

### 层级是三层，不是两层（更正，T-99 / T-100）

我第一轮写的是「一个项目 = 一块画布」。**错了**，实测：

| 层 | 入口 | 操作 |
| --- | --- | --- |
| **工作区** | 顶栏 logo 旁 `▾` | 回到主页 / 全部项目 / 创建新项目 / 删除项目 |
| **画布** | 第二个 `▾`（T-99） | 面板标题「画布」+ **`⊕` 新建画布** + 画布列表（当前项打勾） |
| **节点** | 画布内 | — |

**一个项目下可以开多块画布。** 所以「一集一块画布」是这个模型下的正常用法，
规模问题不成立 —— 我之前「48 集照抄 = 6000 节点」的推论作废，见 §5。

## 2. 从零到一条视频 —— 实测步骤链

### Step 0 · 新建项目（T-08）

点左栏 `＋ 新建项目` → **没有任何表单、没有对话框、没有命名步骤**，
直接打开一块空画布，标题占位 `未命名工作区 / 画布 1`，URL 是
`liblib.tv/canvas?spaceId=…&projectId=…`。

空画布中央给出 **4 个起步工作流**：

| 起步卡 | 作用 |
| --- | --- |
| 故事脚本生成 | 剧本 → 结构化脚本 |
| 角色三视图 | 角色形象一致性 |
| 全能参考生视频 `SD 2.5` | 参考图 → 视频 |
| 音频生视频 `SD 2.5` | 音频 → 视频 |

> 这四张卡与我们 `index.html` 的 `.entrybar` 四个入口**一字不差**
> （故事脚本生成 / 角色三视图 / 首帧图生视频 / 音频生视频）——
> 我们的原型本来就是照它做的，但那条 entrybar 现在**已经不在 Studio 的创作路径上**。

### Step 1 · 剧本（T-52 故事脚本生成）

点「故事脚本生成」→ 画布上一次长出**两个相连的节点**：

```
[剧本] ──→ [脚本生成器]
```

- **剧本节点**：一段可直接双击编辑的富文本（示例是《我在盛唐写天下》，
  带 `类型 / 时长建议 / 基调 / 【序幕】【第一幕】…`）。提示语：**「双击剧本内容，可直接编辑或替换」**。
- **脚本生成器节点**：指令框「根据我上传的剧本生成一个完整的故事脚本」+
  模型 `GVLM 3.1` + **价格 `⚡6`** + 提交。

**关键**：剧本不是「一页」，是**画布上一个可编辑的对象**，可以被连线喂给任何下游。

### Step 1.5 · **脚本节点 = 一张分镜表 + 三步向导**（T-104，用户提供）

**这是整条链的枢纽，也是我这几轮一直没点进去的地方。**

`＋添加节点 › 脚本 › 脚本 NEW` 得到「脚本生成器」，三条入口（T-95）：
**剧本生成分镜脚本** / **视频参考生成分镜脚本** / **角色生成分镜脚本**
（点任一条会在画布上长出一个「预设 - 文本生剧本」子图 + 一个文本节点，T-96）。

跑完之后，节点展开成**一张全屏分镜表**：

| 镜号 | 时长 | 画面描述 | 景别 | 光影氛围 | 对白·旁白 | 音效 | 运镜 | 最终提示词 | 操作 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 7s | 镜头在**算法实验室**内平缓推进…定格在靠窗的**工位**上，**林照**正平静地注视着前方的**显示器**。 | 全景 | 白天，室内自然光。气氛平静日常，带有冷灰色的严肃科技感。 | + | 轻微的键盘敲击声、平稳的中央空调环境音。 | 向前平缓推进 | 待生成提示词 | `⋯` |
| 2 | 6s | **林照** 拿起桌上的**咖啡杯**轻轻喝了一口… | 近景 | 白天，室内，平淡且枯燥的常规工作氛围。 | + | 瓷杯放置在桌面的轻微"叩"声。 | 固定机位 | 待生成提示词 | `⋯` |

**头部是一条三步流水线**：

```
① 确认镜头          ② 准备资产              ③ 合成提示词
   9个镜头已就绪  →     0/6 已生成、还差 6 个  →   0/9 已合成
                  1/3 · 完成后可批量生视频
```

底部：`＋ 添加镜头` · `→ 下一步：准备资产`
行操作 `⋯`：**颜色标记（6 色）** / **删除该行**

**最关键的一点 —— 画面描述里的实体是高亮链接**（`算法实验室` `工位` `林照`
`显示器` `咖啡杯` `触控板`）。**第 ② 步的「还差 6 个」就是它们。**
系统从分镜表**自动推导出「你需要准备哪 6 个资产」**，而不是让创作者自己数。

> 这是把「分镜 → 资产缺口 → 提示词 → 批量生成」变成一条**可见的、有进度的流水线**，
> 而不是四个页面。

### Step 2 · 角色一致性（T-53 角色三视图 / T-24 角色库 / T-48 创建主体）

三条路，任选：

| 路径 | 做法 |
| --- | --- |
| 起步工作流 | 「角色三视图」直接生成三视图节点 |
| **角色库**（T-24） | 内置**预设角色原型库**：甜妹/清新少女、霸总/精英大佬、温柔熟男、清冷千金/白切黑女主、古风男主/女主、恶毒女配/白莲花、正派长辈父/母、反派长辈、生活方式普通人、时尚感亚洲/欧美男女生、小男孩/小女孩……每个原型自带**全身图 + 面部特写 + 表情九宫格 + 人物呈现板**，一键「**应用至画布**」，带筛选与「最近使用」 |
| **从任意一张图右键 →「创建主体」**（T-48） | 把画布上已有的一张图升格为可复用的角色主体 |

### Step 3 · 分镜画面（T-61 图片节点 / T-47 节点选中态）

`＋ 添加节点 › 图片`，或从上游节点右侧 `⊕` 端口拉出。

**图片节点的表单**（T-61）：

- 快捷：`图生图` / `图片高清`
- 按钮：`＋参考` `标记` `风格`
- Prompt：「可直接文字生图，或上传图片输入文字指令对图片进行编辑，如：将背景改为雪夜」
- 模型 `Lib Image` · 规格 `16:9 · 标准画质 · 2K · 1张` · **价格 `⚡18`**
- `高级设置` · **`智能引用 AutoLink`**

**已生成的图片节点选中后**（T-47）—— 这一屏最值得看：

- 节点顶部浮出工具条：`人像质感调节 NEW` `全景` `多角度` `打光` `九宫格`
  `高清` `宫格切分` + 编辑/翻转/下载/放大
- 节点底部是**这次生成的完整存根**：
  - 三张**编号参考图** ①②③
  - Prompt 文本里**内联嵌着** `图片1` `图片2` `图片3` 的缩略图 chip
    —— 参考图不是「另一处的绑定关系」，而是**写在提示词里的一等公民**
  - 模型 `General image Pro`、规格 `21:9 · 2K · 1张`、**价格 `⚡14`**、提交箭头
  - `高级设置` / `联网搜索` / `智能引用 AutoLink`
- 徽章 `AI生成` + 尺寸 `2752 × 1536` 常驻在节点标题栏

**右键菜单**（T-48）：`Seedance2.0合规校验` / `保存到我的资产` / `进入全景预览` /
**`创建主体`** / `复制节点 ⌘C` / `复制图片` / `创建副本 ⌘D` / `粘贴 ⌘V` /
`删除 ⌘⌫` / `复制到剪贴板` / **`复制 TaskId`**。

### Step 4 · 视频（T-60 视频节点）

`＋ 添加节点 › 视频`。表单：

- 快捷：`5分钟超长视频` / **`首尾帧生成视频`** / **`首帧生成视频`**
- 按钮：`＋参考` `标记` `特效` **`角色库`** **`运镜`**
- Prompt：「描述你想要生成的画面内容，**@引用素材**」
- 模型 `2.0` · 模式 `文生视频` · 规格 `16:9 · 720P · 5s · 1个` · **价格 `⚡135`**
- `高级设置` / `联网搜索` / **`自动校验素材`** / `智能引用 AutoLink`

**运镜**从哪来 —— 「我的工具箱」（T-22）：一堆可复用的**运镜/特效预设**
（【预设】左弧滑行 / 360旋转展示 / 瞳孔拉近 / 机械臂视角 / 破盒而出 /
飞鸟解体 / 电商手机弹出效果 / 咖啡杯出场 / Live 2D / 周星驰经典名场面…），
每条一个「使用」按钮。

`素材库 / 风格库 / 特效库`（T-23 / T-51）：可**新增风格节点 / 新增特效节点**，
把风格与特效也变成画布上的可连接对象。

### Step 5 · 音频（T-65 音频节点）

- 快捷：`音频生视频`
- Prompt：「描述你想要的音频效果，**可用 `@` 引用音频**」
- 模型 `Seed Audio 1.0` · `中文 · 24k · wav` · `0/2000` 字 · **价格 `⚡1`**
- `高级设置`：语速 / 声调 / 音量

### Step 6 · 剪辑成片（T-62 智能剪辑 Beta）

`＋ 添加节点 › 智能剪辑`：

- 空态直说：**「空空如也，请连接视频节点后操作」**
- 快捷：`讲解视频` / `批量广告` / `素材混剪`
- `＋参考` + 「描述想剪成什么效果」
- 模式 `默认模式` · 规格 `16:9 · 720P · 30s`

**剪辑是画布上的一个节点**，输入是连过来的视频节点，输出是成片。
不是一个独立的时间线页面。

### 另外两个专门工具

| 节点 | 作用 |
| --- | --- |
| **导演台 NEW**（T-63） | 「在 3D 空间中搭建场景并进行多视角截图」→「打开导演台」。用 3D 预演解决**机位与构图**，配 Blender 插件 |
| **逐帧拉片 SD 2.5**（T-64） | 上传参考视频 → 选**拆解维度**：`分镜` / `动态` / `音乐` → 「开始拉片」。把别人的成片反解成可复用的分镜/运镜/节奏 |

### 贯穿全程的三件事

| 机制 | 位置 | 说明 |
| --- | --- | --- |
| **Agent 常驻会话** | 右栏（T-04/T-40） | 「每个 Skill，都是一个开场」+ `/pixar-animated-ad-creator` 这类 slash 名 + 「换一批」；输入框「开始你的创作，或者 `@` 引用工作流/节点/资源」；有历史对话、可分享 |
| **Agent 设置 · 协作模式**（T-43） | Agent 头部 ⚙ | **「自动生成图片/视频 —— 开启后，Agent 可直接消耗积分，提交图片/视频生成，无需逐次确认」**。默认关，显式 opt-in |
| **历史资产**（T-25） | 底栏 | `图片历史(0) / 视频历史(1) / 音频历史(0)`，时间降序 + 批量操作 |

### 结构化的手段：分镜组

快捷键表（T-26）里有：`成组 Ctrl/Alt+G`、**`合并分镜组 Ctrl+Alt+G`**、
`解组 Ctrl/Alt+Shift+G`、`连线 Ctrl+L`、`复制节点和连线 Ctrl+D`、
**`生成 Ctrl+Enter`**、`新建节点 Tab`、`整理画布 Alt+Shift+F`、撤销/重做。

左栏「画布元素」树（T-30）显示这些组的真实用法：
`#分镜` / `#风格测试` / `#海报` / `场景测试` / `分镜1(镜头1…镜头8)` /
`分镜2` / `分镜4` / `分镜测试` —— **共 149 节点**。

> 即：LibTV **没有内建 Episode→Scene→Shot 模型**，
> 用户是**用画布分组手工模拟**出「分镜1 / 镜头1…8」的。
> 一部 5 分钟片子就已经 149 个节点。

## 2.5 一条**跑完了的**真实工作流长什么样（T-70…T-75）

前面走的是「每个节点提供什么」。这一节走的是**别人已经跑完的一整部片子**——
首页「精选画布 → **查看创作过程**」把他人的完整画布以**只读模式**打开
（右上「只读模式，如需创建请点击 **复制项目**」），零花费，是看完整链路最好的样本。

样本：**《黑翼天使终章》**（Jcy樂多，暗黑高燃美学短片，成片 02:56）。

### 它的画布结构（T-74，10% 缩放看整体）

```
┌─ 天使资产 ────────┐   ┌─ 标题卡组 ─────────────────┐
│ 4×4 角色/资产参考图 │   │ 参考 → CROWN of ASHES 标题 │
└───────────────────┘   └───────────────────────────┘

┌ 分组 5 个节点 ┐ ┌ 分组 5 个节点 ┐ ┌ 分组 5 个节点 ┐ ┌ 分组 5 个节点 ┐
│ 参考图 ┐      │ │ 参考图 ┐      │ │ …            │ │ …            │
│ 文本(Prompt)─→│ │ 文本   ─→     │ │              │ │              │
│ 图片节点 ─→   │ │ 图片   ─→     │ │              │ │              │
│ 视频节点 ■    │ │ 视频   ■      │ │              │ │              │
└──────────────┘ └──────────────┘ └──────────────┘ └──────────────┘
  1没有日出的圣城   2最后一次天光    3黑羽之雨       4失效的祝福
        …… 一路排到 20没有神的第一场日出，规则网格 ……
```

- **20 个镜头 = 20 个手工复制出来的、结构完全相同的 5 节点小流水线**，
  排成规则网格。节点名就是镜头名：`1没有日出的圣城` … `20没有神的第一场日出`，
  每个还带一份 `- 副本`（做第二版）。
- 另有一个 `天使资产` 分组（4×4 角色参考图网格）当**角色一致性池**，
  以及一个标题卡分组。
- 侧边一个 `分组 20 个节点` —— 二十条视频的汇总。

> **这就是一张分镜表，只不过是用画布分组手工搭出来的。**
> 创作者付出的代价：复制 20 次相同的 5 节点结构、手工编号、手工排版、
> 手工维护 `- 副本` 的版本关系。
> 我们的 Episode → Scene → Shot 模型**就是为消除这个代价而存在的**。

### 单个镜头节点的内容（T-73）

选中 `8空椅子的神谕`（1456 × 816）：

- `参考` / `风格` 按钮 + 一张编号参考图
- Prompt 是**三段式**，写得像分镜脚本：
  1. 内容 —— 「一个单独的真人电影框架在一个黑暗的废弃投影教堂内…」
  2. 人物与事件 —— 「穿着破旧铅灰色外套的苍白女性艺术保管员…」
  3. **镜头语言** —— 「从两个观察者的后面拍摄，**35 毫米镜头**，分层的轮廓和投影图像，
     深度曝光不足，冷青色投影仪光…」
- `高级设置`：**个性化风格** / **风格化程度 100** / **怪异度 50** / **多样性 5**
- `智能引用 AutoLink`

文本节点里还写着完整的镜头规格：`**场景设定**`（环境 / 主体 / 核心视觉 /
画面运动 / **运动原则：24fps 真实速度，绝对无升格；动作短促、过载、抽帧**）+ `**SHOT …**`。

> 注意：**运镜、机位、焦段、运动原则全都写在 Prompt 文本里**，
> 因为 LibTV 没有地方结构化地存它们。
> 我们**有**这些字段（景别/角度/运镜/动作/情绪），但真实项目里 60 个镜头**全是「未记录」**（GAP-16）。
> 两边都没解决这件事 —— 只是失败方式不同。

### 链式生成：`引用该节点生成`（T-80）

点任意节点右侧的 `⊕` 输出端口 → **「引用该节点生成」** →
`文本` / `图片` / `视频` / `智能剪辑 Beta` / `导演台 NEW` / `逐帧拉片 SD2.5` /
`音频` / `脚本` / **`参考节点`**。

**任意类型 → 任意类型，一个统一动作。** 这是整个画布模型的引擎。

### Agent 的两个显式引用机制（T-45 / T-46）

**`/` 唤出 Skill 全表**（不是右栏那 4 张推荐卡）：
剧情广告短片创作 / 百万转场视频 / 电影级镜头生成 / 古风画卷大师 /
S级女频仿真人剧一键成片 / 东方天庭美学 / 专业电影视频制作 5.0 / 云顶天宫 /
灰烬之城-年代黑帮剧创作 / 诺兰IMAX真人电影制作 / **小说转剧本(大师版)** /
**角色、场景、分镜一键提取** / …

> 最后两条正是我们的 `script-writer` 和 `script-breakdown` / `storyboard-director`。
> 差别只在：**它们能被用户一句话唤起，我们的要先导航到正确的页面。**

**`@` 引用两类对象**：

| 分区 | 内容 |
| --- | --- |
| **节点** | `#分镜`、`图片节点 4`、**`分镜组3`**、加载更多 —— 节点**和分组**都能引用 |
| **模型** | General image Pro / Lib Image / Seedream 5.0 Pro / Style Image V8.2 · V8.1 · V7 / General image V2 / **Seedance 2.5** / Seedance 2.0 VIP / **Minimax H3** / Seedance 2.0 Fast VIP / **Kling O3** / Kling 3.0 |

> 于是用户可以直接说：「用 `@Seedance 2.5` 把 `@分镜组3` 里的图都生成视频」。
> **对象和模型都是对话里的一等公民。**

### 历史资产（T-81）

`图片历史(0) / 视频历史(1) / 音频历史(0)` · 时间降序 · 批量操作；
每条三个动作：**查看 / 使用 / 下载**。「使用」= 直接放回画布。

## 2.6 **工作流 / 故事板 —— 同一份数据的两个视图**（T-90…T-94）

顶栏项目名右边有两个没有文字的图标，`aria-label` 分别是 **`工作流`** 和 **`故事板`**。
它们是**互斥的视图模式**，切换的是同一个项目：

| 模式 | 形态 |
| --- | --- |
| **工作流**（默认） | 无限画布：节点 + 连线 + 分组（前面 §1–§2.5 讲的全是这个） |
| **故事板** | **三列清单**：`文本` / `图片` / `视频`，把画布拍平成可审阅的表 |

> **我上一轮的判断错了，在这里更正：** 我写过「LibTV 没有结构化视图，全靠画布」。
> 不对 —— 它有 `故事板`。画布是**制作面**，故事板是**审阅面**。

### 故事板长什么样（T-90）

三列，每列列出该类型的**每一个节点**，每条带：

| 列 | 每条显示 |
| --- | --- |
| **文本** | 节点名（`风格确定`） |
| **图片** | 名称 · 缩略图 · **尺寸**（`3168 × 1344` / `6336 × 2688`）· **模型**（`General image Pro`）· `对话` 按钮 · **失败态**（`生成失败，详情 ›`） |
| **视频** | 名称 · 可播缩略图 · **模型**（`Kling 3.0` / `Hailuo 2.3` / `Kling 2.6` / `2.0`）· **时长**（`10秒` / `6秒` / `5秒`）· **尺寸**（`1472 × 624` / `1696 × 720` / `2208 × 936`）· **首帧来源缩略图**（卡下方的小方块）· `对话` |

- 视频列有筛选 **`全部 ▾` → `全部` / `成片` / `片段`**
- 每列可 `⤢` 展开成两栏（清单 + 详情，T-94）
- 每条都有 **`对话`** —— 一键把这一项丢进 Agent 会话

> **一屏之内可以回答：这一集有哪些镜头、每条用了哪个模型、多长、多大、
> 首帧来自哪张、哪些失败了。** 这正是我们「审片」页想做但没做到的事
> —— 我们那页是**逐镜分页，60 个页码平铺**（C-016），一次只看一个。

### 失败态：免费拿到了（T-93 / T-94）

我一直说「生成失败」这个状态要花钱才能实拍。**不用** —— 用户项目里本来就有一条：

- 清单上：`图片节点 4  生成失败，详情 ›`
- 详情：大图上盖 ⚠ **生成失败** + **`TaskID: 20260330184103774304541`** + 一键复制
- 顶部：`⋯` 菜单 / **「添加到对话」** / 关闭
- 右侧是那次生成的**完整可复现存根**：
  - **6 张编号参考图 ①…⑥**
  - Prompt 里内联引用它们：「在 `图片1` 石头两侧增加 `图片3` `图片5` 女人与
    `图片4` `图片6` 男人，男人在画面左侧的石头边上，女人在画面右侧的石头边上，
    姿势参考 `图片2`，32k超清」
  - `General image Pro` · `16:9 · 2K · **4张**` · **`⚡56`**
  - `高级设置` / `联网搜索` / `智能引用 AutoLink`

> **一次失败保留了全部输入、模型、规格、单价和 TaskID，并且能一键「添加到对话」
> 让 Agent 去诊断。** 失败不是一个红叉，是一份可复现的工单。

## 4. 由这一轮走查新增的 Gap

### GAP-15 · 一次生成被拆在四个地方
`Interaction Gap` · **P1** · 🟡 需小改 · **COMBINE**

**Current** 做一张图要经过：制作台左栏绑参考 → 中栏看编译出的 Image Prompt →
`查看/修改` → `自动生成` 或 `复制` → 到别处上传结果。价格只在预检弹窗里出现一次。

**Target** T-47 —— 参考 ①②③ 以缩略图 chip **内联在 Prompt 文本里**，
模型、规格、**价格 `⚡14`**、提交按钮全在同一张卡上。

**Why it matters** 创作者做的是**一次决策**（用这些参考、这个模型、这个规格，
花这么多，生成）。我们把这一次决策拆成四次导航，价格还藏到最后。

**Existing support** `promptc.js` 编译器已经知道每一段来自哪个对象
（场景地/角色/画面内容/基调），`refUse` / `mediaref` 有绑定关系，
预检已经能给报价。**材料齐全，只是没有拼在一张卡上。**

**Required change** 镜头制作 ② / ③ 步做成一张「生成卡」：内联参考 chip +
模型 + 规格 + 报价 + 一个提交按钮。

### GAP-16 · 运镜 / 风格 / 特效是文本字段，不是可复用资产
`Domain Model Gap` · **P2** · 🔴 需后端 · **ADD**

**Current** C-011 —— 镜头详情里 `景别 / 角度 / 运镜 / 动作 / 情绪` 全部是自由文本，
真实项目里**全是「未记录」**。

**Target** T-22 我的工具箱（运镜预设，可「使用」）、T-23/T-51 风格库 / 特效库
（可「新增风格节点 / 新增特效节点」）。

**Why it matters** 60 个镜头的运镜全空，说明**逐镜手打自由文本这条路走不通**。
预设库让「同一个运镜用在 12 个镜头上」变成选择而不是重打。

**Required change** 一个项目级的「运镜 / 风格 / 特效」预设集合，镜头引用其 id
（与 Asset Registry 同构：只引用不复制）。属于新领域对象，需要 ADR。

### GAP-17 · 没有角色原型库，也不能「从一张图创建角色」
`Capability Exposure Gap` · **P2** · 🟡 需小改 · **ADD**

**Current** C-004 —— 6 个角色里 3 个「还没有参考图」。建一个角色要手工填档案、
再另外找图、再绑定。

**Target** T-24 角色库（20+ 预设原型 × 四件套 × 一键应用）；
T-48 图上右键 →「创建主体」。

**Why it matters** 角色一致性是短剧的核心难点，而我们的入口是**空表单**。
我们已经有 `shot-asset-recommender` / `reference-planner` 两个 Skill 和完整的
角色状态模型 —— 缺的是**「从已有的图反向建角色」这一个动作**。

**Required change**

2. （可选）内置若干中文短剧常见原型作为起步模板。

### GAP-24 · 分镜是「卡片＋详情」，不是一张可横向比较、可批量编辑的表
`Information Architecture Gap` · **P1** · ⚪ 纯前端 · **MODIFY**

**Current** C-011 —— 左边一列镜头缩略卡，选中一个在右边看详情。
**一次只能看一个镜头的景别 / 运镜 / 台词。**60 个镜头要对齐节奏、检查景别是否重复、
看哪几镜没写运镜 —— 全部做不到。真实结果：**60 镜的景别/角度/运镜/动作/情绪全是「未记录」**。

**Target** T-104 —— 一张表，**十列**：镜号 / 时长 / 画面描述 / 景别 / **光影氛围** /
对白·旁白 / **音效** / 运镜 / **最终提示词** / 操作。一屏横向可比。

**Gap 细分**

| 列 | 我们 | 说明 |
| --- | --- | --- |
| 镜号 / 时长 / 画面描述 / 景别 / 运镜 / 对白 | ✅ 有字段 | 但只在详情里，逐个看 |
| **光影氛围** | ❌ **没有这个字段** | 目前只能塞进「画面内容」自由文本 |
| **音效** | 🟡 有 `sfx`，在音频工作区 | 不在分镜表上，写分镜时看不到 |
| **最终提示词** | 🟡 在另一个页面编译 | 不是分镜表的一列 |
| 行内颜色标记 / 删除该行 | ❌ | 没有行级标注 |

**Why it matters** 写分镜是**横向工作**（这一场的节奏、景别变化、光影连续性），
不是纵向逐个填表。卡片式强制纵向，于是没人填 —— 这就是 60/60「未记录」的成因。

**Existing support** 字段大部分已在 `shot` 草稿 schema 里；`storyboard.js` 已有
纯视图模型可测。

**Required change** ⑦ 分镜设计增加**表格视图**（与现有卡片视图并存），
补 `lighting`（光影氛围）字段，把 `sfx` 和编译出的 Prompt 拉进同一张表。

### GAP-25 · 画面描述里的实体没有链接，资产缺口要靠另一个页面猜
`Domain Model Gap` · **P1** · 🟡 需小改 · **ADD**

**Target** T-104 —— 画面描述里 `算法实验室` `工位` `林照` `显示器` `咖啡杯` `触控板`
**是高亮链接**，而第 ② 步「准备资产 **0/6 已生成、还差 6 个**」的 6 就是它们。
**缺口是从分镜表推导出来的，就写在分镜表旁边。**

**Current** 我们有「参考统筹」页（C-012）在做类似的事，但：
1. 它是**另一个页面**，写分镜的时候看不到；
2. 真实项目里它说 **「没有缺口」**，而实际上 60 个镜头**一个参考都没绑**；
3. 画面描述是纯文本，`林照`（我们已有的角色实体）在里面**不是链接**。

**Why it matters** 「我还差什么才能开始生成」是创作者每天要问的问题。
现在的答案分散在：分镜页（有没有描述）、参考统筹页（有没有绑参考）、
作品设定页（角色有没有参考图）、画面页（0/60）。**没有一处合起来说。**

**Existing support** `bibledoc` 有角色/场景地实体与稳定 id；
`breakdown.js` 已经能从剧本里**认出**这些实体（剧本拆解就是干这个的）；
`promptc.js` 编译时已经会列出「缺什么」（场景地/角色/画面内容）。
**认得出、算得出，只是没有连到分镜表上。**

**Required change** 分镜表的画面描述做实体识别 + 高亮 + 链接到该实体；
表头给「准备资产 N/M」的真实计数。

### GAP-26 · 「确认镜头 → 准备资产 → 合成提示词 → 批量生视频」有实现、无入口

> 真实资产缺口是 Phase 1.2）。证据：C-022。
`Capability Exposure Gap` · **P0** · ⚪ 纯前端 · **EXPOSE**

**Current** 我们**有**这条三步向导 —— `src/ui/wizard.js` + `index.html#wz-scrim`，

**Required change** 把它接到 ⑦ 分镜设计 / ⑧ 镜头制作 的主路径上；
第 ② 步的计数改用 GAP-25 推导出的真实资产缺口。

### GAP-27 · 生成的输入不能自由组合
`Interaction Gap` · **P2** · 🟡 需小改 · **MODIFY**

**Target** 用户原话：「画布的节点也可以用户自由设计的」「可以自由设定参考图片、
文本或者视频」。T-47 / T-60 印证：一个节点上可以任意叠加
`＋参考`（多张，编号 ①②③…⑥）· `标记` · `风格` · `特效` · `角色库` · `运镜`，
Prompt 里再用 `图片N` 内联引用它们，`@` 还能引用别的节点和模型。

**Current** 我们的生成输入是**按角色写死的槽位**：首帧 Start Frame / 尾帧 End Frame /
主要画面参考 / 视频编排参考（C-007 左栏），每个槽位语义固定。
创作者不能说「这一镜我要用这 3 张图 + 这段文本 + 那条视频当输入」。

**Why it matters** 固定槽位在「标准镜头」上够用，在**试验性镜头**上就成了墙。
LibTV 的编号参考 + Prompt 内联引用，让「哪张图起什么作用」由**提示词本身**说明，
而不是由槽位名说明。

**Existing support** `refUse` / `mediaref` / `geninput` 已经是「引用不复制」的模型；
`shotctx` 已经在做输入集合。

**Required change** 参考位从「固定角色槽」改为「**有序编号列表 + 每项可标注用途**」，
Prompt 编译时以 `图片N` 形式内联引用。**这条会改跨层合同，属高风险，需 ADR。**

### GAP-28 · 界面说「模型直接输入」，付费链路一张都不送
`State Model Gap` · **P0** · ⚪ 纯前端（标注）/ 🔴 后端（真送出多图）· **MODIFY**

> 本条在
> [ui-correction-plan.md](ui-correction-plan.md) 的 0.3 / 3.1 里被引用，但走查里一直没有自己的
> 条目 —— 补记于此（TASK-077 收口）。

**Current** `src/workflow/geninput.js` 的 `ROLE_USE` 把人物 / 场景 / 道具 / 风格参考
四类写死成 `"model-input"`，`ROLE_USE_LABEL` 在镜头制作左栏渲染成 **「模型直接输入」**；
`promptc.js` 还会编出「（作为参考图一并提供，保持一致）」。

**证据（读代码，不是猜）** 整条付费链能送出的图像只有一张：

```
shot.first_frame_image → packet.first_frame_image
  → ProviderRequest.provider_parameters
  → providers/cloud_minimax.py `_payload`
body = { model, prompt, duration, resolution, first_frame_image? }
```

`ProviderRequest`（`providers/models.py`）没有任何多图字段。那四类参考在付费路径上
**不会被送出**，模型只收到那行文字。

**Why it matters** 这是「用户误解状态」里最贵的一种：创作者会**为了一致性去准备参考图**，
而它们在付费生成上一张都不到模型手里。

**已闭合的一半 ✅（TASK-077 §1.3，2026-08-16）—— 如实标注**

`ROLE_USE` 这张**声明表不动**（它决定引用进哪条 Prompt、画在生成图的哪一侧，
改它就是跨层改动）；新增按路线解析的 `effectiveRoleUse(role, capability)` +
`ROUTE_CAPABILITY`，界面改为**同时列出两条路线的事实**：

```
✓ 免费 / 手工路线：由你把文件附给外部工具，所以这些参考图真的会被模型看到。（当前路线）
✗ Gateway 付费生成：请求只带一张图片（首帧）。人物 / 场景 / 道具 / 风格参考不会进模型
   —— 它们只会被 AI 解读成 Prompt 里的文字描述。
```

**为什么列两条而不是只列当前那条**：这个产品同时提供两条活路线 —— 不论 Gateway 写路径
有没有开，创作者今天都可以复制 Prompt 去外部工具。只印当前那条虽然此刻诚实，仍会让一个
**正在计划付费跑一次**的人以为四张图会被送出。要消灭的是**无条件断言**，不是其中一条事实。
`promptc.compileVideoPrompt` 同理分路线：手工路线保留「作为参考图一并提供」（那是给创作者
的正确指示），Gateway 路线改成「图片不随本次提交发送，仅以此描述指定」。
全库已搜不到「模型直接输入」这句渲染文案。

**未闭合的一半 ❌** 让付费路线**真的**能送出多张参考图 —— 那是 GAP-27 的同一条改动
（`ProviderRequest` 加 `reference_images`、catalog 声明每个 model 吃几张），
**跨层合同 + 需 ADR**，见修正计划 3.1。

---

### GAP-22 · 没有「把整集拍平成一张可审阅清单」的视图
`Information Architecture Gap` · **P1** · ⚪ 纯前端 · **ADD**

**Current** 审片页（C-016）是**逐镜分页**：一次看一个镜头，底下 **60 个页码平铺**。
想知道「这一集哪些镜头有视频、分别多长、用了哪个模型、哪些失败了」——
**没有任何一屏能回答**。画面/视频/音频三个工作区各自只给 `0/60` 一个总数。

**Target** T-90 故事板 —— 三列（文本/图片/视频），每条带模型 · 时长 · 尺寸 ·
首帧来源 · 失败态 · `对话`；视频列可按 `成片 / 片段` 筛。

**Why it matters** 这是**审阅**这件事的基本形态：并排比较，而不是逐个翻页。
60 个页码不是导航，是放弃导航。
而且这个视图**几乎零成本** —— 我们的 canvas 里 `assets` / `generations` /
`shotAudio` / `timelines` 全都有，`prodgraph` 已经能算出每个镜头的产出状态。

**Existing support** 数据齐全；`assetlibws` 已经会渲染带筛选的媒体网格。

**Required change** ⑨ 粗剪审片（**目前完全不可达，见 GAP-01**）改成这个形态：
一集的镜头清单 × 图片/视频/音频三列，每条带模型 / 时长 / 尺寸 / 来源 / 状态。
**一条改动同时解决 GAP-01 的死页面和 GAP-22 的缺失视图。**

### GAP-23 · 生成失败没有可复现的工单
`State Model Gap` · **P2** · 🟡 需小改 · **MODIFY**

**Target** T-93 —— 失败的节点保留：**6 张编号参考图 + 内联引用它们的 Prompt +
模型 + 规格 + 单价 `⚡56` + `TaskID` + 一键复制 + 「添加到对话」**。

**Current** 我们的失败处理是 fail-closed 报错 + 一段有界的原始输出摘录 —— 姿态是对的，
但**失败之后那次生成的输入没有被保留成一个可以重开的对象**，
也没有「把这次失败交给 AI 导演去诊断」这个动作。

**Existing support** `generations` 注册表已经记录 `promptSnapshot` / `provider` /
`inputAssetIds`；Run 记录有 id 和错误。

**Required change** 失败也进 Generation 注册表（现在只有成功进），
卡片上给「重试（同参数）/ 改参数重试 / 交给 AI 导演看」三个动作。

### GAP-19 · 没有通用的「从这个东西生成下一个」
`Interaction Gap` · **P1** · ⚪ 纯前端 · **ADD**

**Current** 我们只有**一条**类型间流转：资产 →「🎬 用作视频首帧」。
其余全靠导航：想给这张图配音，要切到音频工作区、找到对应镜头槽位。

**Target** T-80 —— 任意节点 `⊕` →「**引用该节点生成**」→ 9 种下游类型，一个统一动作。

**Why it matters** 创作是**链式**的：这张图 → 这条视频 → 这段音 → 这个剪辑。
我们把每一步都做成了一个页面，于是「往下走一步」= 一次跨页导航 + 重新找到当前对象。

**Existing support** `framebind` / `mediaref` / `mediadep` 已经建模了类型间依赖；
`shotgraph` 已经能画出「这个镜头的制作流程图」。**缺的是那个统一菜单。**

**Required change** 在任意媒体卡（画面/视频/音频/资产）上加一个
「以此生成 →」菜单，落到对应工作区**并预填这一项为输入**。

---

### GAP-20 · 模型不是用户能看见、能选、能引用的东西
`Capability Exposure Gap` · **P2** · 🟡 需小改 · **EXPOSE**

**Current** 我们有 provider catalog（版本化、锁定、带报价），但界面上
**没有任何地方让创作者看到「这次要用哪个模型」**，更不能换。

**Target** T-45 —— `@` 菜单里模型和节点并列，13 个模型直接可引用；
T-47/T-60/T-61 —— 每个节点卡上都写着当前模型（`General image Pro` / `2.0 文生视频`）
和这次要花多少（`⚡14` / `⚡135`）。

**Why it matters** 「用哪个模型、花多少」是创作者的决策，不是系统的实现细节。
藏起来的结果是：用户不知道自己在用什么，也无法为不同镜头选不同模型。

**Existing support** catalog 有 model / resolution / duration / 报价，
Gateway 预检已经能返回单价。

**Required change** 生成卡上显示并允许选择模型与规格（GAP-15 的同一张卡）。

---

### GAP-21 · 没有「拿别人跑通的流程当模板」
`Capability Exposure Gap` · **P3** · 🟡 需小改 · **ADD**

**Target** T-70 —— 精选画布「查看创作过程」以**只读**打开他人完整工作流，
右上「**复制项目**」一键变成自己的起点。

**Current** 我们有 21 个 Skill（单步能力），但**没有「整条流程」这一级的可复用物**。
新项目从空白开始。

**Existing support** Skill 包机制（ADR-0067）已经是三件套 + 三级来源；
canvas.json 本身就是一份完整流程的快照。

**Required change** 「项目模板 / 流程预设」：从一个已完成项目导出结构
（不含媒体字节），新建项目时可选。需要一份小 ADR。

### GAP-18 · 没有「逐帧拉片」这类反向输入
`Backend Capability Gap` · **P3** · 🔴 需后端 · **ADD（先不做）**

LibTV 的 `逐帧拉片`（上传参考片 → 按 分镜/动态/音乐 拆解）是**把参考作品变成
可复用创作输入**。我们有 `reference-interpreter` Skill，但输入只有静态图。

**建议**：记为 follow-up，不进当前批次。这需要视频理解能力，超出当前授权。

## 5. 结论 —— 该学 LibTV 的三件事，和不该学的一件事

**该学（后端全都支撑得起，纯前端或小改）**

1. **一次生成 = 一张卡**（GAP-15）：参考内联进 Prompt、模型/规格/**价格**/提交同屏。
2. **Skill 是可浏览的一级资产 + Agent 是一个常驻会话**（GAP-04 / GAP-08）：
   `/skill` 调能力、`@` 引对象，而不是靠「你在哪一页」。
3. **URL 即状态**（GAP-07）：可分享、可书签、可后退。

4. **通用的「从这个生成下一个」**（GAP-19）：任意媒体 → 任意下游类型，一个统一动作，
   而不是只有「用作视频首帧」这一条特例。
5. **模型与价格是创作者的决策，不是实现细节**（GAP-20）。

**该学（需要新领域对象，走 ADR）**

6. **预设即资产**：运镜/风格/特效预设库（GAP-16）、角色原型库与「从图创建角色」（GAP-17）、
   项目/流程模板（GAP-21）。

**该学（最便宜、见效最快的一条）**

4.5 **「制作面 / 审阅面」双视图**（GAP-22）：LibTV 用 `工作流`（画布）与
   `故事板`（三列清单）覆盖同一份数据 —— 做的时候看画布，审的时候看清单。
   我们的 ⑨ 粗剪审片**目前完全不可达**（GAP-01），把它做成故事板那个形态，
   **一条改动同时解决死页面和缺失的审阅视图**。

**不该学**

7. **不要照抄「画布是唯一的组织方式」——但规模不是理由。**

   > **两处更正。** 我先后写过两句错话，都在这里改掉：
   >
   > **错话一**：「一个项目 = 一块画布，48 集照抄 = 6000 节点」。
   > **不成立** —— 层级是 工作区 → **多块画布** → 节点（T-99），
   > `⊕ 新建画布` 就在项目名旁边。**一集一块画布是这个模型的正常用法**，
   > 每块 150–200 节点完全可控。规模论据作废。
   >
   > **错话二**：「LibTV 没有结构化视图，全靠画布」。**不成立** ——
   > 它有 `故事板`（§2.6）作审阅面，还有 `脚本节点` 的**分镜表**（§1.5）作设计面。
   > 它的结构化程度比我第一轮判断的高得多。

   那么真正该保留的判断是什么？**不是规模，是跨集的一致性。**

   一集之内，画布很好用。但**跨集**的东西 —— 角色档案与状态、场景地、
   人物关系、世界规则、分集规划、全季进度 —— 在 LibTV 里**没有归属层**：
   《黑翼天使终章》的 `天使资产` 组是**画布内**的一个分组，换一块画布就得再复制一份；
   而「第 7 集拍到哪了 / 全季 48 集哪些做完了」，项目列表只给封面 + 日期。

   我们的 Episode / Scene / Shot + 作品设定 + 分集规划**就是那个跨集层**，
   而且是我们相对目标产品最实的优势（§3 里我们「远远更强」的那几行全在这一层）。
   **保留跨集层，同时把一集之内的制作面做成画布/表格那样好用** —— 这才是正确的合成，
   不是二选一。

   **ADR-0066 的固定 IA 方向是对的，它的问题是没被实现（GAP-01 / GAP-26），不是它错了。**

**两边都没解决的**

8. **镜头语言（机位/焦段/运动原则）没有结构化的地方放。**
   LibTV 把它们写进 Prompt 长文本（「从两个观察者的后面拍摄，35 毫米镜头…
   24fps 真实速度，绝对无升格」）；我们**有字段**但真实项目 60 个镜头全是「未记录」。
   谁先把这件事做成**可选、可复用、可批量套用**，谁就赢这一段（GAP-16）。
