# 从零做一集

这是产品自己跑通过的那条顺序。它不是唯一正确的顺序，是**一条已经走通的**顺序 ——
你可以照着走，也可以在自己的项目里改出一份新的。

## 为什么是这个顺序

七步之间不是随便排的，每一处顺序都有一个具体的失效在后面顶着：

| 这一步 | 为什么在这个位置 |
| --- | --- |
| ① 故事大纲 | 后面每一步都从它派生。先有世界观再有故事，做出来的是一份设定集，不是一个故事 |
| ② 世界观 | 排在故事**之后**：世界是为这个故事服务的，不是先建好再往里塞 |
| ③ 分集规划 | 读大纲，写出每一集要发生什么 |
| ④ 剧本 | 把**一集**的规划写成剧本。一次一集，不是一次十二集 |
| ⑤ 剧本拆解 | 它的产出决定下一步要准备什么资产 —— 所以必须在准备资产之前 |
| ⑥ 基础资产 | 排在拆解之后，因为要先知道有哪些实体才知道要设计谁 |
| ⑦ 分镜 | 最后，因为它要**同时**读剧本与已经准备好的资产 |

## 它不会替你做的事

- **不会自动跑完。** 每一步都是你按下去的。「按模板自动跑完整条流程」是自动化，
  不是模板，而且它会直接撞上「套用模板不获得付费/定稿/锁定/导出」这条禁令。
- **不带任何内容。** 你拿到的是顺序、每一步用哪个版本的能力、以及几条项目层约定。
  剧本、角色、世界观都还是空的 —— 那是你的作品，不是模板的。
- **不保证每一步都能跑。** 如果你这台机器上缺了某个版本的能力，这份流程在**加载时**
  就会拒绝并说出缺的是哪一个。它不会跳过那一步偷偷往下走 —— 少做一步的流程，
  结果上看不出来。

## 想改它

复制一份到 `<项目>/studio/flows/`（这一部作品专用）或 `<应用数据根>/flows/`
（这台机器上的你），改 `flowId` 之外的任何东西。同名的话，越靠前的来源**整体**
覆盖后面的 —— 不做字段级合并，因为半个来自你、半个来自内置的流程，没有人能预测
它会做什么。

改了内容就把 `flowVersion` 加一。已经被项目引用过的版本不得原地覆盖：那些项目的
`createdFrom` 说它们是从那一版起步的，让字节在底下动等于把溯源变成猜测。
