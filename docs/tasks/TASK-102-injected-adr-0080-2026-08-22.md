# ADR-0080：测试所有权、Agent Skill 与集成闸门

- 状态：Accepted
- 日期：2026-08-22
- 决策者：实施 Agent（产品负责人 2026-08-22 授权执行，TASK-102）

## 背景

原规则把验证和审查绑定到低／中／高风险分级：同一种变更既要猜分类，又会因
分类触发全量测试、审查轮次预算和连续修改链例外。规则分散在 `AGENTS.md`、
`CLAUDE.md`、Skill 与 commit gate 中，已出现互相矛盾。

仓库正在通过 TASK-102 建立清晰的测试域所有权。验证应由改动影响的合同和其
直接消费者决定，而不是由抽象风险标签决定。与此同时，`.claude/skills/` 的
目录名不应把这些可复用工作流限定为 Claude 专用。

## 决策

1. **单一规范**：`AGENTS.md` 是所有编码 Agent 的唯一操作规范；`CLAUDE.md`
   仅保留指向它的兼容入口。原只在 `CLAUDE.md` 出现的可逆决策、切片和升级
   规则合并进 `AGENTS.md`。

2. **区分两类 Skill**：产品 Skill 是 ADR-0067 定义的 Studio 运行时资产；
   Agent Skill 是 `.claude/skills/<name>/SKILL.md` 中的工作流说明。后者是
   跨 Agent 共享资产：支持该格式的工具可自动发现，其他 Agent 按 `AGENTS.md`
   的触发说明显式读取。保留 `.claude/skills/`，因为 Claude 的项目级自动发现
   依赖该路径，且 GitHub Copilot 也识别它；不在 `.github/` 复制第二份真相。

3. **验证按归属，不分风险档**：日常提交运行受影响功能域的测试、直接消费者
   的测试和必要的合同测试。未知归属或依赖图不清时，先扩大到可确定的共同域；
   仍无法界定时才 fail-closed 到完整集成套件，并把缺失映射列入 TASK-102。
   不再因为“高风险”这一分类自动运行全量。

4. **全量是集成检查点**：CI、合并到 main、跨域/依赖图不清的变更完成整合、
   用户要求的发布或交接前，运行两阶段完整 pytest、完整前端套件与 ruff。
   这不替代日常归属测试；也不要求每个可独立验证的切片重复运行全量。

5. **审查收敛**：需要审查的行为/合同变更按影响范围做一次独立审查；纯文档或
   纯展示变更可不审。P1 修复后做一次复审；P2 修复跑归属测试即可，P3/P4 记录为
   Follow-up。审查不可用时可如实标记后提交，但不得把“测试通过”称为独立审查；
   需要审查而尚未完成的变更不可进入合并/交接集成点。

6. **移除连续修改链**：废止 ADR-0068 的 `MOTV_CONTINUOUS_CHAIN` 令牌及其
   gate 逻辑。每个提交按测试归属验证；完整套件只在上述集成检查点执行，故不再
   需要跳过全量的特殊通道。

7. **Git 集成**：commit 不需逐次询问。受 auto-push 管理的 Change 分支可在
   任务的归属验证和所需独立审查完成后自动 push；main 的 merge/push 仍须用户
   明确授权。ADR-0079 的窄例外在此成为 `AGENTS.md` 的正式规则。

8. **工具解析边界**：产品和流水线代码使用 `shutil.which` 解析外部工具并
   fail-closed。Agent 工装使用宿主 shell 的等价解析（PowerShell `Get-Command`、
   POSIX `command -v` 或项目 venv 解释器）并同样 fail-closed；不把 Agent 工装
   的调用方式误当成产品运行时合同。

## 后果

- ADR-0060 的“按风险分级”本地 gate 决策被本 ADR 取代；其 shell 解析和
  fail-closed 实现原则仍保留。
- ADR-0068 的连续修改链决策被废止。
- ADR-0069 中按风险设置的审查轮次预算被本 ADR 取代；两阶段 pytest 方案保留
  作为完整集成套件的执行方式。
- TASK-102 负责把当前临时映射逐步落实成清晰的 `backend/studio/contract/e2e/tooling`
  测试所有权；CI 继续运行完整集成套件。
