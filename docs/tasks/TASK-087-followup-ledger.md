## 0. 这张卡不做事，它防止遗忘

**它不改任何代码。** 唯一的功能是：让「还欠什么」有一个地方能一眼看完，
并且每条都带**风险档**和**为什么还没做** —— 后者比前者重要，因为
「忘了」和「刻意押后」在清单上长得一样，而处理方式完全不同。

排序不是优先级，是**分组**：按「拦不拦得住下一步」分。

## 7. 一条贯穿本批的方法论（值得单独读）

TASK-077～086 里真正的缺陷有**六条是同一个形状**，而且没有一条是「实现写错了」：

| | 形状 |
| --- | --- |
| `_package_dirs` | 屏蔽表键在 `skill_id=""` 上对不上，注释把危害写得很准，代码从未生效 |
| `gate.sh` 分类器 | 预算注释写着 must never fail open，而它是唯一没超时的一步 |
| `is_symlink()` | Windows junction 返回 `False`，守卫恰好抓不到它要防的那个东西 |
| 媒体探针 | 「问不出来」被记成「文件不见了」，永久 |
| 往返测试键集 | 性质是对的，**覆盖的集合恰好排除了坏掉的两个成员** |
| 短选项簇 | 簇内不再过度匹配了，**调用点还在做成员测试** |

共同点：**不变量只覆盖了一半，另一半就在相邻那一层。**

推论，已在多张卡里生效，建议继续执行：

1. **断言性质，不要断言写法**（TASK-077 跨源、TASK-086 往返集合）。
2. **守卫的键集要派生，不要手写**——新成员应当**因为存在**而进测试。
3. **每条新守卫做变异验证**：改坏实现看它是否变红。但要记住变异验证抓
   「实现被改坏」，**抓不住「用例本身没覆盖到的形状」**——后者只有独立审查买得到
   （TASK-085 三轮买到的正是它）。
4. **杀不掉的变异如实记录**，不要编一个断言非法输入的测试凑绿点
   （TASK-085 短集合里的 `U`）。
