## 根因（服务端，而且只在权威平台上发生）

丢字那一次的服务端探针录到：

```
+0.38s  project='样本 · 迷雾入城'   len=98074
        请求体里带那段字      = True    ← 客户端确实发出去了
        _canvas_put 返回后文件里有 = False
        status = 500 {"category":"write_failed","detail":"could not save"}
```

`os.replace(tmp, canvas.json)` 覆盖一个**正被打开读**的文件，Windows 抛
`PermissionError [WinError 5]`；POSIX 上 rename 覆盖打开的文件是允许的。
而 `canvas.json` 的读者到处都是 —— 服务端为运行中的 run 组装事实要读它、
`_canvas_get` 要读它、创作者的备份/同步软件也可能开着它。

**所以这是一条只在 Windows 上发生的数据丢失，而 Windows 是本仓库的裁决平台**
（ADR-0062）。Ubuntu CI 全绿对它一个字都没说。

## 三条被证据推翻的说法，其中一条是我自己的

| 说法 | 出处 | 推翻它的证据 |
| --- | --- | --- |
| 「写在到达 `ctx.persist` 之前就没了」 | §6.12 原登记 | `persist` 的 warn 一次没出现 → 它走的是保存分支 |
| 「载入期间重画出来的框没上锁」 | **本卡实施者的第一个假说** | 丢字那刻 `isLoading=false`、`readOnly=false`、`hasOnInput=true`、`is-loading` 期间重画 **0 次** |
| 「控制台没声音 = 没走到保存」 | §6.12 原登记的推论 | 走到了；**失败之后没人吭声**才是那条静默的来源 |

第二条值得单独记：那**是**一条真实存在的代码路径（`pollProposals` 的异步回调会
在载入窗口内重画），但这次丢字走的不是它。**代码里存在一条路径，不等于这条缺陷
走的是它** —— 差一点就照着错的假说改了代码。

## 取证方法本身是这次最难的部分

**探针会把这个缺陷探没。** 基线（不带探针）8 跑 2 红；四版探针里三版让它消失：

| 探针 | 做法 | 结果 |
| --- | --- | --- |
| v1 | 打字前后各 4 次 `page.evaluate` | 10 跑 0 红 |
| v2 | 页面内被动监听，事后取 | **1 跑即复现** ✓ |
| v3 | 页面内包一层 `fetch` | 12 跑 0 红 |
| v4 | Playwright 侧读 85KB `post_data` | 13 跑 0 红 |
| v5 | **服务端** `_canvas_put` 记一行 | **1 跑即复现** ✓ |

**一个能让缺陷消失的探针，它测出来的绿是假的。** 可用的只有两类：页面内被动监听、
以及完全在另一侧（服务端）的记录。

## 修了什么

1. **服务端**：`_replace_retrying()` —— 冲突是短暂的（读者读完就松手），重试
   6×25ms；上限故意短，这是请求处理线程，宁可如实报错也不许把请求挂住。
   仍失败时**把原因照带**，不再压成一句 `could not save`。
2. **客户端**：`persist.js` 的 `_write` 在 PUT 非 ok 且非主动中止时，
   不再只往 `localStorage` 一塞就完事 —— `console.warn` + 可注入的
   `_onSaveFailed`，`app.js` 接到 toast。**存副本和说出来是两件事，都要做。**
3. **加固（与本条根因无关，但确实是缺口）**：`editlock.js` 加注入式观察者，
   锁定期间被重画出来的输入框也会被锁住。它是 2a 在上一轮记为「可接受、未修」
   的那条；**没有拿它冒充本卡的修复**。

## 独立审查（codex，1 轮）

**无 BLOCKING**，但 Requirement 两条 `NOT_EVIDENCED` + `VERIFICATION: INSUFFICIENT`。
按 ADR-0081 的分级表这是 P1 级、但**只补证据不动产品代码 → 不买新一轮**：
补完跑归属域即收口。三条**全部接受，没有反驳**：

| 它说什么 | 为什么对 | 补了什么 |
| --- | --- | --- |
| 「原因照带」那条只断言了「不等于旧那句话」 | 那在 detail 换成**任何一句新的固定文案**时同样成立 —— 等于没查 | 改为断言异常**类型**与异常**自己那句话**都在 detail 里 |
| 创作者可见的失败**未被驱动** | 前端守卫注入了自己的通知口，真正会被他看见的那条路径一次没跑过 | `tests/contract/test_frontend_write_path_invariants.py` 加一条接线守卫（入口编排层，该文件既有边界）。**变异验证：删掉接线当场转红** |
| 生产那个 `MutationObserver` **未被驱动** | 注入的观察者把它绕开了 —— 与定时器那条 P1 同一个形状 | 导出 `defaultObserve`，用假 `MutationObserver` 驱动它：盯不盯子树、认不认后代、文本节点算不算、解锁断不断开 |

**第一条最值得记**：`assert detail != "could not save"` 看起来在守「原因要照带」，
其实只守住了「别用那一句」。**断言写成「不等于某个旧值」，等于给未来任何一个新的
固定文案发了通行证。**

补完之后：`pytest tests/studio tests/contract` **930 passed** ·
前端 `node --test` **2273 passed** · `lifecycle_check` 0 finding。

面对同样的沉默。

**不许沉默**，不因为这次修好了就不需要 —— 下一个吞异常的分支出现时，
它还得是那个会喊的人。
