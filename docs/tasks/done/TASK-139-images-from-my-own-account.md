## 为什么现在做

图片自动生成今天只有 [ADR-0045](../../adr/ADR-0045-prototype-paid-image-generation.md)
那条按次计费的路（MiniMax image-01，$0.0035/张），它锁在 `--enable-paid` +
`AI_VIDEO_WORKFLOW_ENABLE_PAID_COMMANDS=1` 后面，而闸后面的每一张还要他确认金额。
于是这条路**一直停着**，手工路（复制 prompt → 网页版 Gemini → 传回来）成了实际唯一选择。

[ADR-0100](../../adr/ADR-0100-account-quota-is-not-a-paid-gate.md) 决策 1 把闸的判据
定成「这一次调用会不会产生一笔按次账单」。按这个判据，用他账号免费额度出图**不过闸** ——
和 `claude-code` / `codex-cli` 跑在他订阅上是同一类事。

### 补审轮 2：修复自己引入了三条 P1

轮 2 判 `fail`，3 条新 P1 —— **全在轮 1 的修复代码里**，按 ADR-0081 §2a 买它自己那一轮：

1. **同意用 `bool()` 判**（`server.py`）。`bool("false")` 是 True，一个前端把复选框的值
   当字符串传过来，「显式确认」就成了一句空话。改判 `is True`。
2. **意外放掉在途标记时没留下「不确定」**（`server.py`）。`except BaseException` 那条
   出口只 discard 不记 —— 请求可能已经送到供应商那边了，而下一次同样的请求可以直接
   重放。**同一条 P1 从另一个出口漏了出去**：修一处出口不等于修了那个类。
3. **隔离动作自己会删掉上一次隔离的证据**（`credstore.py`）。名字循环跑满 100 次之后
   `backup` 仍然存在，而 `os.replace` 会把它盖掉。改成**名字用完就停手**并报错 ——
   他能自己清掉那些文件，被覆盖的字节回不来。
   （同样的 100 次上限写法在 `runstore._load` 里也有，**那是仓库里的既有缺陷**，
   不在本卡范围，已记 Follow-up。）

放对的位置：**制作画布 ③ 生成视频 的镜头卡上**，就在那句「还没有画面」旁边
（`ui/epcanvas.js`，绑定在 `production.js` 的画布那一段）。只在**这一镜还没有画面**
时出现 —— 它是那个洞的出口，不是常驻控件；主按钮仍然是「下一步」。

**顺手修了一条挡路的真缺陷**（[TASK-087 §5.19](../active/TASK-087-followup-ledger.md)）：
卡片取的 `s.poster` **这个字段不存在**（`episodeShots` 摊平的是 `storyboardModel`
的镜头，当前画面在 `thumb` 上），所以那张卡从上线起就永远显示「还没有画面」，
哪怕关键帧早就打了勾 —— 截图里三张卡都是这样。它本不在本卡范围（第 17 条），
但**它挡住这颗按钮**：出完图卡片仍说没有画面，他会以为没成功、再点一次，
而那是一次真的重复消耗。按第 17 条的例外就地修掉，只改这一处取值。

验证：`node --test` 全量 **2206 passed / 0 failed**（新增 2 条钉那一屏：没有画面时
卡上带 `data-ec-gen` 且主按钮仍在、有画面时那颗按钮消失；后者用**真的资产登记路径**
造图，不靠一个不存在的字段）。

### 出图成功了，但图完全不对 —— 模型读不懂中文（2026-09-05）

产品负责人第一次真出图之后：「这个生成是根据什么做的呢。怎么完全不对」。

**先查台账，不猜**（`data/account-image-log.jsonl` 记着实际发出去的前 120 字）：
发出去的确实是人物页那段编译好的中文设定，取值没错。于是做**对照实验** ——
同一份设定、同一个 seed，只改语言：

| 发出去的 | 回来的 |
| --- | --- |
| 中文原文 | 和服少女、暖色日式室内。除「东亚女性」外几乎全错：三十出头 / 短发 / 黑衬衫 / 冷侧光 / 都市悬疑，一条没中 |
| 英文改写 | 短发、黑衬衫、冷灰调、眼下阴影、克制表情，甚至自发给了多视图排布 —— 与设定基本对上 |

**所以缺陷不在取值，在语言**。Pollinations 只有 `sana` 一个模型（`/models` 实测），
换模型这条路不存在。

修法：**发出去之前把中文编译成英文**，用本地 `claude-code`（他的订阅内，不产生
账单；不引第三方翻译服务 —— 引一个就等于在「不花钱」这条路上开了个会花钱的口子）。

三条纪律，每条都是这个仓库踩过的坑：

1. **不静默替换他的字。** 界面上他编辑的仍是中文；**实际发出去的英文那份回给界面
   并显示在提示里**，台账**两份都记**（只记原文就判不了是不是编译走样，只记译文就
   对不回他改的哪句话）。
2. **fail-closed**：编译不出英文就**一张图都不出**（`prompt_translation_failed`，
   `side_effect: none`，一个字节没发）。硬发中文只会再出一张与设定无关的图，
   而他要从那张图反推「是设定没写清还是模型不行」几乎不可能 —— 那正是这次事故的形状。
3. **回来还是中文 = 没照做**，同样拒绝。
4. 已经是英文的提示词**不白跑一次本地模型**。

**顺带修掉一条测试卫生问题**：加完翻译后这个测试文件从 1.5 秒变成 **144 秒** ——
每条用中文 prompt 的用例都真的起了一次本地 claude，慢、不确定、还烧他的订阅。
夹具里默认打桩，翻译本身由那一组专门用例守（真件留一份给它们用）。

验证：`pytest tests/studio/test_account_image_gen_task139.py` **55 passed（1.1 秒）**·
`node --test` 全量 **2220 passed / 0 failed**。

**还没做**：设置页显示「现在用的是哪一家 + 后四位」（判据 3 的界面那一半 ——
凭据现在从 `.env.local` 走，界面缺的是**说出当前来源**，否则「我明明改了」会没处对证）。
