## 0. 要解决的用户问题

**创作者答不出「这个系统一共能帮我做哪些事」，也没法主动叫它做。**

- `GET /api/skills` 实测返回 **21 个 Skill**（+1 deprecated），每个带
  `role / purpose / inputs / optionalInputs / reviewCriteria / outputSchema /
  recommendedRuntime / skillDigest / source`，外加 `problems[]` /
  `inputs{}`（12 个共享上下文）/ `shotScopedInputs[]`（5 个镜头级）。
  **界面上它只是右栏 AI 导演里一个折叠行「能力 21 个能力」。**

  创作者必须**先导航到正确的页面**才能得到正确的能力 —— 系统的内部路由规则
  变成了用户的负担。

## 1. 交付

### 1.1 Skill 目录界面

**约束先说清**：ADR-0066 决策 10「新增 Skill 不得新增一级或二级页面」约束的是
**每个 Skill 不得各占一页**，不是「Skill 目录不能有页」。一个目录页是
**一页承载全部 21 个**，正是该约束想要的形状。**实施前在卡里写明这个论证**；
若判断仍冲突，落到 ⚙ 项目设置的一个分区，**不要静默新增一级页**。

**实施结论：落到 ⚙ 的一个分区。** 与决策 10 本身不冲突，上面的论证成立；真正
冲突的是 IA 的另一半：`PAGES` 是**十一页的封闭集合**，`workspaces.test.mjs` 的
「the IA is a CLOSED set」直接断言 `PAGES.length === 11`。靠改那个数字来通过测试，
就是让一个「冻结集合」不再冻结。而 ⚙ 项目设置本来就在三空间十一页**之外**
（shell.js `PROJECT_SETTINGS` / §1.7），所以目录落在 ⚙ 的一个分区里，两条规则
都不用动——这正是本节事先写好的退路。完整论证在 `src/ui/skillcatalog.js` 头部。

**要做**：
- 分类 / 搜索 / 按 `work`（creative / review）分组
- 每张卡：`role` · `title` · `purpose` · **需要哪些输入**（`inputs` + `optionalInputs`，
  用 `/api/skills` 已返回的 `inputs{}` 标签表翻译成人话）· 是否 `shotScoped` ·
  `recommendedRuntime` · `source`（project / user / builtin）
- **可用性与失败原因**：`problems[]` 已经在 payload 里，**加载失败的能力必须
  可见且带原因，不得从列表里消失**（ADR-0067 决策 7）
- `deprecated[]` 的能力标出来，不与在用的混排
- 「在当前上下文运行」：把当前选中对象作为输入送进 Run

**明确不做**：Skill 市场 / 远程安装 / 编辑 Skill 包 / 评分收藏（ADR-0067 明确不做）。

### 1.2 右栏统一为一个 Agent 会话

**目标形态**（对位 T-004 / T-045 / T-046）：一个**常驻会话**，上下文由用户**显式给出**，
不由「你在哪一页」隐式决定。

- **`/` 唤出 Skill**（全表，不是四张推荐卡）—— 复用 1.1 的目录数据源
- **`@` 引用对象**进上下文：镜头 / 角色 / 场景 / 场景地 / 资产 / 剧集。
  **稳定 id 全都已经有了**（`shotId` / `characterId` / `locationId` / `assetId` / `episodeId`）
- 当前上下文**可见且可编辑**（今天是隐式的，用户看不到也改不了）
- Run 历史（`runstore` 已经有持久化 Run 记录）

**迁移纪律（本卡最容易出事的地方）**：
1. 四个面板的**能力**一个都不许丢。本卡合并的是**入口**，不是删功能。
2. 页面仍可**预填**上下文 —— 只是不再是唯一来源。
3. `directorshot.js` 的「缺少清单 / 下一步」是**镜头级的诊断**，价值很高，
   合并后必须仍在（作为会话里的一个上下文卡片，或保留为镜头级区块）。
4. **分批次**：批次 A 只做「一个会话 + `/skill` + `@对象`」并让四个旧面板
   仍可达；批次 B 才收旧入口。**不要一次性替换。**

## 4. 验收（产品负责人看的）

1. 有一个地方能看到全部 21 个能力，每个说清「它要什么输入、产出什么」。
2. 加载失败的能力**看得见**，并写明为什么。

5. 换一个页面，会话**不重置**，上下文可以自己改。
6. 原来四个面板能做的事，一件都没少。
