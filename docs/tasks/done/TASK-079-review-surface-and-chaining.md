## 1. 交付

### 1.1 ⑨ 粗剪审片做成「故事板」形态

**现状**：`cutreview`（⑨ 粗剪审片）在 TASK-077 之前**完全不可达**
（`production.js:807` 有渲染器、`:1562` 有绑定，`activeModule === "cutreview"`
永远不成立）。TASK-077 §1.5 给了它入口，本卡给它内容。

**目标形态**（对位 T-090 故事板）：**一集的镜头 × 三列清单**

| 列 | 每条显示 |
| --- | --- |
| 文本 | 镜头名 · 画面描述摘要 |
| 图片 | 缩略图 · **尺寸** · **模型** · 状态 · `问 Agent` |
| 视频 | 可播缩略图 · **模型** · **时长** · **尺寸** · **首帧来源缩略图** · 状态 · `问 Agent` |

- 筛选：`全部` / `已通过` / `待审` / `已生成` / `待生成` / `失败`
- 每条一个「问 Agent」把这一项丢进 AI 导演的上下文
- 「✓ 通过 / 跳过」保留，但**本卡不接评价闭环** —— 那是 Phase 3.4（GAP-05），
  四个 Gateway 命令今天只注册在 `workspace_shell`

**数据全都现成**：`canvas.assets` / `canvas.generations` / `canvas.shotAudio` /
`workflow/prodgraph.js` 已经能算出每个镜头的产出状态。**不建第二份状态。**

> **一屏之内回答：这一集哪些镜头有视频、各用了哪个模型、多长多大、
> 首帧来自哪张、哪些失败了。** 这就是「审阅」这件事的基本形态。

### 1.2 「以此生成 →」通用链式

**现状**：只有资产 →「🎬 用作视频首帧」一条。

**目标形态**（对位 T-080「引用该节点生成」）：任意媒体卡上一个统一菜单
→ 下游类型 → **落到对应工作区并把这一项预填为输入**。

允许的类型对，**按现有能力如实给，不可用的要说明为什么**：

| 从 | 可以生成 |
| --- | --- |
| 图片 / 参考 | 视频（作首帧）· 图片（图生图 / 改写）· 设为角色参考 |
| 视频 | 提取尾帧 → 下一镜首帧 · 配音 · 进时间线 |
| 音频 | 进时间线 |

- 落点必须**预填输入**，不能只是跳转到一个空页面
  （「落到一个没有该内容的页面」= ADR-0063 决策 1 禁止的失败）。
- 不可用的组合**灰掉并说明原因**，不要隐藏。

### 1.3 失败态工单化（顺带，成本很低）

**现状**：失败是 fail-closed 报错 + 一段有界的原始输出摘录 —— 姿态对，
但**那次生成的输入没有被保留成可以重开的对象**，也没有「把这次失败交给
AI 导演诊断」这个动作。今天**只有成功进 Generation 注册表**。

**目标形态**（对位 T-093）：失败保留 参考 + Prompt + 模型 + 规格 + 单价 + Run id，
卡上三个动作：**同参数重试 / 改参数重试 / 交给 AI 导演诊断**。

**要做**：失败也进 Generation 注册表，`status: "failed"` + 失败原因。

> **这一条动生成登记 = 高风险。** 若与 1.1/1.2 一起做会把整卡拉到高风险档。

## 6. 实施记录（2026-08-16）

### 6.1 批次 A（中风险）—— 已提交 `529185f`

| # | 改动 | 文件 |
| --- | --- | --- |
| 1 | ⑨ 粗剪审片 = 一集的镜头 × 三列清单；六个筛选各报各的条数；每条一个「问 Agent」 | `ui/cutreview.js`（新） |
| 2 | ⑧ 步骤④ 保留逐镜头走查；「逐镜头看 →」把位置交接过去 | `ui/production.js` |
| 3 | 「以此生成 →」通用链式菜单 | `ui/chain.js`（新） |
| 4 | 生成记录暴露 `model` / `resultAssetIds` / `error`（此前只到 provider） | `ui/storyboard.js` |

**两处按如实交付而非照抄卡面**：

- **没用 `prodgraph`，用了 `dailiesModel`。** 卡上 §1.1 写「状态取自 prodgraph」，
  但 `productionModel` 只作用于**场景已认领**的镜头。真实项目 60 个镜头**全部
  未归组**，用它会渲染出一个空白审片页——一个看起来诚实、实则什么都不显示的
  屏幕。`dailiesModel` 覆盖未归组池，且两者调的是**同一个** `shotprod.shotStage`，
  所以「不新建第二份计算」这条实质满足。
- **尺寸如实写「未记录」。** 资产登记表里没有像素尺寸，视频**实际**时长也没人
  存过（只有设计时长 6/10s，已标注为「（设计）」）。按 TASK-077 的姿态如实标注，
  不编数。**这是真实缺口，见 §7 Follow-up。**

**链式菜单的诚实处**：
- 图片→视频（作首帧）、视频→提取尾帧→下一镜首帧 都是**真操作**
  （后者走 `framectl` 的 `extract` + `bind`，传的是**提取溯源对象**而不是裸 shotId）。
- 图生图、设为角色参考**今天没有能力**，灰掉并写出原因，不隐藏。
- 进时间线如实标注是**派生**的——时间线由每个镜头的当前媒体自动纳入，
  写成「加入」会让人以为做了一个不存在的动作。
- 「没有下一镜」的**两种原因分开说**：真实项目里是「没归入任何场景」
  （`nextShotOf` 按场景取），不是「这是最后一镜」。混为一谈就是假话。

**独立审查**：codex 2 轮，第 2 轮 `pass` 零发现。round 1 的 P1 正中要害——
`latestGen` 只按类型取最新那次生成，于是「早先一次成功产出、后来又失败一次」
的镜头会把能播的那条视频标成 `failed` 并挂上失败那次的模型，**而这一页存在
的全部意义就是把出处说对**。改为按 `resultAssetIds` 认领当前资产，复用
`shotDetailModel` 已有的同一条规则。

### 6.2 批次 B（**高风险** · 生成登记）

**卡上 §1.3 说「今天只有成功进 Generation 注册表」—— 实测不是这样。**
失败早就能进（`ctx.failGeneration`），记录里也**已经冻结了**参考 / Prompt /
模型 / 参数。真正缺的只有一样：**失败原因根本没被存下来**。所以本批次不是
「让失败进登记表」，而是**「让失败说得出为什么」**，改动因此小得多也精准得多。

| # | 改动 | 文件 |
| --- | --- | --- |
| 1 | `failGeneration(reg, id, status, reason)` 记下原因（加法字段、截断 500） | `workflow/genlib.js` |
| 2 | 付费提交**服务端明确回非成功**那条分支带上真实原因 | `app.js` |
| 3 | 生成卡上的失败工单：模型 · 服务 · packet 版本 · Run id · 当时的 Prompt · 原因 + 三个动作 | `ui/gencard.js` |
| 4 | 「交给 AI 导演诊断」由 shell 接线，事实随按钮属性传递 | `ui/production.js` |

**刻意没有碰的既有不变量**：付费提交**抛异常**那条路径**故意不标失败**——
远端可能已经接单并计费，标失败会让一笔已付费的成功被永久孤立。那里的注释把
理由写得很清楚，我只在**服务端明确回了非成功**的分支上补了原因。

**预检被阻断的失败不记成 generation**：那时什么都没启动，记一条会是在编造历史。
这些阻断已经在生成卡上就地显示。

**独立审查**：codex 2 轮，第 2 轮 `pass` 零发现。round 1 的 P1 不是代码错，是
**措辞在替系统承诺它做不到的事**：按钮写「同参数重试」，实际调普通提交，而付费
路线的每一项参数都来自**当前**已编译的 packet；失败后若重新锁定过分镜，跑的就是
另一个作业，却打着「同参数」的旗号扣费。**做法是停止做这个声称**（没有去发明
重试语义——后端对同一 task 已有付费操作会拒绝并要求建 redo task，那是领域尚未
定义的东西）：按钮改为「重新提交（按当前 packet）」，工单写出当时跑的 packet 版本，
并明说真正的同参数重放需要 redo 任务。round 1 的 P2（provider 收集了没显示）同批修掉。
