- 状态：完成（2026-08-29）
- Workflow：Feature + Bug · 深度：SHALLOW
- 关联 Requirement：[REQ-004](../../requirements/REQ-004-three-pane-shell-and-agent-conversation.md)
  v2 判据 3（对话的另一端是能干活的 Agent）—— 本卡补的是它的**出口**；
  版本展示这一半没有既有 REQ，写技术目标（下）
- 关联 ADR：[ADR-0089](../../adr/ADR-0089-conversational-agent-write-path.md) 决策 3 / 3b
- 技术目标：① 创作页面默认只展示最新版本，旧版按需展开（不删、不改版本链）；
  ② 一条已经提出但没落下的改动，屏幕上要有办法把它落下
- 起因：产品负责人 2026-08-29 —— 「你修改的内容没有反应到这个页面上」
  「我希望只有最新版可以看到。旧版就不看了」

## ① 只露最新版

`src/ui/versionrow.js`（新）：默认画**最新版**，外加**当前依据的那一版**（`active`
不是最新版时 —— 藏起它等于藏起「你现在基于的是哪一版」，那是产品事实不是历史），
其余收进「历史版本 N」，展开一次全在。大纲页里**已批准**的那一版同样常驻（带 ✓），
它是下游的闸门。

创意（`briefws.js`）与故事大纲（`storyws.js`）共用这一个函数 —— 两处各写一遍就会
各自漂移。**旧版本一字未删**：改的只是默认露不露。

## ② 「落到作品上」

TASK-111 的自动落地发生在**发送这一轮的那个页面上下文**里。它没发生时（页面还跑着
旧代码、轮询超时、当时开着别的标签页），屏幕上就剩「它说已经改好了」+「还没落到
作品上」互相打脸，而他没有任何办法把它落下 —— 这正是他看到的。

- 每组「它建议的改动」上加 `落到作品上`，走的是与自动落地**同一个**
  `applyConversationEdits`，所以两条路不会有两种行为
- 已经有回执的那一轮不再给出口（防止落第二遍）；大纲与「做不到的事」不给出口
- 自动落地改为**先刷新、再从这一轮自己那条 turn 上取 edits**：线程是服务端的真相，
  run 只是它的快照，快照可能因为超时而没有 outputs

## 查错记录（我先判断错了一次）

先怀疑是浏览器缓存了旧 JS，动手加了 `Cache-Control` / `Last-Modified`。**判断错了**：
`Cache-Control: no-store` 本来就在（`_SECURITY_HEADERS`），是我看响应头时用
`head -8` 把它截掉了。那个改动已整份撤回，本卡不含任何服务端改动。真实成因是页面
在部署前就已经打开 —— 内存里的旧模块，缓存头救不了，只有刷新。
