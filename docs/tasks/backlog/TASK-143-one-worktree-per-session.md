## 病根

**共享工作树 + 全仓级闸门检查 = 任何一个人的在制品都是所有人的红灯。**

这不是纪律问题。每一条单独看都有「本来就该这么做」的正当理由：
`ruff format --check` 就该全仓跑、生成物就该与源码同进同出、闸门就该在提交前拦。
它们只是都**默认「一个仓库一个人」**。

同一个默认还制造了归属错乱：`git commit -- <paths>` 只限定**文件**、不限定**文件里的
哪些行**，所以「核对 diff」与「执行提交」之间那几十秒就是风险窗口。

## 七种形状（2026-09-05～06 实测，各有出处）

| # | 形状 | 谁被挡 |
| --- | --- | --- |
| 1 | `lifecycle_check` / 文档链接红（别人搬卡，我的提交红） | 全部 |
| 2 | `ruff format --check` 全仓跑，一个人的未格式化在制品挡住所有人（§6.14） | 全部 |
| 3 | 生成物与源码不同进同出（改了 skill 源没跑 `agent_harness.py apply`） | 全部 |
| 4 | 脏 index：裸 `git commit` / `git add -A` 把别人 staged 的改动一起带走（§5.24，两个方向各撞过一次；其中一次是**险过**，见状态栏 ③） | 归属错乱 |
| 5 | `autopush task-ready --paths` 是**整份替换**不是追加，一张卡两个会话共用时会互相抹申报（§5.25） | push |
| 6 | `record-commit` 不带 `--hash` 时记的是 HEAD，而 HEAD 在那几秒里被别人推走了 → 幽灵记录 | 登记 |
| 7 | 未登记提交挡住整条分支的 push（别人的提交，我不能替他申报验证结论 —— AGENTS §18） | push |

## IN SCOPE

1. **每个会话一个 `git worktree`**（同一个仓库、各自的 index 与工作树、各自推分支）——
   §6.11 已经实测过这条路可行（那次合并全程在 `worktree add --detach` 出来的目录里做完，
   共享树上别人的未提交文件一个没动）。要定的是：谁建、建在哪、什么时候回收、
   怎么让新会话默认落进自己那棵。
2. 上表 4 / 5 / 6 三条**与 worktree 无关**，worktree 隔离消不掉它们 —— 哪怕一人一棵树，
   一张**共用的台账卡**仍然会被整份替换掉别人的申报。三条是同一族：
   **auto-push 在「范围」这件事上只做了一半** —— 申报范围整份替换、提交范围不带路径、
   回写范围不现算。
   - 第 4 条（提交范围不带路径）**已有写好的提案，本卡不重述、不实施**：
     [EP-002](../../skill-evolution/proposals/EP-002-writeback-commit-needs-a-pathspec.md)
     （PENDING，等 `visual-try-on-project-23` 的用户答复）。修法是给 `record-commit`
     返回的第二条命令加上同一个 pathspec，一行。**本卡指过去就好** —— 同一个修法
     两处主张、两个人分别实施，正是判据 4 要消掉的「两处陈述」，只是跨了卡和提案。
   - 第 5、6 条本卡认领：`--paths` 改成可追加（或至少在覆盖别人的申报时拒绝并提示），
     `record-commit` 去掉记 HEAD 的默认。
3. 一条给 Agent 的操作规则，写进 AGENTS.md §5 —— **只有在 worktree 方案实测稳定之后**
   （§6.11 现在的措辞就是「若日后证明稳定应升进 AGENTS.md §5」）。

## OUT OF SCOPE

- **不改闸门的严格度**。把 `ruff format --check` 改成只查改动文件、把全量改成增量，
  都是在给「机器过载」和「别人的在制品」发免罪符 —— 病根是共享，不是闸门太严。
- 不引入任务分配器 / 锁服务 / 中央协调进程。会话之间靠仓库文档与 Git 状态共享上下文
  这一条不变（AGENTS 开头）。
- 不碰 `docs/skill-evolution/` 的 append-only 数据形状（§5.24 是提交姿势的问题，
  不是数据结构的问题）。

## 完成判据

1. 一个新会话开始工作时，**默认**不与他人共用 index 与工作树；文档写明怎么建、怎么回收。
2. 上表 7 种形状逐条给出「还会不会发生」的判词；不会发生的说明为什么，仍会发生的
   写明残留代价。
3. auto-push 那两条（5 / 6）有测试钉住：`--paths` 不会静默抹掉别人的申报，
   `record-commit` 不会在 HEAD 被推走时记错提交。**第 4 条不在本卡判据里** ——
   它归 EP-002，本卡收口时只需确认那份提案已落地或仍 PENDING，并如实写明。
4. §6.11 / §6.14 与 §5.24 / §5.25 / §5.30 在本卡收口时更新为指向本卡，不留两处陈述。
