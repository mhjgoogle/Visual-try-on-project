## 2. 当前剧情制作 UI 为什么“能用但不满意”

四入口方向仍然正确，问题在中间工作区没有形成同一套创作语言：

| 当前面 | 当前真实形状 | 用户感受到的问题 |
| --- | --- | --- |
| 故事核心 | 说明文字 + 最小高度 52vh 的单一 textarea + 字数/定稿/历史 | 像打开一个空白记事本；看不到主角、欲望、阻力、代价和变化是否已经说清，也看不到下一步 |
| 故事大纲 | 大 textarea，下方再画一份最多 220px 高的节点清单，并常显稳定 ID | 同一内容重复两遍；技术 ID 抢视觉注意力；看不到故事节奏、段落先后与结构缺口 |
| 结构规划 | 最小宽度 1100px 的九列表格，每格两行 textarea，主要靠横向滚动 | 九列视觉权重相同；用户难以扫出“这一段发生什么、为什么必须发生、结尾变成什么” |
| 正文创作 | 数字章/集按钮 + 200–260px Brief + 大 textarea + 一排工具按钮 | 章节只有编号，没有标题、状态或关联场景；Brief 是字段堆叠；写作过程缺少节拍导航和连续性提醒 |

跨页面还有四个共同问题：

1. 四页只有左栏顺序，没有常驻的“已完成什么 / 当前在做什么 / 下一步是什么”。
2. 大纲节点、结构规划行和正文单元虽然有引用，但用户主要看到的是控件，没有看到故事关系。
3. Agent 在右栏能改内容，但页面没有“先看建议和差异，再应用”的剧情编辑体验。
4. 版本、回收区、Copy、切换形态等管理动作与创作主动作混在同一层，写作焦点不稳定。

## 3. 上游哪些剧情 UI 值得借

### 3.1 Production Hub：借“故事现在卡在哪”，不借多层导航

上游截图最有效的一块是中间的 Next Best Step：一句当前焦点、一个最推荐动作、五张准备度卡；再下方
才是完整工作流。把它适配为本项目故事开发顶部的**创作进度条**：

`故事核心 → 故事大纲 → 结构规划 → 正文创作`

每段只显示 `未开始 / 可继续 / 有阻断 / 已定稿` 与简短证据，右侧只给一个主动作。状态最终来自
TASK-135 的服务端计划；TASK-135 未完成前只显示能由现有正式版本直接证明的事实，不用字数阈值猜完成度。

### 3.2 Director Treatment：借“创作罗盘”和修改预览

上游 Director Treatment 把分析压成 mood、visual theme、pacing、key symbols，再为每个 shot 给
description、rationale、camera/lighting/prompt。剧情制作阶段可借前一半：在故事核心与大纲顶部显示一个
可收起的**创作罗盘**：主角驱动力、核心冲突、情绪方向、节奏、关键意象。

这不是第二份 Story Bible。它是 Agent 对当前版本的分析卡，必须带 `basedOnVersion`，明确标成“分析/建议”；
点击“采用”时展示将改哪几处，经既有提案/Action 应用。正文永远不会因重新分析被静默覆盖。

### 3.3 Scene Wall：借故事卡、排序和暂存区

上游 Scene Wall 最适合本项目结构规划：它按 Reel 画横向列，列中放 Scene Cards，可拖动、复制、双击进
Storyboard；不用的场景进入 Parked / Omitted，而不是删除。选中一张卡后再看完整元数据和 Shot Cards。

本项目不新增 Reel 模型。直接把现有结构规划行做两种同源视图：

- **故事墙（默认）**：按 `Unit No.` 分列；同一 Unit 可有多张 Scene 卡。卡面只露
  `Scene / 目的 / 主要人物 / 冲突 / 关键转折 / Ending State`，大纲引用显示成 `§1 · 文本摘要`。
- **表格（精确编辑）**：保留既有九列与 Excel 式格线，作为批量、精确录入视图。
- **暂存区**：直接投影现有 hidden/软删除行，允许拿回来；不增加第二种删除语义。

两种视图读写同一行、同一稳定 ID。拖动只改变正式顺序；先显示落点预览，再经统一 Action 执行。
不得复制一份 wall state，也不得按数组下标或 `Unit No.` 充当身份。

### 3.4 Microdrama：借节拍条，不借硬编码爆点公式

上游 Microdrama 把 90 秒文本拆成 Hook 0–15、Escalation 15–60、Freeze 60–90，并在右侧做三个检查。
值得借的是“写正文时始终看得到节拍与时间位置”。本项目应根据当前 Unit 关联的结构规划行，画一条
**场景/节拍条**：每张卡显示场景、目的、冲突、转折与 Ending State；点击只切换 Brief 焦点。

不能照搬 Billionaire Romance、Enemies to Lovers、固定 40 秒反转、90 秒 cliffhanger 或关键词校验。
这些是上游的具体内容模板，不是通用剧情合同。节拍来自用户的结构规划；没有就明确显示“尚未规划”。

### 3.5 Scene Map：只作为进入剧集制作后的视觉预演

Scene Map 的角色/道具/环境素材栏、2D 平面、3D blockout 与右侧属性面板适合场面调度，不适合故事核心、
大纲或正文。它可以启发已有 3D 导演台和单镜画布，**本卡不把它塞进故事开发**。

## 4. 建议的新中间工作区

全局左栏四入口与右侧 Agent 都保留。改变的是中间工作区内部：

```text
┌ 故事开发 ──────────────────────────────────────────────────────┐
│ 核心 ✓  →  大纲 ●  →  结构规划 8 行  →  正文 2/12     [下一步] │
├─────────────────────────────────────────────────────────────────┤
│ 当前版本与上游依据                 [专注写作] [历史/管理 ···]   │
├─────────────────────────────────────────────────────────────────┤
│ 创作罗盘（可收起；Agent 分析，带版本，不是第二份真相）          │
├─────────────────────────────────────────────────────────────────┤
│ 当前页面的唯一主工作：编辑器 / 故事墙 / 正文                    │
│ 管理动作退到次级层；问题、引用和版本变化在内容旁边解释           │
└─────────────────────────────────────────────────────────────────┘
```

### 故事核心

- 保留“一个大型编辑器”的产品决定，不改成字段表单。
- 编辑器上方只加一行创作罗盘摘要和一个主动作，例如“让 Agent 检查核心矛盾”。
- Agent 返回的是带 before/after 的建议，可逐项采用；原文仍是唯一可编辑真相。
- 字数、定稿、历史与回收区收入右上角“版本”菜单；常态不占正文下面一整块。

### 故事大纲

- 中间使用**文本 / 结构**分段开关，仍是一页，不新增一级入口。
- 文本视图继续像普通文本编辑器；左侧行号只显示 `§1`，稳定 ID 放 tooltip/详情，不常显一串技术字符。
- 结构视图把同一 nodes 画成纵向/横向故事卡，显示摘要、被哪些结构行引用、是否悬空；拖动是对同一 nodes
  的正式重排，不能只改视觉顺序。
- 选中节点后，右栏 Agent 自动获得 nodeId 与版本上下文，可做“扩写、压缩、找逻辑跳跃、拆成两段”。

### 结构规划

- 默认显示按 Unit 分列的故事墙；卡片强层级展示“Scene → 冲突 → 转折 → Ending State”，人物与大纲引用
  用弱化 chip。点击卡片在同页侧抽屉编辑完整九字段。
- 顶部保留“故事墙 / 表格”开关。表格保留九列，但冻结 Unit No. 与 Scene，长字段按需展开；不要求用户
  一直横向滚动才能知道自己在改哪一行。
- 支持暂存、恢复和拖动排序；批量能力等真实使用后再做，不提前制造工具栏。

### 正文创作

- Unit 选择器从“数字方块”改成带标题、字数/定稿状态、关联场景数的卡片或下拉；大量单元默认只显示当前、
  前后各一个及搜索，不铺满整行。
- 左 Brief 改成可收起的**场景任务栈**，一张结构行一张卡；用户点击场景，只改变 Brief 焦点，不伪装能跳
  到正文中不存在的锚点。
- 编辑器顶部只留一个主动作和最常用的 Copy；定稿、版本、切换小说/剧集收入次级菜单。
- 增加“专注写作”：中间工作区全宽，左栏和右 Agent 变成可唤回抽屉；退出后恢复三栏。它落实当前收敛
  审查已经提出的 1280px / Windows 125%–150% 缩放方案。

## 5. Claude 的实施切片

### 切片 A：同源故事墙，先解决最差的结构规划体验

1. 开工按 `dev-workflow` 把本卡移到 active，追加 REQ-006 UI delta；读取 TASK-127 当前 Action 合同。
2. 从 `story.work.plan.rows` 派生故事墙 model：按 Unit No. 分组、同组保持正式顺序、hidden 行进入暂存区、
   outlineRefs 解析成节点摘要，悬空引用继续明确标错。
3. 在 `planws.js` 内拆小组件/纯 model，不把更多逻辑堆进 `production.js`。增加“故事墙 / 表格”页内开关；
   默认故事墙，表格功能一项不删。
4. 卡片抽屉编辑九字段与当前表格调用同一 `uiAct` / Action。拖动若没有统一 reorder Action，本切片先不画
   可拖 affordance；不能做一个刷新后还原的假排序。
5. 真实 Connected Project 验收：多行同 Unit、跨 Unit、悬空 outlineRef、软删除/恢复、窄屏与长文本。

### 切片 B：大纲结构视图与技术信息降噪

1. 文本编辑仍是默认写入面；结构视图是同一 nodes 的可视投影。
2. 常态只显示 `§N + 摘要 + 引用数`，raw nodeId 仅在 tooltip/复制定位中出现。
3. 节点重排、拆分、合并必须先补正式 Action 和稳定 ID 测试；AI 建议走提案预览，不直接改正文。
4. 大纲变化后，结构规划中的引用必须保持或诚实标成悬空，不能按文本重新猜配。

### 切片 C：正文场景任务栈与专注写作

1. 用当前 Unit No. 对应的全部 plan rows 画场景任务栈；没有对应行时显示明确入口去结构规划。
2. Unit 选择器展示标题、状态和场景数；计划外但已有内容的单元仍保留并标明。
3. 专注模式只改变瞬时布局，不更改路由/项目状态；键盘能进入和退出，焦点正确返回。
4. 正文、标题、planned 数量、定稿/恢复继续使用现有 Action 和版本规则。

### 切片 D：创作进度与 Director 建议

1. 优先消费 TASK-135 的权威 `steps[] / blockers[] / next_action`。若 TASK-135 尚未实施，本切片延后，
   不在前端建临时进度算法。
2. 创作罗盘是带版本的 Agent 分析结果；未分析显示“尚未分析”，旧版本显示“基于旧稿”。
3. 应用建议前显示逐项 before/after、理由与影响对象，用户可只采用部分；采用走统一 Action，支持撤销。
4. 页面每次只突出一个主动作；右栏仍是唯一 Agent 入口，不再加浮动 AI Tools。

## 6. IN SCOPE / OUT OF SCOPE

**IN SCOPE**：四入口内部视觉与交互重构；同源故事墙/表格；大纲结构投影；正文场景 Brief；专注模式；
权威下一步接线；带版本的 Agent 剧情分析与差异预览。

**OUT OF SCOPE**：改变四入口或 11 页闭集；新建 Story/Director/Scene Wall 页面；复制上游 23-workspace
导航；建立第二份 Story Bible/Scene Wall 状态；硬编码短剧模板；把 Scene Map 塞进剧情开发；新 Provider；
Agent 自动定稿；基于字数、文件存在或 prompt 文本猜“已完成”。

## 7. 验收

1. 新用户进入故事开发，一屏看见四阶段、当前阶段、阻断原因和唯一主动作；没有两个位置各自推荐下一步。
2. 结构规划有 12+ 行时，默认无需横向滚动即可读出每个 Unit 的场景、冲突、转折和 Ending State；
   切回表格能编辑原九列，两个视图立即一致。
3. 一行暂存后进入暂存区，可恢复；任何视图不静默删除或复制记录。
4. 大纲中用户主要看到 `§N` 与内容，结构规划引用仍按稳定 nodeId 工作；文本改写后不串引用。
5. 正文页能看出当前 Unit 标题、状态和关联场景；没有结构行时明确说缺什么，不虚构 Brief。
6. 专注模式在 1280px 和 Windows 125%/150% 缩放下保留可用编辑宽度，右栏可唤回且不丢对话。
7. Agent 建议带 basedOnVersion 与逐项差异；旧建议不能覆盖新稿；部分采用、撤销与版本历史一致。
8. 四入口、URL、现有数据、定稿/历史/回收区、UI/Agent 同 Action 合同全部保持。
