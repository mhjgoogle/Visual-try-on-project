## 1. 决定

**D-1：边只住在卡上，格式就是今天已经存在的那一行。**

    - 前置：[TASK-073](TASK-073-fixed-ia-and-contextual-agent.md) 全部验收通过
    - 前置：TASK-080、TASK-081

解析规则：以 `- 前置` 开头的行，抽取其中所有 `TASK-\d+`。链接、顿号、尾注全部容忍 ——
**解析器去认现有写法，不要求人改写**。不新建 `deps.json`、不给卡加 metadata 文件
（ADR-0101 §4 已裁决）。

**D-2：「前置完成」= 那张卡的状态行写着 `完成`。** 状态住在卡上
（[ADR-0105](../adr/ADR-0105-task-state-lives-on-the-card.md)，同日取代了 ADR-0083 的
「目录即状态」）；状态语法只有 `task_status.py` 一个源，本卡只问它 `.done`。
**第一版写的是「那张卡在 `done/`」** —— 同一天产品负责人决定不再分目录，这条跟着
换了载体，判据本身没变。

**D-3：三种坏边一律 fail-closed。** 前置指向不存在的卡（悬空）、指向自己、成环 ——
`task_graph.py check` 转红，并且 `tests/tooling/` 里有一条对着**真仓库**跑它，
所以它自动进 commit gate 与 CI。一条没人读的边可以随便写；一条机器读的边写错了
必须当场有人知道。

**D-4：队列的排序 = 拓扑序，同层按任务号。** 前置未完成的卡**不发**，但 `list` 里
照样显示并写明「等 TASK-xxx」—— 拒绝要说得出理由。

## 2. IN SCOPE / OUT OF SCOPE

**IN**：`task_graph.py`（`deps` / `check` / `order` / `blocked`）· `l5_queue.py`
按图排序与过滑 · 真仓库上的悬空/成环守卫 · 测试。

**OUT**：
- **不做优先级数字。** 边是事实（A 没做完 B 做不了），数字是意见；意见归里程碑闸。
- **不做架构依赖图**（产品负责人同一句话问的另一半）。那是另一条 Requirement：
  从 `src/` 派生模块 import 图并回答「改了 X 影响谁」。现有的只有 3 条 import-linter
  禁令 + `tests/` 根的归属派生。另立卡，不塞进这里。
- 不改任何卡的 `- 前置` 行写法。

## 3. 完成判据

1. `task_graph.py deps` 能列出全仓每条前置边；TASK-074 → TASK-073 那条**不改卡**就被读出。
2. 悬空引用、自指、成环三种坏边，`check` 各自转红，且真仓库上那条守卫在 `tests/tooling/`。
3. `l5_queue.py list` 对前置未完成的授权卡显示「等 TASK-xxx」；`next` **不发**它。
4. 两张授权卡 B 前置 A 时，`next` 先发 A；A 的状态改成 `完成` 之后才发 B。有测试钉住。
5. 收口时如实写「实现完成」与「还没在真实项目上被人看过的」两个独立事实。
