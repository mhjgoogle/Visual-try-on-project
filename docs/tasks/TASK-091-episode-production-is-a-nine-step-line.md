## 0. 产品负责人说了什么（原话）

> 「剧本是一集一份的。但是应该要放到剧集制作里面。
> 该集剧本 → Scene 拆分/确认 → Scene→Shot → Shot Design → Storyboard/关键帧
> → 图像/视频生成 → 配音/音效 → 剪辑 → QC」

## 0b. 这条**修订**了同一天早先给的层级（必须记下来）

同一天早先给过：

> `故事大纲 → 剧集规划 → 单集剧情 → Scene → 剧本 → Shot List`

两条**互相矛盾**：前者 Scene 在**剧本之前**，后者 Scene 在**剧本之后**。
**以后者为准**，理由有二：它更具体、可操作，且「剧本一集一份」本身就排除了
「一个 Scene 一份剧本」。

**因此作废两条此前的结论**（都写在 TASK-088 §5，本卡负责订正）：

| 作废的结论 | 实际情况 |
| --- | --- |
| 「Scene 的位置反了，是架构变更 + 可能的数据迁移」 | **不需要迁移。** `scripts[episodeId]` 一集一份不变；`proddoc` 的 Episode → Scene → Shot 本来就是剧本之后 |
| 「『单集剧情』这一层系统里没有，要新建」 | **不用新建。** 新流程从「该集剧本」起，中间没有这一层；而 TASK-088 正在把分集规划的每一行做厚（核心目标 / 关键事件 / 角色推进 / 信息揭示 / 情绪曲线 / 结尾钩子）——**那一行就是单集剧情** |

**GAP-13 的真正成因也随之改写。** 审计记的是「场景层建了但没人用」，
我先前归因为「位置反了」——错。真实成因是：**流程里没有「Scene 拆分/确认」
这一步**，场景是一个可以完全忽略的可选归组盒，没有任何东西引导创作者去建。
真实项目 48 集全部 0 场景、60 个镜头全在「未分配到场景」，是这个原因。
**这是小改动（把它变成一步），不是架构变更。**

### 1.2 「Scene 拆分/确认」变成一个显式步骤

这是 GAP-13 的真正修法。

- ⑦ 分镜设计的「场景」分区从**可选归组**变成**流水线上的一步**：
  剧本就绪后，主行动是「**把这一集拆成 Scene**」（AI 起草 + 人确认，
  与分镜草稿同一姿态：AI 写、人改、追加新版本）。
- 「未分配到场景」不再是一个可以长期停留的池子 —— 它是**这一步没做完**的显示。
- **不新建第二份状态**：仍写既有的 `proddoc` scenes（`scene.shotIds`）。
- 拆 Scene 的能力：**先查现有 Skill 目录里有没有能担这件事的**
  （`script-breakdown` 产出的是人物/场景地，不是 Scene 划分），
  没有则新增，并在卡里写明为什么不是复用。
