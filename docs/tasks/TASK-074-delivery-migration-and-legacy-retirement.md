### 1.1b 后期交付端点加固（从 TASK-064 转入，2026-08-13 分配）

[TASK-064](TASK-064-creator-ui-consolidation.md) §4h / §4i / §4k 转记的四条 codex 发现
落在 `server.py` 的 `mix-shot` 端点上。它们此前**没有归属**；`mix-shot` /
`render-episode` 属 ADR-0065 明确「不动」的三个端点，不在 TASK-072 的运行链路改造
范围内（TASK-072 §1.9 已记录这一分工），因此归本卡——这是后期交付端点自己的面。

| # | 来源 | 缺陷 | 修法方向 |
| --- | --- | --- | --- |
| a | 064 §4h-1（blocking） | `_agent_mix_shot` 输出 basename 只过 `_NAME_RE`，**未强制 `mix-` 保留前缀** → 构造请求可占用属于对白 / 音效音频链的带版本文件名 | 与其它写入路径一致地用 `_slug_reserved` 家族的规则挡住；`mix-` 是 ADR-0044 为合成产物预留的命名空间 |
| b | 064 §4h-2 | 开放式片段两端上界不一致（`in == 36000` 允许，`out` 夹到 `36000`）→ 零长度片段，混音失败或静默消失 | 两端用**同一个**上界判定，越界即拒绝并说明 |
| c | 064 §4i-1（blocking） | `math.isfinite(v)` 对大到无法转 float 的 JSON 整数抛 `OverflowError` → 合法体积的构造请求让 handler 崩掉而非 400 | 先判类型与范围，再做 `isfinite` |
| d | 064 §4k-1（blocking） | ffprobe 在拿 `_RENDER_LOCK` **之前**跑，每请求最多锁外起 60 个 `ffprobe` → 资源耗尽，且「作业串行化」名存实亡 | 探测移到锁内，或对锁外探测本身限流 |

四条都必须**先复现再修**，并各自补守卫测试。c 与 d 是**可被构造请求触发**的，
优先级高于 a / b。

### 1.2 交付质检（检查层 3）

| 检查项 | 判定方式 | 默认 severity |
| --- | --- | --- |
| 音画同步 | 对白轨锚点 vs 视频时基偏移 | blocking（超阈值） |
| 字幕 | 存在性 / 时序越界 / 空 cue | warning |
| 音量 | 整体响度 + 削波检测（ffmpeg） | warning（响度）/ blocking（削波） |
| 黑帧 | ffmpeg blackdetect | warning |
| 缺帧 | 时长 vs 帧数一致性 | blocking |
| 规格 | 分辨率 / 帧率 / 码率 / 时长 / 容器 vs 项目成片规格 | blocking |
| 素材权限 | 每个用到的 Asset 的来源标记 | blocking（未标注来源） |

- **它不是创意审片**：发现「这场戏不好看」不属于本层，退回检查层 2。
- 检测能力缺失时（未装某工具）→ 该项显示 `unavailable` + 原因，
  **绝不产生一条「通过」的结论**（沿用 ADR-0064 决策 6 的诚实规则）。
- G4：存在 open 的 blocking 问题时 `exportDelivery` **拒绝执行**并列出问题。

### 1.4 真实项目全流程验收

**在真实 Connected Project 上跑完整流程一遍**（AGENTS.md 第 20 条：
demo seed 与 SVG 占位素材不作为主要验收依据）：

```
创建项目 → 设置规格/预算 → 创意 → 大纲 → 设定 → 分集 → 剧本(锁定)
→ 分镜 → 绑定参考 → 主画面 → 视频候选 → 单镜定稿
→ 自动粗剪 → 整集审片(含一次退回重做) → 后期 → 质检 → 导出
```

必须验到的边界情况：

1. 镜头未全定稿时提交正式审片 → **被 G1 拒绝**，可生成测试粗剪。
2. 审片通过后改镜头顺序 → **审片状态回落 `needs_rereview`，画面锁定解除**（G3）。
3. 存在 blocking 质检问题时导出 → **被 G4 拒绝**并列出问题。
4. 长任务运行中刷新页面 → **状态从后端恢复**。
5. 长任务取消 → **子进程真实退出**。
6. 后端不可用 → 页面显示错误，**不显示空列表**。
7. runtime 不可用 → 手工兜底路径可完成同一动作。
8. 每次粗剪 / 每次导出 → **新版本，旧版本仍在**。

**发现真实数据问题时优先如实报告，不得用 mock 绕过。**

### 4.1 §1.1b 后期交付端点加固 —— 四条全部修完，各带守卫

按卡的要求**先复现再修**，`c` / `d`（可被构造请求触发）优先。

| # | 复现 | 修法 |
| --- | --- | --- |
| **c** | `math.isfinite(10**400)` → `OverflowError: int too large to convert to float`（实际跑过） | **范围比较前移**到 `isfinite` 之前：整数与浮点比较对任意大整数安全，且顺带挡掉 NaN / ±inf（它们的比较恒为 False）。修的是**类**不是行 —— 同一个 `_num` 模式在 `mix-shot` 与 `render-episode` **两处**，都改了 |
| **d** | 一次 mix 最多 60 个 clip，每个都在 `_RENDER_LOCK` **之外** 起一个 ffprobe | 新增进程级 `_PROBE_SEM`（`BoundedSemaphore(4)`）+ `_PROBE_WAIT_SECONDS`。**不用 render lock**：探测是只读的、并行几个是安全的，要的是**上限**不是互斥；把校验搬进锁内会让所有调用方排在「不产出任何东西」的工作后面。`finally` 里释放，泄漏一个 permit 会永久缩小上限 |
| **a** | `mix-` 是保留前缀，其它写路径都检查 `_slug_reserved` 以**留在命名空间外**；这一条**写进**命名空间却从不检查自己是否留在里面 → 构造请求可用 `voice-shot-1` 占用对白链的带版本文件名 | 强制输出名以 `mix-` 开头 |
| **b** | `in` 允许到 36000 **闭区间**，而 `out` 被**夹到** 36000 → 开放式片段 `in == 36000` 变成**零长度**（混音失败或静默消失） | 两端用同一个上界；`in >= 36000` 直接 400。**检查点放在读文件之前** —— 它只依赖请求本身，输入问题不该排在媒体读取后面才被报告（第一版我放在 probe 之后，守卫立刻暴露了它永远先撞上 `file missing`） |

守卫：`tests/test_motv_mix_hardening_task074.py`（6 项），含 `10**400`、
`NaN`/`Infinity`/`-Infinity` 字面量、命名空间占用、零长度片段、
上限真的会绑（取满 permit 后第 5 次必须失败）、以及**探测队列打满时诚实失败而不是
假设一个时长**。

### 4.2 §1.2 交付质检（检查层 3）—— 领域实现完成

新增 `src/workflow/deliveryqc.js`：七项检查 + `runDeliveryQc()` 产出 QCReport
（层 3 的 `ReviewIssue`）。

**最要紧的一条规则已落地并被守卫**（§1.2 / ADR-0064 决策 6）：
「检测能力缺失 → 该项 `unavailable` + 原因，**绝不产生一条『通过』的结论**」。
每项答 `pass` / `fail` / `unavailable`；`unavailable` **既不是通过也不是失败**，
它是未知 —— 所以 `passed` 为假，但 G4 不会因它阻断导出（G4 只看
`blocking` + `open`），未知交给创作者判断。守卫里「什么都没测」的报告
`passed === false` 且 `issues.length === 0`。

两处按合同分了级：**响度偏离是 warning，削波是 blocking**（削波是坏掉的音频，
不是偏好）；缺帧、音画同步、规格、素材权限按 §1.2 表为 blocking。
「规格」项**委托** `deliveryspec.checkRenderedAgainstSpec`，所以 ⚙ 与质检读的是
同一份比对，不会各自推导一遍。

守卫：`tests/deliveryqc.test.mjs`（10 项），含七项 = 层 3 category 集合（与
§6.1 的互不相交对齐）、每个未知都带原因、warning 不阻断导出但也不算通过、
质检问题 `source === "agent"`（测量是观察，不是结论）并真的喂给 G4。
