## 0. 改之前的问题

「进入剧集制作 →」**一律**落在 `EPISODE_DEFAULT`（制作台）。制作台是**逐镜详细制作**的
地方——而一集还没有分镜草稿时，它打开就是一句「先选一个镜头」，可根本没有镜头可选。

分镜工作区一直存在、也能生成，但它藏在「工作区 ▾」菜单里，不在主路径上。

## 1. 改成什么

```
故事开发（剧本写完）
   └─ 左栏「🎬 进入剧集制作 →」   ← 唯一明确的跨空间入口，未改动
        ├─ 还没有分镜 → 【分镜】  生成 → 直接编辑 → 定稿
        └─ 已有分镜   → 【制作台】逐镜详细制作
```

规则提成纯函数 `shell.episodeEntryModule(hasShots)`，因为它原本是一段埋在 shell 闭包里、
只有浏览器能触达的条件——而「没有分镜」那一支恰恰是**真实项目跑不到**的那一支
（夜班沉默已有 3 个分镜）。提出来才能给它一条守卫。

## 2. 分镜也是点了就能改

去掉 `✎ 编辑镜头` 模式开关，字段直接可编辑——与分集规划（TASK-069）同一个处理，理由也
一样：一个要先发现才能做显而易见之事的控件，不该存在。

**仍然是版本化的**：打字进入 `ui.buffer`，「保存为新草稿版本」才提交。分镜草稿和 Prompt、
分集规划一样是不可变版本，生成记录指着**具体某一版**，所以打字不能就地改掉它。

| | 行为 |
| --- | --- |
| 打字 | 进 buffer，立刻显示「已修改（未保存为版本）」，`保存` 变可用，出现 `放弃修改` |
| 保存 | `ctx.shots.saveEdit` → 新草稿版本，旧版本保留 |
| 切换镜头 | 有未保存修改时仍然确认（原有保护未动） |

## 3. 顺手修的两个同类缺陷

分镜这边和分集规划有一模一样的两个坑，一并修了：

1. **打字不重绘 → 状态条停在「一致」、保存按钮一直灰着**（草稿其实早记下了）。改为
   就地同步状态条，不重绘——重绘会把光标从正在输入的字段里弹出去（`ui/fieldsync.js`
   存在的理由）。
2. **`.chip` / `.btn` 自带 `display`，author 规则压过 UA 的 `[hidden] { display: none }`**
   → 该隐藏的元素照样显示。补属性特异性 (0,2,0) 的规则。

## 5. 如实说明

**「没有分镜 → 落在分镜」那一支没有在真实项目上跑通**：夜班沉默已有 3 个分镜，所以它
落在制作台（已验收）。那一支由 `episodeEntryModule(false) === "shots"` 的守卫测试覆盖。

## 6. 明确不做

分镜的增删与重排（现有 `ctx.shots.saveEdit` 只改字段）；把分镜草稿的 buffer 持久化
（与分集规划草稿不同，它仍是会话内的，刷新会丢——切换镜头时有确认保护）；
改动 `EPISODE_DEFAULT` 本身（制作台仍是这个空间的中心）。
