## 1. 这一片交付什么

他在「开发」窗口说一句要求 → 应用起一轮**真的会改仓库**的开发 → 改完提交 →
结果作为提案回到他眼前，写着他在屏幕上看得到的变化和那个提交的短 hash。

现在这条路走到一半就断了：`dev.request` 会起一轮 claude（`dev.proposal`），
但那一轮按 ADR-0056 决策 2 是**工具全关、中性目录**的，只能写方案。

## 2. 设计结论（理由在 ADR-0107，这里只记落点）

- **两个执行器条目并存**：`claude-code` 的 `args`（`["-p","--tools",""]`）
  一个字节不动；新增 `claude-dev`，不带 `--tools ""`，在仓库根启动。
  **不做成一个带开关的条目** —— 传错一个布尔值是静默的，写错一个名字有守卫。
- **提示词组装函数不接受作品事实**（ADR-0107 决策 2，本卡最重要的一条）。
  现有的 `_dev_prompt` 恰恰带着 `_conv_facts`，直接给它加工具就等于把注入面打开。
- **只有「开发」窗口能发起**，服务端判 `intent`，与 REQ-007 判据 4 同一道闸。
- **权力到 change 分支为止**：不碰 main、不合并、不 force push。
- **一次一轮**，第二句排队并如实告知（ADR-0107 决策 6）。

## 4. IN SCOPE / OUT OF SCOPE

**IN SCOPE**：`claude-dev` 执行器条目 · 开发指令的 task_type 与执行路径（仓库根、
带工具）· 不含作品事实的提示词与它的守卫 · 「开发」窗口强制 · 一次一轮的排队 ·
结果与失败的回写 · 上述测试。

**OUT OF SCOPE**：合并到 main（ADR-0107 决策 4）· 定时 / 轮询唤醒（REQ-011 明确
不做）· 给 codex 开这条路 · 让应用进程自己写源码（边界没变）· 付费 API ·
任何创作能力的运行方式。

## 5. 验收

1. 在「开发」窗口说一句要求 → 起得来一轮带工具、在仓库根跑的开发；屏幕上立刻
   有「正在做」。
2. 在**作品**窗口说同样的话 → **起不来**，并说清要切回哪个窗口（服务端强制）。
3. 开发指令那一轮的提示词里**不含**当前项目的故事核心 / 大纲 / 正文片段 ——
   守卫断言，删掉守卫要变红。
4. `claude-code` 执行器的 `args` 仍然是 `["-p","--tools",""]` —— 创作能力那条路
   一个字节没变。
5. 那一轮跑完，提案里写的是他看得到的变化 + 提交短 hash；跑挂 / 超时 / 被闸门拦
   都如实写进去，**不会停在「正在做」**。
6. 同一时刻只有一轮在跑；第二句排队并告诉他在排队。

## 6. 一条新路径的接线清单（四轮审查换来的）

新增一个执行器 / task_type，**五处都要接**，漏任何一处都不报错，只是安静地不工作：

| # | 接在哪 | 漏了会怎样 |
| --- | --- | --- |
| 1 | `server._EXECUTORS` | 解析不出 argv |
| 2 | **`runstore.FIXED_EXECUTORS`**（封闭集） | `create` 抛 `InvalidRun` —— **整条路起不来** |
| 3 | **`server._AGENT_PARSERS`** | `_execute_run` 只返回 `{"text": …}`，落地读不到 `outputs.proposal`，**每次成功都被写成失败** |
| 4 | **合同 §5.9b 的端点全表** | `test_the_endpoint_map_and_the_executor_enum_agree` 转红（它是封闭表） |
| 5 | 权限白名单（本卡是 `_REPO_WRITING_TASK_TYPES`） | 该挡的挡不住 |
| 6 | **执行器 argv 里的 `--permission-mode`** | `-p` 是非交互，不给权限它一动手写文件就被拦 —— 那一轮会**「成功」地回来说自己什么都没做成** |

2 与 3 是四轮审查里没人测到的那两处；**6 是四轮审查也没发现、一次真跑立刻暴露的
那一处**。每一处都配一条「它真的被接受」的测试。

## 7. 端到端走查（2026-09-19）

用真实代码走了一遍：真的 `_start_dev_proposal(build=True)` · 真的 RunStore ·
真的 `claude-dev` · 真的落地对账，没有一处 mock。

**第一次跑：起来了，但一个字都没落地。** 登记表实拍
`dev.implement | claude-dev | running → succeeded`（这是四轮里从没到达过的状态），
而 HEAD 没动、工作树没变。它自己在回执里说：「它没有改文件的权限，所以一个字都
没落地」「还差一步：启动这一轮开发的时候没给它写文件的许可」。
→ 补了 §6 的第 6 处，并修掉一个自相矛盾的标题：那次的标题是
「（做完了）走查没通过：…」——「模型答成了」不等于「事情做成了」，现在标题由
**有没有提交**决定。

**第二次跑：被实施 Agent 自己的会话权限层拒绝**（`Create Unsafe Agents` ——
它会启动一个带 `bypassPermissions` 的子进程）。按 AGENTS §1「会话权限层拒绝：
如实报告一次，不反复问」。

**这个限制只在实施 Agent 的会话里**：产品负责人在应用里真正使用时，那个子进程由
studio 服务启动，不经过它。所以**最后一步只能由他来验** —— 在「开发」窗口说一句
明确的小要求，看那条回执是不是「（做完了）… 提交：<hash>」。

## 8. 还差最后一步（**这是信息，不是闸门** —— AGENTS.md §1）

| 走过了 | 还没走 |
| --- | --- |
| 请求 → RunStore 建 run → `claude-dev` 真的起来 → 跑完 → 解析 → 回执落到台账 | **它真的把一行字写进文件并提交** |

差的那一步不是机制，是**权限**：补上 `--permission-mode` 之后，实施 Agent 自己的
会话权限层拒绝再起一次（见 §7）。产品负责人在应用里跑不受这个限制。

他要看的那句话：回执标题是「**（做完了）… 提交：<hash>**」而不是「（没改成）」。

卡的措辞史值得留着：轮 4 之前这里写的是「机制已验证、只差走查」——**那是错的**，
当时机制的第一环是断的；现在起跑那一段有测试、也真跑过了，只剩最后一步。
