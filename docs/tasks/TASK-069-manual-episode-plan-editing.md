# TASK-069：分集规划可以手工修改

- 状态：**已实施，待产品验收**
- 负责 Agent：Claude Code（单一实施 Agent）
- 依据：[ADR-0054](../adr/ADR-0054-production-canon-and-episode-arc.md) 决策 5 / 决策 6
  （规划是 Production 的出口；剧集记录自己基于哪一版）
- 产品要求（2026-08-13）：「故事开发的剧集规划也要可以修改的」「我是说手动修改」
- 产品确认：
  1. 版本化方式 = **草稿缓冲 + 显式「保存为新版本」**
  2. 范围 = **只改已有剧集的 6 个字段**（不增、不删、不重排）

## 0. 改之前是什么样

`分集规划` 里只有 **Arc 推进**（主线 / 人物 / 关系 / 世界 beat）可以手改，行内自动保存。
而**标题 / 梗概 / 戏剧功能 / 开场钩子 / 结尾拍 / 时长**是只读的 —— 它们来自已确认的规划
版本，唯一的改法是让 AI 重新生成一版再确认。

## 1. 为什么不是就地改

`story.plans[]` 是**不可变的版本链**，每一集都通过 `canondoc` 记录了自己「基于规划 vN」，
界面上就是那行 `Based on … 规划 vN`。就地改已确认的那一版会让这个标记**继续显示 vN、
而内容已经被换掉** —— 基线成了假的，而 ADR-0054 决策 6 的影响审阅正是建立在它上面。

所以手改落进**草稿**，形状与本集剧本的 `workingText`、创意 Brief 的工作草稿完全一致：

| | 行为 |
| --- | --- |
| 打字 | 写进 `story.planDrafts[基线版本]`（**持久化**，刷新不丢），**不产生版本** |
| 界面 | 立刻显示「已手工修改（未版本化）」，`保存` 变为可用 |
| 保存 | 追加一个新版本，`origin: "manual"`，`basedOn` 记下从哪一版改出来的 |
| 确认 | **仍是单独一步**。保存不移动 `confirmedPlan`，下游剧集不会被一次手改带跑 |

## 3. 三个刻意的行为

1. **手工修改是一个模式，不是默认状态。** 字段默认只读，点「✎ 手工修改规划」才可编辑 ——
   一次误点不该改掉规划。但**已有未保存草稿时自动打开**，否则那份改动既看不见也无从处理。
2. **空字段渲染成空输入框，而不是被隐藏。** 只读版会跳过空字段，于是「这一集没有钩子」和
   「钩子这一栏不存在」长得一模一样，也没有地方可以写进去。
3. **草稿按基线版本分开存。** 切到别的版本看一眼，回来时你写的东西还在原处；每一版的
   保存与放弃互不影响，另有未保存修改的版本会在状态条上被点名——否则它既看不见也做不完。
4. **状态条就地更新，不重绘。** 打字时重绘会把光标从正在输入的字段里弹出去
   （`ui/fieldsync.js` 存在的理由），但让状态条留在「未改动」会让创作者以为改动没被记下、
   `保存` 不可用 —— 而草稿其实早就存好了。

## 4. 实施中被自己的测试与验收抓到的三个缺陷

| 来源 | 缺陷 |
| --- | --- |
| 单元测试 | `editPlanEntry` 先建草稿再校验 episodeId → **被拒绝的编辑也留下了草稿**。改为先校验后建。 |
| 真实项目验收 | 保存后 `planEditBase` 取 `confirmedPlan`，而保存只动 `activePlan` → **刚保存的那一版从屏幕上消失**，看起来像改动被丢了。改为 `active ‖ confirmed`，与上方规划面板 (`data-pl-v`) 的约定一致。 |
| 真实项目验收 | `.chip` 自带 `display`，author 规则压过 UA 的 `[hidden] { display: none }` → **没改动时也显示「已手工修改（未版本化）」**。补一条属性特异性 (0,2,0) 的规则。 |
| **codex 审查（P1）** | 草稿只有一份 → 改了 v1 不保存、在上方切到「查看 v2」，v1 的草稿**仍被显示在 v2 的编号下**，而下一次击键会用 v2 重新播种草稿、**静默吞掉那份未保存的修改**。改为**按基线版本分别存草稿**（`planDrafts[v]`）：切走再切回来就是原样，保存 / 放弃都只作用于当前这一版，另有草稿的版本在状态条上被点名。 |

## 6. 产品复核后的两轮形状调整（2026-08-13）

### 6a. 「现在我只能编辑剧本。编辑不了剧集规划的内容」

**根因是重复渲染**：`renderPlanPanel`（顶部高亮的「剧集规划 · vN」）把每一集的
梗概 / 戏剧功能 / 钩子 / 结尾拍 / 时长 **只读**地又渲染了一遍，就在可编辑卡片的正上方。
产品点的是上面那块——它看起来才像正文。

改：面板只保留**版本切换 + 确认 + 重新规划**，内容归卡片。**唯一留下的是完整性告警**
（「⚠ 剧集实体缺失」）——被删掉的剧集在下面没有卡片，面板是唯一能说出这件事的地方，
这一点是被既有测试抓住的。

同时去掉 `✎ 手工修改规划` 模式开关：一个要先发现才能做显而易见之事的控件，不该存在。

### 6b. 「分集规划应该是各个集要表达的内容概要」+「要填的框太多了」

卡片收口成**一个框**：

- **「这一集要表达什么」** 是主区域（6 行），标签直接告诉你要写什么；
- 戏剧功能 / 开场钩子 / 结尾拍 / 时长 **折叠**，已填的以文字显示在摘要行，点「改」才
  展开成输入框——已经写好的东西不该以四个空框的样子占着屏幕；
- 「本集要推进什么」（Arc）留在台面（产品选择）；
- 上游基线 / 影响审阅 / 进入剧集制作 收进「详情」——它们是「怎么做出来」，不是
  「这一集说什么」。

## 5. 明确不做

新增 / 删除 / 重排剧集（会动到 Episode 实体及其场景、镜头、生成记录 —— 需要先想清楚
「删一集时它的镜头怎么办」，是独立一轮的工作）；就地改已确认版本（会破坏基线契约，
要改需另立 ADR）；自动确认新版本。
