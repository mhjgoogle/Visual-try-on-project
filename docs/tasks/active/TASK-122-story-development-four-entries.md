## 第 1 步：数据模型（`src/workflow/storywork.js`）

住在 `story.work` 里，与既有的创意简报 / 大纲版本 / 分集规划**并存**，一条不删。

- `form`：小说 / 剧集，**不替他默认**
- 大纲节点：作者写文本，系统切节点并发**稳定 id** —— 改错别字、中间插段落，
  其余节点 id 一个不变（结构规划的引用因此不会集体断掉）
- 结构规划：他点名的九列，最后一列引用节点；引用失效**会被指出来**；删行是软删除可撤销
- `planned.novel / planned.episode`：**可增可减**，减少时既有章/集一个不删
- 定稿：日常编辑不产生历史；`finalizeUnit` 才存一版，内容没变不重复存；
  历史可看、可恢复、**可手动删**，删历史不动当前正文
- `seedPlanFromEpisodes`：现有 12 集可一键变成结构规划的行，且只灌一次

## 第 2 步：四个入口（ADR-0092）

左栏画出来的严格四行：故事核心（brief）/ 故事大纲（story）/ 结构规划（episodes）/
正文创作（script）。`settings` 收起（页面与地址都在，只是不画）；分集行进页内选集器
（`epPicker`，默认只显示当前那一集，点开才列全部），数据与旧左栏**同一份来源**。

**这一步改了被 ADR 冻结的 IA**，所以先立了 ADR-0092，再按它更新那些守卫测试 ——
每一条新断言都指回 ADR，并保留旧规则的出处。被更新的：`bibleposture`（作品设定的位置）、
`creatornav`（分集行的行为，搬到选集器上照旧成立）、`wizardskeleton` / `workspaces` /
`upstream`（script 的归属、EPISODE_NAV 的第一行、生产链）。
`crumbScope("script")` 补了一条显式规则：正文仍是**集级**，不能因为换 space 就退成项目级。
