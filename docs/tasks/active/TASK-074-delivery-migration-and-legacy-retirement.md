### 1.4 真实项目全流程验收

**在真实 Connected Project 上跑完整流程一遍**（AGENTS.md 第 20 条：
demo seed 与 SVG 占位素材不作为主要验收依据）：

```
创建项目 → 设置规格/预算 → 创意 → 大纲 → 设定 → 分集 → 剧本(锁定)
→ 分镜 → 绑定参考 → 主画面 → 视频候选 → 单镜定稿
→ 自动粗剪 → 整集审片(含一次退回重做) → 后期 → 质检 → 导出
```

必须验到的边界情况：

1. 镜头未全定稿时提交正式审片 → **被 G1 拒绝**，可生成测试粗剪。
2. 审片通过后改镜头顺序 → **审片状态回落 `needs_rereview`，画面锁定解除**（G3）。
3. 存在 blocking 质检问题时导出 → **被 G4 拒绝**并列出问题。
4. 长任务运行中刷新页面 → **状态从后端恢复**。
5. 长任务取消 → **子进程真实退出**。
6. 后端不可用 → 页面显示错误，**不显示空列表**。
7. runtime 不可用 → 手工兜底路径可完成同一动作。
8. 每次粗剪 / 每次导出 → **新版本，旧版本仍在**。

**发现真实数据问题时优先如实报告，不得用 mock 绕过。**

#### §1.4 用**合成真媒体**做到哪一步（2026-08-24）

产品负责人 2026-08-24：「TASK-072 §1.9 #10 / 074 §1.4 要真实素材，你本人这个
可以你准备虚拟素材的把」。照做了，并且**把它能证的和不能证的分开写**——
这一节的价值全在后半段。

**为什么合成素材在这里是合法的**：AGENTS.md §20 禁的是「demo seed 与 SVG 占位
素材」，理由写在 [TASK-055 §5](../done/TASK-055-project-rooted-storage.md)：占位
素材**不像真媒体那样行为**，于是掩盖缺陷——一个 SVG 放进 `<img>` 恰好能显示，
「视频资产被放进 `<img>`」这条缺陷就永远不会亮。ffmpeg 生成的 MP4/PNG
**就是**真媒体：真容器、真编码、真时长、真 magic bytes，放进 `<img>` 该失败
就失败。构造器与「能证 / 不能证」对照表在
[`tests/e2e/assets_synthetic.py`](../../../tests/e2e/assets_synthetic.py)。

**已闭合**（`tests/e2e/test_studio_real_media_task074.py`，5 条全绿）：

| 验到了什么 | 怎么验的 |
| --- | --- |
| **Studio 自己**把视频资产渲成 `<video>`、图片渲成 `<img>`，且渲出来的元素**真的解得出** 320×320 | 驱动生产代码的两级决策：`libraryModel` 的 `mediaClass`（domain → 媒体类）→ `renderAssetLibrary` 的标签分发，真 Chromium + 真 H.264 + 真同源 URL |
| 真 MP4 放进 `<img>` **必须失败**（真 PNG 作阳性对照） | 占位素材掩盖缺陷的机制，写成一条会红的测试 |
| 边界 6：后端不可用 → **报错，不是空列表** | 驱动 `services/query.js` 里真实的列表函数，把 `fetch` 打成失败 |
| 八条边界逐条**钉到一个具名测试上**，测试被删/改名就红 | 归属表存的是「文件 + 测试名」，不是「文件在不在」 |
| **无归属的边界被写出来，而不是从表里省掉** | 缺口集合变多变少都红 |

四处构造错误值得记，因为它们全属于同一族：**守卫在它要守的东西消失时变绿**
（fail-open），而这一族恰恰是最难自己发现的 —— 它表现为绿。

- 用 `blob:` URL 喂媒体，在真页面上解不出来。原因是**页面 CSP 本来就那么规定**
  （`default-src 'self'`，`media-src` 回落到它，不含 `blob:`）——那是正确行为，
  错的是构造。改走同源 URL 之后反而更贴近生产。
- 用 `httpd.shutdown()` 造「后端不可用」：它只停 accept 循环，已建立的 keep-alive
  连接照样被服务完，于是答了 200 —— **「不可用」根本没造出来**。
- **测试自己 `createElement("video")` 再看能不能解码**（codex round 1 的 P1，判得对）：
  那证的是 **Chromium 的行为，不是本产品的行为**。Studio 照样可以把 MP4 渲成
  `<img>`，那样写的测试仍然绿 —— 而缺陷恰恰出在**产品的选择**上。改成驱动
  `renderAssetLibrary` 之后做了变异验证：把生产代码改成对视频返回 `<img>`，
  测试立刻红（`+ IMG`）。
- **归属表只查文件在不在**（codex round 1 的 non-blocking，同一机理，一并修）：
  加严之后**立刻抓到了我自己写错的三条** —— `cutreview` / `reviewsync` /
  `deliveryspec` 里根本没有 G1 / G3 / 版本 的测试，真正的归属全在
  `review.test.mjs`。fail-open 守卫的真实代价就在这里：它连**登记本身是错的**
  都盖住了。

**顺带查出一条真缺口**：八条边界里，「每次粗剪 / 每次导出 → 新版本且旧版本
仍在」**没有任何测试**。它守的是 AGENTS.md 第 13 条（禁止静默覆盖已有生成
结果），所以缺口在规则层面是实的。已登记为 [TASK-087 §4.10](TASK-087-followup-ledger.md)，
并在归属表里固定成**已知缺口**：补上测试却不更新表，同样会红。

**仍然要产品负责人本人**（合成素材证不了，不是因为素材假，是因为要证的东西
本身是判断）：

- **完整一集走一遍**（创建 → … → 导出）里**内容是否成立**：分镜切得对不对、
  参考绑得像不像、粗剪节奏顺不顺、审片退回的理由讲不讲得通。合成素材是
  一段纯色渐变，它在这些问题上不携带任何信息。
- **边界 1/2/3/8 的产品语义**：归属测试证的是 G1/G3/G4 与版本机制**按写下的
  规则动作**；「这条规则本身在真实创作里对不对」是另一件事。

所以 §1.4 的状态是：**机械那一半已闭合并有测试钉住，判断那一半仍未做。**

#### §1.5 批次 1（2026-08-25）：`run.skillRunId` 别名已删除

上表把这一条判为「否 —— 这一条本身就是一次独立迁移」。**那次迁移做完了。**

| 落点 | 内容 |
| --- | --- |
| `workflow/skillrun.js` | `startRun` 只铸 `runId`，记录上**不再写出** `skillRunId`；`findRun` 与八个状态转换全部按 `runId` 匹配 |
| `services/canvasschema.js` | 新增 `migrateV18ToV19`：先补齐身份再删旧名；`CANVAS_SCHEMA_VERSION` → 19。校验按**文档自己那一版的词汇**判：v19 要求 `runId`，v12–v18 仍要求 `skillRunId` |
| 读侧 | `skillctl` / `directorshot` / `skillpanel` / `production` / `agentsession` / `taskrow` / `runskill` / `provenance` 共 31 处属性访问改读 `runId`；`skillctl` 的参数名一并统一 |
| `server.py` | `_reconcile_skill_runs` 的 `runId or skillRunId` 回落**刻意留着**，理由写在代码里：它读的是**还没被这个前端迁移过**的 PUT body |

**范围判断（这一条比改动本身重要）**：`skillRunId` 在仓库里有两种用法，只有第一种
是别名。

- **Run 记录自己的 `skillRunId`** —— 同一个对象上，同一个值挂两个名字。**这是别名，
  已删。** 删它不丢信息：v15 起校验就拒绝 `runId !== skillRunId`，所以任何能被加载的
  v15–v18 文档里这两个名字下面必然是同一个字符串。
- **别的结构上叫 `skillRunId` 的字段** —— `generations[].origin`、promptdoc / refinterp /
  ctxcache 的版本记录。那些是**外键**：一个值，一个名字，不存在「读侧该信哪个」的问题。
  给它们改名要再跨四种持久化形状做一次迁移，换不到任何行为上的东西（规则 3）。
  **不动，并且在迁移注释里写明了不动的理由**，免得下一个人把它当遗漏重做一遍。

**守卫**（两条都断言性质，不断言写法）：`runs.test.mjs` 的
「a new run carries the contract's fields」现在钉的是 `!("skillRunId" in r)` ——
此前它钉的是「两个名字、同一个值」，别名删掉之后那句话会**恒真**，也就是说
有人把字段写回来时不会有任何东西变红；新增「v18 → v19：别名被删掉，身份一个都没少」
覆盖三条路径（两名齐全 / 只有旧名 / 两个都给不出 id 时原样不动）。
「v15–v18 冲突被拒」与「v19 冲突被拒」**两版各留一条** —— 同一条不变量换了形状，
只留新的那条等于把旧版文档的保护删掉。

验证：前端 1856 全绿；`pytest tests/studio tests/contract` 662 passed；ruff 全绿。

### §4.2 §1.2 的接线 —— 五项从「未检查」变成真判（2026-08-15）

领域层与界面在下一节已完成，缺的只是**数字**：浏览器跑不了 ffmpeg，所以音画同步 ·
音量 · 削波 · 黑帧 · 缺帧五项一直如实显示「未检查」。本轮把测量补上。

| 落点 | 内容 |
| --- | --- |
| `server.py` `POST /api/delivery/probe` | **新增**。对成片跑 ffprobe（流/格式）+ 一次 ffmpeg（`ebur128=peak=true` 与 `blackdetect` 同一遍解码）。**只读**，因此**不进** `_MEDIA_WRITE_ROUTES` |
| `server.py` `_build_delivery_probe` | **新增**纯函数：把 ffprobe JSON 与 ffmpeg stderr 翻成 `deliveryqc` 读的 `probe` |
| `services/query.js` `deliveryProbe()` | 测量是观察不是命令（ADR-0064 决策 6 / §6.2），所以归 query 而不是 command；`timeoutMs: 0`，真正的上限由后端持有（900s → 504） |
| `app.js` `DELIVERY_PROBE` / `runDeliveryProbe` / `_latestCut` | 探测状态**不持久化**：一次探测描述的是**某一个成片文件**，新成片一合成，数字就是在说另一个文件 |
| `ui/qcpanel.js` `probeBar` | 按钮 + 状态；`ui/production.js` 绑定并**渲染两次**（先让按钮变「正在探测…」，再渲染结果） |

**为什么一个测不出来的字段必须缺席而不是填 0。** 解析是**逐字段全有或全无**：
ffprobe 会大方地给出 `N/A`、省略 `nb_frames`；任何一处填默认值，`deliveryqc` 就会把
「我们没测」渲染成创作者屏幕上的「合格」——正是 §1.2 / ADR-0064 决策 6 要防的事。
`tests/test_motv_delivery_probe_task074.py` 的一半断言钉的就是这一条。

**音画同步测的是什么、不是什么。** 用的是两条流的**容器层起始时间差**，
不是内容层的唇音同步——ffmpeg 没有可靠的内容级检测，硬说有就又是编数字。
但对**我们自己 concat/mix 出来的**成片，容器层错位正是真实的失败模式
（合成步骤把音频接错位置）。两条流都必须报出 `start_time`，否则该项保持缺席。

**`blackSpans: []` 是一次真实测量，不是缺席**：blackdetect 干净时一行都不打印。
所以只有**存在视频流**时才给空数组——没有视频流时那是「没得测」，不能说「干净」。

**帧率按有理数除出来**：`30000/1001` → 29.97 而不是 30。缺帧检查用
`时长 × 帧率` 算期望帧数，一个被舍入上去的帧率会凭空造出「少了几十帧」。

**`nb_frames` 缺失时保持缺席**：真数帧要再解码一遍整片，代价不值；缺帧项如实报未检查。

测试：`tests/test_motv_delivery_probe_task074.py` 15 项（纯函数）、
`tests/qcpanel.test.mjs` 6 项新增（三种「未检查」状态必须可区分、探测必须说出它测的是
哪个成片）。全量：pytest 3153 + 5，前端 1061，ruff 全绿。

**成片从哪来（这条链跨五个模块，断了只表现为「按钮不亮」，所以写全）**：

```
时间线「渲染本集」 → command.renderEpisode → 后端 _agent_render_episode
  → render-ep-v<N>.mp4（uploads 目录，版本化不覆盖）
  → timelinectl.js:280 assetlib.addFinal(...) 登记为 kind="final" 资产
  → assetreg.listAssets 把 reg.finals 扁平出来
  → app.js _latestCut() 取最后一条、从 url 提取文件名
  → POST /api/delivery/probe → _resolve_upload_file 过上传白名单正则
  → ffprobe + ffmpeg → probe → 五项真判
```

最脆的一环是**文件名白名单**：两条产出路径命名不同
（`render-ep-v<N>` / `final-cut-v<N>`），而单元测试拿假名字跑得好好的；正则一旦
收窄，界面上只显示「探测失败」，没人会想到是白名单。
`test_the_probe_accepts_the_names_the_render_paths_really_produce` 用**真实产出的
名字**钉住它，并配一条反例测试防止有人顺手放宽（`../secret.mp4` / `a/b.mp4` /
`.exe` / 带空格）。

**`compose` 端点前端仍无调用方**（`ctx.composeFinal` 存在但没有 UI 入口）——它是
agent 直接从镜头视频合成的另一条路径，与上面这条并行。不影响本轮：成片由时间线
渲染产出。多版成片时由创作者选哪一版来测，属 §1.1「成片预览」的范围；当前取最后
登记的一条并在界面显示其文件名。

### §1.2 交付质检 —— 领域层 + 界面完成

`workflow/deliveryqc.js` 早已有七项检查的领域实现，但**一个调用点都没有** ——
⑩ 后期交付页的「交付质检」分区是空的。本轮补上界面（`ui/qcpanel.js`）与
视图模型（`ctx.deliveryQc()`）。

**这一屏的全部意义在于如实说出它没测什么。** 浏览器跑不了 ffmpeg，所以
音画同步 · 音量 · 削波 · 黑帧 · 缺帧五项确实测不了，它们渲染成**未检查**并附
原因，`passed` 保持 false。颜色上用中性色，不是绿也不是红：它是一个待答的问题。
给它们喂一个编造的 probe 把屏幕填绿，正是 §1.2 / ADR-0064 决策 6 要防的事。

今天真能判的两项，数据页面本来就有：

| 检查项 | 数据来源 | 现状 |
| --- | --- | --- |
| 字幕 | 字幕轨（空 cue / 时序倒置 / 越界） | 真判 |
| 素材权限 | **本片剪辑用到的**资产的 `origin` 标记 | 真判 |
| 规格 | ⚙ 成片规格 | 缺的是**设置本身**，界面明说去哪儿填 —— 与「装个 ffmpeg」是两个动作 |

字幕越界按**当前剪辑**的时长判，不是按成片文件（还没渲染），也不是按 ⚙ 的
`episodeSeconds`（那是目标不是测量）。空时间线给出 null 而不是 0 —— 0 会把每条
字幕都判成越界。

「素材权限」看的是**这条片子用到的**素材，不是整个资产库。传整个 registry 会让一条
与本片无关的旧记录（没有 `origin`）判成阻断，反过来绿行数的也是片子外面的素材，
等于什么都没说。剪辑里有 clip 指向查不到的资产时，清单**不完整**，报 unavailable
而不是权限失败 ——「查不到这个素材」和「这个素材没标来源」是两个不同的发现。

G4 的结论由界面**渲染**而不是重新推导：两个地方决定能不能导出，就是多了一个。
绿字只看 `report.passed` 而不是 `g4.ok`：G4 只清阻断级问题，一次警告级不合格会让
`g4.ok` 为真而报告并不合格。

### G4 为什么还没接到渲染上（明确记录，不是遗漏）

§1.2 要求「存在 open 的 blocking 问题时 `exportDelivery` 拒绝执行」。当前代码里
**没有 `exportDelivery`**：`controllers/timelinectl.js` 的 `render()` 一步同时
渲染成片并把它登记为 Final。

把 G4 接在那一步是错的：质检要探测的正是那次渲染的产物，先渲染才有东西可检。
闸门装在那里会挡住产出被检对象的动作本身，于是永远进不到能通过的状态。

正确顺序是系统合同 §6.5 的四段生命周期 —— **候选 → 质检 → 用户确认导出 →
Final**。要接 G4，得先把 `render()` 拆成「产出候选」与「确认导出为 Final」两步。
那是 §1.1「导出及导出记录」分区的工作，本轮没做，因此 G4 的结论目前只在质检
