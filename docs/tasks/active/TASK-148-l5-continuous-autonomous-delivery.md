## 1. 为什么 L5 的第一件事不是「自动取下一项」

L5 要的是**无人催促地连续跑**。今天的闭环里有两条已经实测的破口，它们在 L4 下只是
恶心，在 L5 下变成**静默放行错误代码**：

| # | 实测 | 出处 |
| --- | --- | --- |
| 1 | **闸门会静默不触发** —— 14 次提交尝试中 5 次 `PreToolUse` 未被调用，且**不可由命令形状复现**。结论：`PreToolUse` 可作 early feedback，**不能当 authoritative enforcement** | [TASK-147](TASK-147-session-isolation-and-evidence-identity.md) §6.2 · §8 |
| 2 | **旁树完全没有闸门** —— 在 `motv-wt/pilot-143` 里暂存一个 ruff 必报三项（I001 + F401 + 格式）的文件，`cd <worktree> && git commit` **直接成功，闸门零输出**。机理：钩子按会话的 `CLAUDE_PROJECT_DIR` 定根，`cd` 换得掉 git 的树、换不掉钩子的树 | [TASK-143](../backlog/TASK-143-one-worktree-per-session.md) §「第 8 种形状」（2026-09-16 实测） |

两条合起来是同一句话：**闸门的沉默，既可能是「检查全过了」，也可能是「它根本没跑」，
从输出上分不出来。** L4 时人在每一步旁边，漏一次有人看见；L5 没有那个人。

**而且第 2 条正好打在 L4 的交付物上** —— L4 把每个会话搬进各自的 worktree，
恰恰是让闸门失效的那个动作。TASK-147 决定 A-1 断言「hook 与配置装一次覆盖所有树」，
那句**对 git 原生 hook 成立，对 Claude Code 的 `PreToolUse` 不成立**。
这不是 A-1 判错，是 A-1 说的那个「hook」和闸门实际所在的那个「hook」不是一回事。

所以切片顺序是定死的：**没有 A，B 和 C 是灾难放大器。**

## 2. 三个切片

**切片 A：闸门成为权威（先做）。**
git 原生 `pre-commit` 成为 authoritative enforcement；`PreToolUse` **不删**，
降级为 early feedback（快反馈本身有价值，只是不再是唯一防线）。
实测支撑已在 TASK-147 A-1 拿到：worktree 的 `git rev-parse --git-path hooks` 解析到
**主 `.git/hooks`**，`git config` 也跨 worktree 共享 —— **装一次覆盖所有树**，
第 1 节第 2 条因此被闭合，而不是被绕开。需要 ADR-0104。

**切片 B：度量台账。**
任务书 §6 的五项：工程介入次数 · 自主完成率 · 交付耗时分项（实现/测试/审查/等待/返工）·
质量（错误合并、串入他人改动、失效证据被接受、交付后回退）· 用量（取不到记未知，
**不把估算当账单**）。append-only，**不造第二份状态文件**（TASK-143 OUT OF SCOPE 已写死）。
没有它，「L5 达标了吗」只能靠感觉答，出事也没法复盘。

**切片 C：队列与取下一项（最后做）。**
- **授权池 fail-closed，默认空** —— 一张卡必须被**显式**标记才进池。
  不把所有 `active/` 卡视为可自动实施，不把建议当成批准（任务书原文）。
  **这一条是我定的默认，不是问句** —— 理由：错误方向的自动实施代价远高于多标一次的成本；
  要拦就拦。
- 一批最多 **3** 个任务；同一外部失败最多重试 **2** 次，无进展则保存状态并报告。
- 停止条件：队列结束 · 用户叫停 · 权限拒绝 · 配额耗尽 · **未授权花费**（AGENTS.md §1，
  唯一还必须问的那件事）。

## 3. 一个本卡不修、但 L5 绕不过的前提：工作落不了地

实测（2026-09-16）：`main` 最后一次合并是 **2026-09-06**，十天没动；
`change/TASK-109-three-pane` 上堆着 **56 个提交**，`change/l4-loop` 又叠在它上面，
本卡这棵树叠在 `l4-loop` 上。

L5 的闭环定义里「跑完同一闭环」**包含合并**。如果自动取下一项只是把提交继续堆在一条
永不落地的分支上，L5 产出的不是交付，是**更快的堆积** —— 这正是 §1 那两条破口的放大版：
没人看着的时候，堆积不会喊疼。

本卡**不修这条**（它是 `change/TASK-109-three-pane` 那条链自己的收口问题，
换实施者会违反 AGENTS.md §14），但把它记为切片 C 的**前置条件**：
**C 开工前，这条链必须已经落地，或已明确它为什么可以不落地。**

## 6. 切片 A 交付记录（2026-09-16）

两个独立事实，分开写（AGENTS.md §1）：

**一、实现完成。** 代码级证据：

| 项 | 证据 |
| --- | --- |
| 权威闸门 | `.claude/hooks/pre_commit.py` —— 定根问 git（**被提交的那棵树**，不是脚本住的那棵）· `-z` 取暂存路径 · 复用 `commit_gate_policy.classify()` · 便宜的检查排在前面 |
| 安装器 | `.claude/tools/install_git_hooks.py` —— 写一层不含仓库路径的 sh shim；`core.hooksPath` 被设时**拒绝安装**（否则会「装好了、报告成功、从不触发」）；`--check` 报告漂移 |
| 决策 | [ADR-0104](../../adr/ADR-0104-git-native-hook-is-the-authoritative-gate.md)，ADR-0050 已补上反向取代链接 |
| 测试 | `tests/tooling/test_git_native_gate.py` **16 passed**，含端到端一条：由 **git 自己**调起 shim，提交被拒且 `HEAD` 没动 |

两条判据的对照实测：

- **判据 1**：同一个探针（ruff 必报 I001 + F401 + 格式的文件），2026-09-16 上午在
  `motv-wt/pilot-143` 里**提交成功、闸门零输出**；换成本闸门后，普通仓库与 worktree
  两种情形都被拒（`test_a_ruff_violation_is_blocked_in_a_worktree_too`）。
- **判据 2**：过了也留一行 `[gate] pre-commit ok · 档位 … · N 项检查 · <树>`
  （`test_a_clean_commit_still_says_the_gate_ran`）。沉默从此只剩一种解释：没跑。

**二、还没在真实项目上被人看过的**：

1. **闸门尚未铺开，这是刻意的。** shim 找不到 `.claude/hooks/pre_commit.py` 时
   fail-closed，而这份实现只在本分支上 —— 开发中实测装上之后，同仓另外两个会话的树
   上没有这个文件，**他们的提交会被一起拦住**。当场撤销。安装因此是**合并时的动作**
   （ADR-0104 决策 5），不是现在。**在合并前，第 1 节那两条破口仍然成立。**
2. **`install_git_hooks.py --check` 还没进体检**（`motv_doctor.py`）。`.git/hooks`
   不随仓库分发，新克隆必须跑一次安装器 —— 没有这道提醒，「忘了装」会安静地变回
   今天的状态。ADR-0104 代价一节已记，接线留在本卡收口。
3. **只覆盖 `pre-commit`。** `pre-push` / `commit-msg` 不在范围内。
4. **独立审查未做** —— 见下。
