## 6. 实施记录

### A 批 —— 唯一 API Client 出口收口（`0346b10` + `fc5884d`）

- `persist.js` 的 canvas 读/写、`runtime.js` 的 `cancelRun` / `runOnExecutor`
  迁到 `apiclient`。前端裸 `fetch` 从 4 处降到 0 处（唯一豁免见下）。
- `apiclient` 两处**加法**：`keepalive` 透传；`ApiError.contentType`。
  后者是迁移中发现的真缺口：`MALFORMED` 把两件不同的事塌成了一件 ——
  「后端回了它自己都解析不了的 JSON」（**权威**，不许回落 localStorage）
  与「静态站点对 /api 回了 HTML」（**没有后端**，该回落）。`persist` 必须分开
  它们，而唯一的证据是 content type。不从 `detail` 文案里嗅，因为改一句措辞
  不该悄悄翻转一次回落决定。
- 三处迁移点显式 `timeoutMs: 0`，保住迁移前的**无期限**语义：canvas 存档可以
  很大，取消「等不到」不等于「没取消」，本地 CLI 跑一次以分钟计。
- 守卫落在**前端套件**（`tests/apioutlet.test.mjs`），扫 `src/**.js`，成员集合
  派生。**第一版放错了地方**：写成 `tests/contract/` 的 Python 源码文本断言，
  但被守的 `services/*.js` 都能被 node import，不属于 ADR-0080 决策 3 那个
  「`.test.mjs` 拿不到的入口层」例外。据 ADR 自行改正并删掉 Python 侧重复。
- 变异验证两次全部转红：给 `budget.js` 加一个裸 `fetch`；去掉一个 `timeoutMs: 0`。
- 唯一豁免 `mediaprobe.js`（媒体字节 `HEAD` + 测试注入点），**被断言**而非被假设。
- 验证：前端 1763/1763；`pytest tests/contract` 139 passed / 1 skipped（本机无
  提权，符号链接用例跳过）。

### B 批 —— 评价 / 反馈闭环接进 Studio Gateway

- 核心侧抽出共享缝 `register_creative_loop_commands()` +
  `CREATIVE_LOOP_COMMANDS`；`build_wfm1_registry()` 改为调它。**规格不复制**：
  风险等级、校验器、落到哪个服务只有一份答案。
- Studio 的 `_command_gateway` 注册这四个命令；非付费门的允许名单改为**派生**
  （`_NO_SPEND_COMMANDS = {"lock-draft-plan"} | CREATIVE_LOOP_COMMANDS`），
  这样核心加第五个无花费命令时不会被这道门静默 403。
- 新增只读路由 `GET /api/projects/<p>/review-target?shot_id=<id>`，两种模式都可用
  （审片不花钱）。**这是实施中被实测推翻的一个设计**：原打算前端自己拼
  `{ref, version}`，但 `CommandEnvelope` 要求 target 恰好是
  `{ref, version, content_digest}`，digest 是记录字节的 sha256。前端编一个的后果
  **不是「被拒」，是把命令绑在一个不存在的版本上** —— 所以改由后端用网关提交时
  校验的同一个 resolver 算。
- 前端 `workflow/reviewsync.js`：纯的信封构造 + 回答翻译，零 fetch、零 DOM，
  可被 `.test.mjs` 完整驱动。`app.js` 只剩「拿到结果、存起来、说出来」。
- 「✓ 通过」与「撤销通过」都登记。**只登记通过是半个故事**：核心会一直以为
  某镜通过了，而创作者已经收回了。
- 回执落 `reviewsDoc.coreSync`（decisionId → 状态），审片卡片如实显示。
  它是**传输回执台账**，不是第二份结论 —— G5「只追加」管的是结论。
  旧存档没有这张表读作「还没问过核心」，不是「核心拒绝过」。
- 五种结局各说各的，绝不塌成「登记失败」：`recorded` / `blocked`（原样转述核心
  给的理由）/ `unavailable`（演示模式没有核心，这是正常的）/ `failed`。
  **`AMBIGUOUS` 与非 `completed` 回执一律不算成功** —— 把「可能写了也可能没写」
  显示成「已登记」比不显示更糟。
- 一条**实测推翻假设**的记录：镜头没有正式记录时，网关在 **target 绑定**就
  fail closed（409 `command_refused`），比 preview 的 blockers 更早，所以
  「缺项目身份」那条 blocker 在这种项目上根本轮不到出场。测试钉的是实测行为。
- 验证：前端 1782/1782；`pytest tests/studio tests/contract` 513 passed；
  `pytest tests/backend -n 8` 2643 passed。ruff 干净。

### C 批 —— 服务端媒体审计与真实尺寸/时长

- 新增只读路由 `GET /api/projects/<p>/media-audit`：服务端读自己的目录，于是
  **项目媒体只剩「在 / 不在」两种答案**。TASK-077 的前端 `HEAD` 探针那个第三态
  `INCONCLUSIVE` 是关于**传输**的事实（服务器拒答 405/501、5xx、请求本身炸），
  不是关于项目的事实 —— 创作者不该被告知「问不出来」自己磁盘上的文件。
- `mediaprobe` 增加 `applyAudit`：能判的一定判，**判不了的一个都不许乱判**。
  截断之外的名字保持未知 —— 把一个上限读成「不在」等于让阈值去指控用户的文件
  不见了。审计失败也不改表（后端故障不得读成「都不在」）。
- `?measure=<文件名>`：**ffprobe-only、一次一个文件**，给出真实像素尺寸与时长
  （TASK-087 §4.3）。刻意不用 `/api/delivery/probe` —— 那条要做完整 ebur128 +
  blackdetect 解码，比「这段多长」需要的重一个数量级（TASK-087 §3.5.4）。
- **实测推翻了一个想当然**：`rc == 0` 不是成功的证据。给 ffprobe 9.0 一个内容为
  16 字节文本、名字叫 `.png` 的文件，它返回 rc=0 + `width: 0, height: 0` +
  `duration: "0.040000"`，只看 JSON 的检查全都会放行。真实结论写在 stderr
  （`Invalid PNG signature …`），而 `-v error` 下 stderr 只在真出错时才有内容。
  于是判据改成 stderr + 正整数尺寸 + 正时长。**这正是这条端点存在的理由**：
  一列因为探测器半答而显示「0×0」，比显示「探不到」更糟。
- 审片列不再一律「未记录」：`未探测`（还没量，可以按「测量」）/ 真实像素 /
  `探不到（没有 ffprobe / 读不出画面 / 文件不在 / 文件名不合法）` 各自分开。
  真实字节数（审计免费带回）**只作附注，绝不冒充像素尺寸**。实测时长与设计
  时长不一致时**两个都说** —— 差异本身就是审片要看的东西。
- 「测量」按钮由创作者按下才跑，一次一个。整块自动测量会让 60 镜的审片页一次起
  60 个 ffprobe —— 换个地方重犯 §3.5.4 记下的那个错误没有意义。
- 登记表**仍然没有**像素尺寸字段：加它是 schema 改动，有自己的归属。这里是
  只读探测 + 会话内缓存，与 `mediaProbe` 同一姿态，**不写 `storageState`**
  （TASK-087 §4.1 仍然开着，刻意的）。
- 一条被取代的测试就地更新：`尺寸没人记过，就写未记录` → 现在钉「未探测 ≠
  未记录 ≠ 探不到」这条更锐的不变量（旧行为已被本卡取代，符合收敛判据）。
- 验证：前端 1795/1795；`pytest tests/studio tests/contract` 521 passed。
  `ok` 路径用 ffmpeg 合成的真片子实证（工具缺失时跳过），不是假件。

### D 批（其一）—— 生成意图与路由闩

**E 项 · `ui.genIntent` 按 (种类, 镜头) 存**（TASK-087 §5.2）

- 旧形状 `ui.genIntent[kind]` **一种媒体只有一格**。三个消费方都比对
  `intent.shotId`，所以不会张冠李戴 —— 但会**静默丢失**：给 A 镜复制图片
  Prompt → 切到 B 镜再复制 → 回 A 镜导入，A 的意图已被覆盖，那张图落地时溯源
  为空，界面什么都不说。
- 抽出 `src/ui/genintent.js`：`(kind, shotId)` 才是这条意图真正的身份。键说出了
  身份之后，读的时候就不必再拿 `shotId` 比对一遍 —— 那种「键不完整、靠调用点补
  一个判断」的形状正是 TASK-087 §7 六条缺陷的共同长相。
- 身份不合法时**什么都不存**：存进 `null` 键会变成一条谁都可能捡走的孤儿意图，
  那是把「丢失溯源」换成「错误溯源」，更难发现。
- 「上传在飞时新写的意图不被上一次导入顺手删掉」这条既有语义保留并测到。

**G 项 · 路由闩改「合并」而非「丢弃」**（TASK-087 §5.6，P3）

- `routeApplying` 早退解决的是真问题（一次后退同时触发 `popstate` 与
  `hashchange`，重复应用会重绘并把「有未保存的修改」问两遍），但它用的是丢弃：
  快速连按时第二次按下静默消失。
- 抽出 `src/services/routelatch.js`：在制中到达只记一个标记，跑完补一次；多次
  到达合并成一次（要去的是**最后**那个地址）。`honourAddress` 自己去读当前
  地址，所以闩**不缓存参数** —— 缓存第一次的参数还是「按了没反应」，只是换了种
  表现。一次导航失败也不丢掉排队那次，否则只是换了个触发条件的丢弃。
- 连带补强了二重事件的去重判据：原来靠 `routeApplying` 早退，现在靠
  `lastHonouredHash`（同一个地址再来一次 = 同一次按下的第二个事件）。这条比
  依赖 `writeUrl()` 更新 `currentRoute` 更稳 —— 有两条 return 路径根本走不到
  `writeUrl()`（拒绝丢弃未保存修改、地址指向后端没有的项目）。
- 为什么各自成模块：两者原本都住在入口编排层 `app.js`，`.test.mjs` import 不到，
  于是行为在前端侧没有可执行落点。抽出后闩可被完整驱动（重入、异常、连续合并）。
- 验证：前端 1808/1808；`pytest tests/studio tests/contract` 521 passed。

### D 批（其二）—— 未确认的规划条目可以逐格编辑（§5.8）

- 旧行为：未确认的规划条目整行显示一句「确认后才能改」。理由是「每次规划编辑都按
  `episodeId` 寻址」—— 那是**实现约束**，不是产品意图。创作者面对的是 AI 写出来的
  一版规划，下一步本来就是先改再确认；把改的能力推迟到确认之后，等于逼他先接受
  一版他还不同意的东西。
- 寻址扩成「有 `episodeId` 用它，没有就用 `ep#<本版第 N 集>`」（`planAddress`）。
  **仍然是身份，不是索引** —— 索引会在任何重排下移动并把 EP03 的钩子写到 EP02 上，
  那正是原来只认 `episodeId` 要防的事，现在照样防住。
- 已确认与未确认两种行**共用同一套单元格**（`contentCells`）。分两套写迟早会长歪：
  加一个 facet 时只改了一边，未确认的行少一列而没有任何东西会报错。

### 独立审查（codex，5 轮，独立性未降级）

| 轮 | 结果 | 处理 |
| --- | --- | --- |
| 1 | fail：5 blocking + 3 non-blocking | 全部真缺陷，全部修 |
| 2 | fail：2 blocking + 2 non-blocking | 1 条按范围驳回，其余修 |
| 3 | fail：3 blocking（含 1 条由驳回升级）+ 2 non-blocking | 升级那条按协议**重新评级**并缓解，其余修 |
| 4 | fail：2 blocking + 2 non-blocking | 全部修；第 1 条改用**终结做法**（见下） |
| 5 | fail：1 blocking —— ffprobe TOCTOU 的 **ABA 变种** | **停在这里**：同一失效机理的第三次报告，按 ADR-0081 §2b/§2c 驳回并记录 |

**为什么跑到 5 轮而不是 2 轮**：ADR-0081 §2a —— 每个**新**报出的 P1 各买一轮，
不是全程硬顶两轮。轮 2/3/4 都报出了新机序的 P1（不是更窄的变体），其中轮 4 的
「未确认行的时长仍是只读」是我自己实现与自己承诺不符，轮 3 的「链条只按 shotId
串」在切项目后会永久挂住 —— 按硬顶读法它们会原样出门。轮 5 才第一次出现
「同题更窄拼法」，于是停。

**轮 1 的五条 P1（都真）**：

1. 通过/撤销是两条不同命令（不同 `evaluation_id`），fire-and-forget 并发发出会
   乱序 —— 撤销先落、通过后落，核心留下一个创作者已经收回的「passed」。
   修：**按镜头**串行链（不是全局，否则 60 镜批量审片变成排队）。
2. 请求飞在半空时关掉页面，本地已有一条通过、核心什么都没收到，而台账里空空
   如也。修：**开始之前**就写 `pending` 并立刻存盘；从磁盘读回的 `pending` 如实
   改写成 `interrupted`；卡片上给「重试登记」（镜头一旦通过，「✓ 通过」就被
   「撤销通过」顶掉了，没有第二次机会）。
3. `await` 之后写全局 `reviewsDoc`，中途切项目会把上一份的回执写进新画布。
   修：捕获 `PROJECT_NAME` + 新增 `canvasEpoch`，变了就不写。
4. 路由闩补跑时才去读地址 —— 而第一次导航结束时 `writeUrl()` 已经把地址**规范
   回**它自己所在的位置，于是补跑读到旧地址、`sameRoute` 短路，**最后一次按下
   仍然丢失，只是丢在更靠后的地方**。修：事件到达那一刻取下地址交给闩。
   这一条值得记住：我的修复只挪动了丢失的位置，没有消除它。
5. `feedbackFor` 导出了、测了、**没有任何调用方**，而卡里写着「反馈闭环已接通」。
   根因不是忘了接线：**界面上根本没有「提出审片问题」这个动作**
   （`workflow/review.js` 的 `issue()` 在整个 `src/` 零调用方）。修：删掉构造器
   与其测试，把缺口如实登记为 [TASK-087 §5.9](TASK-087-followup-ledger.md)，
   并把本卡与提交信息里的说法改成「评价一半接通，反馈一半没有」。

**轮 2 的两条 P1**：

6. `entryMatches` 的「身份优先」只写在**单条记录内部**，取的时候仍是 `.find()`
   —— 于是谁在数组前面谁被选中。一个 id 恰好长成 `ep#3` 的已确认剧集若排在编号
   3 的未确认行后面，编辑会静默落到未确认行上。**每条记录内部的优先级不是优先
   级。** 修：解析走两遍（先整表找身份，再找编号），并钉住「有身份的行不接受
   编号地址」。
7. 同步过程中任何异常都会让 `pending` 永远留着，而卡片在 `pending` 上**隐藏**
   重试 —— 唯一不能卡住的状态恰好会卡住。修：整段包 try，异常也写成可见可重试
   的 `failed`。

**轮 3 的三条 P1**：

8. 轮 2 的修复被从**反方向**再报一次：改成「身份优先」之后，一个 id 恰好读作
   `ep#3` 的已确认剧集会把编号 3 的未确认行顶掉。**一条代码被两个方向各报一次，
   说明错的不是仲裁规则而是那条代码** —— 于是不再调整优先级，改成带标签的
   `id:` / `num:` 两个空间。
9. 同步链条只按 `shotId` 串：切到另一个项目后，一个**同名**镜头会排在上一个项目
   那次请求后面，而那次请求没有客户端超时（本地 CLI 与大存档都需要无限期），
   后端一挂住，新项目的登记就永远发不出去。键里加上项目与文档世代。
10. ffprobe TOCTOU 由 non-blocking **升为 blocking** —— 按协议重新评级，改成
    「探测前后取身份，对不上就丢弃结果」的检测式缓解（见下）。

**轮 4 的两条 P1**：

11. 标签方案里我保留了「裸字符串 = 身份」的兼容路径，于是一个 id 恰好读作
    `num:3` 时**第三种拼法**又出现了。这一次不再补拼法：**标签改为必填**，
    裸形式作废，31 处既有调用一次迁完。容忍一个形式，就是第四种拼法进来的路。
12. 未确认行的**时长**仍渲染成只读文字（已确认行的时长住在 `<details>` 折叠里，
    未确认行没有那个折叠）—— 「逐格可改」这句话在这一格上不成立。两种行改为共用
    同一个时长编辑器。

**轮 2 起被驳回、并在轮 3 升级后重新评级、最终在轮 5 收口的一条**：ffprobe 的 TOCTOU（校验与 ffprobe
之间换成符号链接）。赢下这个竞态需要**对项目 media 目录的写权限**，而有该权限者
可以直接放一个真文件进去，或替换应用本来就在读并渲染的任意媒体；本路由只读且只
返回宽高与时长。修它买不到安全性 —— 与 [TASK-087 §2.2](TASK-087-followup-ledger.md)
对硬链接/TOCTOU 的既有姿态同一判据。

轮 3 把它升为 blocking，按协议**重新评级**：不再纯驳回，改成**检测式缓解** ——
`ffprobe` 接的是路径不是描述符，`/dev/fd/N` 只有 POSIX 有而 Windows 是权威环境
（ADR-0062），所以原子化在这里做不到；能做的是探测前后各取一次身份，对不上就
**丢弃结果** —— 读仍可能发生，**泄露不会**。

轮 5 又报了一个 **ABA 变种**（换走 → 让 ffprobe 读 → 换回来，前后身份因此相等）。
这是同一失效机理的第三次报告，而**再加一层检测就会有下一个变种**。按 ADR-0081
§2b/§2c 停止追更窄的拼法：保留轮 3 的检测（它挡住不还原的简单替换），残余登记
[TASK-087 §5.12](TASK-087-followup-ledger.md)。根治只有把探测做进进程内一条，另立卡。

**这条留下的教训值得写下来**：一个「防不住只能检测」的缺陷，检测层数是无限的，
而每一层都能被下一个变种绕过。判据不是「还能不能再挡一点」，是「攻击者要先拥有
什么」—— 这里是项目 media 目录的写权限，而有它的人可以直接放一个真文件进去。

同轮的另外三条 non-blocking 全部修了：目录审计改「懒迭代 → 截断 → 再排序」（原来
`sorted(iterdir())` 先把整个目录materialise，上限只保护了响应不保护服务端）；
measure 的遏制改成**解析叶子之后**再判包含并拒绝符号链接（原来只查父目录，文件
本身可以是指向项目外的链接）；测量失败后按钮**留下**（原来任何缓存结果都会让它
消失，于是「探不到」变成终局，修好文件也只能刷新页面）。
