3. **项目列表**：本机创建的「画布项目」+ 连接模式下后端报告的「真实项目」+

## 2. 资产位置的默认值从哪来（不硬编码平台路径）

AGENTS.md §3/§4 禁止在流水线/原型代码里硬编码 Windows 路径与分隔符，所以
`D:\02_Work\04_video-work` **不写在任何 JS/Python 源码里**。它是这样到达界面的：

- **连接模式**：默认值 = 后端 `/api/meta` 上报的 `account_root`，即
  `server.py --account-root` 的实参。界面永远显示这个部署真正写入的位置。
- **`run-windows.ps1`（ADR-0049 允许的 Windows 产品入口）**新增 `-AssetRoot`
  参数，**默认取仓库的父目录**。在本机上仓库位于
  `D:\02_Work\04_video-work\Visual-try-on-project`，父目录正好是
  `D:\02_Work\04_video-work`——用户要的默认值因此自然成立，且生成媒体天然落在
  仓库之外（AGENTS.md §23）。其他机器上它同样指向「仓库外面那一层」，不会带着
  别人机器的路径跑。
- **演示模式**：没有后端，默认值取上次用过的位置；界面如实说明「只记录位置，
  不会写盘」。

分隔符由 `separatorFor()` 依据**位置字符串本身**判断（`D:\…` / `\\nas\…` → `\`，
其余 → `/`），因此 Windows 路径不会被显示成 POSIX 路径。无平台判断、无硬编码。

## 3. 边界（本检查点不做的事）

- **不创建目录、不写媒体**。对话框记录的是一个**声明的**资产位置；真实项目
  目录由后端 / CLI 的写入路径创建（ADR-0033+）。连接模式下如果填写的位置与后端
  当前 `--account-root` 不同，界面明确告知「需要用该位置重启后端才会生效」，
  绝不假装已经生效。
- **不引入任意路径的服务端写入**。让浏览器指定任意绝对写入根目录会正面冲击
  ADR-0004（项目根包含与符号链接策略），需要单独的 ADR 与容器化校验，
  本卡不做。
- 项目注册表是**原型本机 scratch**（localStorage，与画布存档同一性质），
  不是核心事实投影。
