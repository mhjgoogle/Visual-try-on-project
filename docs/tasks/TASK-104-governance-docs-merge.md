## 第二部分：gate 的 heredoc 假阳性（同批修掉）

**症状**：一条**纯编辑**的 `python - <<'PY' … PY` 被闸门拦住并跑了全量检查，
然后被当时恰好翻红的**别人的在制代码**挡掉。两个独立会话都撞到（我 + TASK-103
会话），共享工作树里的代价是「A 会话的 WIP 阻断 B 会话的无关编辑」。

**真因与我们最初的猜测不同**：不是「被判成 commit」。是 `shlex` 一路数引号数进
了 heredoc 正文 —— 正文里出现**奇数个撇号**（`# don't`、Python 的 `'''`、中文
注释里一个落单的 `'`）就让 `_tokenise` 返回 `None`，调用方**正确地** fail-closed
到全量。所以拦得没错，错在「根本没能解析一段本不该被解析的文本」。

**修法**：切词前摘掉 heredoc 正文（`_strip_heredoc_bodies`）。shell 从不把正文
当命令解析，而三道扫描关心的东西 —— `git commit` 调用、ADR-0068 链令牌、尾随的
`&& git push` —— **永远在命令文本里，不在正文里**，所以摘掉只去噪、不减弱。
`<<<`（here-string）不在范围内：它的载荷是同行的普通词，本来就处理得对。

**验证**：10 个用例全对，其中三个是关键负向 —— 真提交仍 `check`、链令牌带 push
仍 `block`、非 heredoc 的真未闭合引号仍 fail-closed。两个变异均被抓到（去掉摘
正文；把摘除范围扩大到吃掉定界符后的真命令）。全量 3307 + 6 passed。
