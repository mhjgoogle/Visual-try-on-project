## 第二部分：gate 的 heredoc 假阳性 —— **尝试过，撤回了**

**症状**：一条**纯编辑**的 heredoc 命令被闸门拦住并跑了全量，然后被当时恰好
翻红的**别人的在制代码**挡掉。两个独立会话都撞到，共享工作树里的代价是
「A 会话的 WIP 阻断 B 会话的无关编辑」。

**真因**（与最初猜测不同）：不是「被判成 commit」。是 `shlex` 一路数引号数进
了 heredoc 正文 —— 正文里奇数个撇号就让切词失败，调用方**正确地** fail-closed
到全量。拦得没错，错在「解析了一段本不该被解析的文本」。

**尝试的修法**：切词前摘掉 heredoc 正文。**四轮审查，每一轮都查出真绕过：**

| 轮 | 发现 | 性质 |
| --- | --- | --- |
| 1 | 摘未加引号的 `<<EOF` 隐藏了 `$(git commit …)` —— 未加引号的正文里 shell **会**做命令替换 | **commit gate 绕过** |
| 2 | 带引号词里的 `<<'EOF'` **字面量**长得像开启符；后面没有定界符时吞掉剩余全部行 | 绕过 |
| 3 | 同上，后面**恰好有**一行 `EOF` 时吞掉中间的真提交（我上一轮只修了一半） | 绕过 |
| 4 | 两条 finding **方向相反**：一条要补救路径更保守，一条要合法正文别当命令 | **不可兼得的证明** |

**决定：撤回，并记录为已知局限。** 第 4 轮那两条互斥的 finding 就是结论 ——
判定 heredoc 的范围需要 shell 自己的语法，一个行/正则扫描器不可能同时做到
「不漏」和「不误报」。真正的解法是让 hook 拿到**结构化解析结果**（TASK-085
对 PowerShell 已经这么做：shell 负责切，本模块只负责判），那是另一张卡。

代价对比很清楚：收益只是「偶尔少跑一次全量」，而我在追它的过程中**引入过三个
真绕过**，其中一个是 commit gate bypass。按 MNF 判据（「不做这个，当前功能能否
安全完成？」）—— 能。

**保留下来的两样**（它们与 heredoc 无关，是这轮顺带发现的独立缺陷）：

1. **反引号加入分隔符集合**。`$(git commit …)` 一直能抓到（因为 `(` 本就是
   分隔符），等价的反引号写法此前**抓不到** —— token 变成 `` `git ``，匹配不上
   任何命令名。同 class 的真漏洞，已修 + 守卫 + 变异验证。
2. **代码里那段「不要用扫描器修它」的说明**，以及一条钉住它的守卫：
   `_strip_heredoc_bodies` 不得重新出现、那段说明不得删除。三次绕过换来的经验，
   不能让下一个人重走一遍。

**已知局限如实留下**（两条都偏向过度检查，是可接受的方向）：
① 正文里奇数个撇号 → fail-closed 到全量，纯编辑也会中；
② 正文里的 `git commit` 字面量会被当成那条命令。

**验证**：4 个变异全部被抓（反引号移出分隔符 / 偷偷加回摘除函数 / 删掉说明 /
以及撤回前那三轮各自的守卫）。全量 pytest 3308 + 6、前端 1763、ruff 全过（较撤回前少 4 项 = 被撤回那版的守卫）。
