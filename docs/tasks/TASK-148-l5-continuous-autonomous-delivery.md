## 1. 为什么 L5 的第一件事不是「自动取下一项」

L5 要的是**无人催促地连续跑**。今天的闭环里有两条已经实测的破口，它们在 L4 下只是
恶心，在 L5 下变成**静默放行错误代码**：

| # | 实测 | 出处 |
| --- | --- | --- |
| 1 | **闸门会静默不触发** —— 14 次提交尝试中 5 次 `PreToolUse` 未被调用，且**不可由命令形状复现**。结论：`PreToolUse` 可作 early feedback，**不能当 authoritative enforcement** | [TASK-147](TASK-147-session-isolation-and-evidence-identity.md) §6.2 · §8 |
| 2 | **旁树完全没有闸门** —— 在 `motv-wt/pilot-143` 里暂存一个 ruff 必报三项（I001 + F401 + 格式）的文件，`cd <worktree> && git commit` **直接成功，闸门零输出**。机理：钩子按会话的 `CLAUDE_PROJECT_DIR` 定根，`cd` 换得掉 git 的树、换不掉钩子的树 | [TASK-143](TASK-143-one-worktree-per-session.md) §「第 8 种形状」（2026-09-16 实测） |

两条合起来是同一句话：**闸门的沉默，既可能是「检查全过了」，也可能是「它根本没跑」，
从输出上分不出来。** L4 时人在每一步旁边，漏一次有人看见；L5 没有那个人。

**而且第 2 条正好打在 L4 的交付物上** —— L4 把每个会话搬进各自的 worktree，
恰恰是让闸门失效的那个动作。TASK-147 决定 A-1 断言「hook 与配置装一次覆盖所有树」，
那句**对 git 原生 hook 成立，对 Claude Code 的 `PreToolUse` 不成立**。
这不是 A-1 判错，是 A-1 说的那个「hook」和闸门实际所在的那个「hook」不是一回事。

所以切片顺序是定死的：**没有 A，B 和 C 是灾难放大器。**

## 2. 三个切片

**切片 A：闸门成为权威（先做）。**
git 原生 `pre-commit` 成为 authoritative enforcement；`PreToolUse` **不删**，
降级为 early feedback（快反馈本身有价值，只是不再是唯一防线）。
实测支撑已在 TASK-147 A-1 拿到：worktree 的 `git rev-parse --git-path hooks` 解析到
**主 `.git/hooks`**，`git config` 也跨 worktree 共享 —— **装一次覆盖所有树**，
第 1 节第 2 条因此被闭合，而不是被绕开。需要 ADR-0104。

**切片 B：度量台账。**
任务书 §6 的五项：工程介入次数 · 自主完成率 · 交付耗时分项（实现/测试/审查/等待/返工）·
质量（错误合并、串入他人改动、失效证据被接受、交付后回退）· 用量（取不到记未知，
**不把估算当账单**）。append-only，**不造第二份状态文件**（TASK-143 OUT OF SCOPE 已写死）。
没有它，「L5 达标了吗」只能靠感觉答，出事也没法复盘。

**切片 C：队列与取下一项（最后做）。**
- **授权池 fail-closed，默认空** —— 一张卡必须被**显式**标记才进池。
  不把所有 `active/` 卡视为可自动实施，不把建议当成批准（任务书原文）。
  **这一条是我定的默认，不是问句** —— 理由：错误方向的自动实施代价远高于多标一次的成本；
  要拦就拦。
- 一批最多 **3** 个任务；同一外部失败最多重试 **2** 次，无进展则保存状态并报告。
- 停止条件：队列结束 · 用户叫停 · 权限拒绝 · 配额耗尽 · **未授权花费**（AGENTS.md §1，
  唯一还必须问的那件事）。

## 3. 一个本卡不修、但 L5 绕不过的前提：工作落不了地

实测（2026-09-16）：`main` 最后一次合并是 **2026-09-06**，十天没动；
`change/TASK-109-three-pane` 上堆着 **56 个提交**，`change/l4-loop` 又叠在它上面，
本卡这棵树叠在 `l4-loop` 上。

L5 的闭环定义里「跑完同一闭环」**包含合并**。如果自动取下一项只是把提交继续堆在一条
永不落地的分支上，L5 产出的不是交付，是**更快的堆积** —— 这正是 §1 那两条破口的放大版：
没人看着的时候，堆积不会喊疼。

本卡**不修这条**（它是 `change/TASK-109-three-pane` 那条链自己的收口问题，
换实施者会违反 AGENTS.md §14），但把它记为切片 C 的**前置条件**：
**C 开工前，这条链必须已经落地，或已明确它为什么可以不落地。**

轮 1 报出来的五条，**全部成立，全部已修**。其中第一条直接打在本卡的立论上：

| # | 机理 | 修法 |
| --- | --- | --- |
| 1 | **ruff 查工作区、git 提交索引** —— 暂存违规版本，再在工作区改干净但不暂存，违规版本就能提交成功。判据 1 的一个更阴的拼法 | `index_snapshot()` 把**整棵索引**物化到临时目录，ruff 在那里跑。**范围仍是全仓**（只查改动文件被 TASK-143 点名为免罪符），变的是查哪一份全仓 |
| 2 | **git 的仓库身份变量泄进子进程** —— `GIT_DIR` / `GIT_INDEX_FILE` 被继承，pytest 在临时仓库里的 git 会指回正在提交的仓库 | `clean_env()` 摘掉八个身份变量，所有子进程统一走它 |

证明的只是「shim 会调起某个东西」。现在把**真闸门**（`pre_commit.py` +

违规提交被拒且理由是 ruff，干净提交落地且输出 `[gate] pre-commit ok`。

### 轮 2：一条**新 P1**，而且是轮 1 那条修复自己引入的

判据 2 已转 `PASS`（真闸门端到端两条都认了）。判据 1 仍 `FAIL`，但**换了机理**，
按 ADR-0081 §2c（看失效机理、不看代码位置）判为新 P1，买它自己的那一轮：

| # | 机理 | 修法 |
| --- | --- | --- |
| 1（P1） | 轮 1 为了不污染子进程，把 `GIT_INDEX_FILE` 一起摘了。但 `git commit -a` 与 `git commit -- <路径>` **不写普通索引** —— git 另建一个临时索引并用这个变量指过去。摘掉它，闸门查的是普通索引：**普通索引干净就放行，而真正被提交的那份含违规内容** | 拆成两个环境：`gate_env()` 给闸门自己的 git（原样继承，包括临时索引身份），`clean_env()` 只给被拉起来的检查工具 |
| 2（P2） | 安装器直接覆盖已有的 `pre-commit`，**静默删掉**那个仓库原有的检查 —— 一个以「闸门不许安静消失」立论的工具，不能自己去让别的闸门安静消失 | 认签名：不是本工具装的就拒绝并提示 `--force`。拒绝的是**静默**覆盖，不是覆盖本身 |

这是同一个病的**第三种拼法**：查工作区（轮 1）→ 查旁边那棵树（本卡起点）→
查另一份索引（轮 2）。三次都是「被检查的东西 ≠ 被提交的东西」。

`VERIFICATION: INSUFFICIENT` 一并闭合：新增 `commit -a` 与 `commit -- <路径>` 两条
真提交测试。**这两条守得住是验过的** —— 把修复临时退回去，
`test_commit_dash_a_is_checked_against_gits_temporary_index` 当场变红。

轮 2 修复后验证：`pytest tests/tooling -n 8` → **485 passed / 2 skipped** ·
`ruff check` + `format --check` 干净（742 文件）· `lifecycle_check` 0 finding。

### 轮 3：两条判据都 `PASS`；剩下的一条是我**没修全类**

判据 1 `PASS` · 判据 2 `PASS` · `CA §1` / `CA §4` / 平台中立 / 外部工具解析全 `PASS`。
剩一条 BLOCKING，codex 自己判 P2：`git diff --cached --check` 也走 `run_check()`，
因此照样拿到被摘掉索引身份的环境 —— `commit -a` 时它读普通索引，**非 Python 文件
里的行尾空白能从这个缺口出去**（ruff 管不到非 Python 文件）。

**这是轮 2 那条 P1 的同一失效机理的第二个实例**，不是新机理。按 ADR-0081 §2b
判为「同一主题的更窄变体」，**不再买轮**；这是一次显式的范围判断，记在这里。
—— 而它之所以存在，正是 TASK-147 §7 那条教训的重演：**先修被点到的那一处，
而不是修整个类**。

所以这次按类修：**每条检查自己带它需要的那份环境**（`Check` 从四元组变五元组），
不再由 `run_check()` 统一硬写一份。问 git 这次提交的那条拿 `gate_env()`，
其余拿 `clean_env()` —— 以后新增检查时不需要「记得特判」。

**两条新守卫都验过真的会红**：
- 把那条检查退回 `clean_env()` → `test_whitespace_in_a_non_python_file_is_checked_against_the_temporary_index` 变红。
- `test_every_check_carries_the_environment_it_needs` 第一版**没有变红** ——
  平时跑 pytest 时环境里没有 `GIT_*`，`clean_env()` 与 `gate_env()` 恰好相等，
  断言恒真。补上 `monkeypatch.setenv` 之后才真的会红。**一条永远绿的守卫等于
  没有守卫**，这条差点就留下了。

轮 3 修复后验证：`pytest tests/tooling -n 8` → **487 passed / 2 skipped** ·
`ruff check` + `format --check` 干净（742 文件）· `lifecycle_check` 0 finding。

| 测试 | `tests/tooling/test_l5_ledger_and_queue.py` **18 passed**；工装域合计 **505 passed / 2 skipped** |

**两条设计上的硬选择**，都朝「不方便但不会骗人」的一侧：

1. **队列在 L5 台账未达标时一律拒绝开门。** 不是提醒，是拒绝 —— 先跑起来再补度量，
   等于让整套度量变成装饰。
2. **窗口只看有结论的任务**（交付了，或被外部挡住并记了理由）。在办的逐行显示但
   不进分母 —— 否则「手上开着三件」会把前面五个真实样本挤出窗口，达标状态跟着在办
   数量上下跳。这条是写测试时撞出来的，不是设计时想到的。

**三条关键守卫都验证过「拿掉实现会变红」**：授权池默认空 · 空依据不算授权 ·
未达标时拒绝发牌。

**二、还没在真实项目上被人看过的**：

1. **台账里一个样本都没有。** 工具能记了，但 L5 的闸是**连续 5 个真实任务、至少 4 个
   零工程介入**，现在是 0。`report` 对空台账的回答就是「一个试点样本都还没有」。
2. **队列从未真正发过牌** —— 它在达标之前不会发。所以 C 的实际运行行为只有测试覆盖，
   没有真实运行记录。
3. **工程介入靠自觉记录。** 代码没法强制我把用户的每一次催促记下来。这是这套度量
   最软的一环，如实写在这里。
4. 切片 A 的三条残留（未铺开 / 体检未接线 / 只覆盖 `pre-commit`）不变。

## 9. 切片 B / C 的独立审查（codex，轮 1：八条 BLOCKING，全部成立）

第一版把两条判据都判了 `FAIL`。八条里有**六条是同一个家族**：
「**默认拒绝**写对了，但每一条拒绝都有一条绕过去的路」。

| # | 机理 | 修法 |
| --- | --- | --- |
| 1 | 窗口只看「有结论」的任务 → 在办与被放弃的被剔出去，**五个精选成功就能在一堆失败中间开出 L5** | 窗口改成**连续开工的最后 5 个**；在办的留在窗口里并算不自主 |
| 2 | 质量事故只在有结论的任务上算 | 改成不看结论 —— 串改就是串改 |
| 3 | 判闸靠**在报告文本里找「达标」二字** → 一条外部阻塞理由里写上那四个字，闸就开了 | `gate_status()` 返回结构化判词，文本由它生成，反过来不行 |
| 4 | 授权正则用 `\s*` **吃掉换行** → 空授权行把下一行认成依据 | `[ \t]*`，依据必须与冒号同行 |
| 5 | 只查授权，**没查里程碑闸**（任务书要求两道） | 候选只扫 `active/` —— `backlog/` 的定义就是闸判「现在不做」（ADR-0083 目录即状态）。要进池就 `git mv`，那正是重新过闸这个决定本身 |
| 6 | 发牌**不留痕** → 不算批次上限，也挡不住重复发同一张；没有串行约束 | `next` 写 `dispatch`；手上那张没结论就不发下一张 |
| 7 | 重试计数**按批清零**，且停止期间仍可重试 | 跨批累计；停止生效时一律拒绝 |
| 8 | 池子空了只报错，**不记 `queue-done`** → 新加一张卡就能让同一批死而复生 | 耗尽时记 `stop(queue-done)` |
| 9 | 缺 `kind` 的质量事件被读成 `"?"`，**逃出致命清单** | 按事件类型校验必填字段与取值，缺/错即坏行 |
| — | 非阻断：测试残留写进了真台账 | 已删；重试逻辑早先已从 CLI 挪进函数，正是为了这个 |

**修复过程中自己又撞出两条**，都记在这里而不是悄悄改掉：

- **并发追加会丢事件。** 四个线程各写 20 条，读回来只有 76 条。原以为「`a` 模式
  单次写就够原子」—— 实测不够。改成 `mkdir` 做的跨进程锁（不是 TASK-143 禁的
  「锁服务」：没有进程、没有守护，只是一个目录）。
- **那把锁在 Windows 上有 delete-pending 竞态。** 上一个持有者刚 `rmdir`，NTFS 把
  目录标成删除挂起，这期间同名 `mkdir` 返回的是 `PermissionError` 而不是
  `FileExistsError` —— 只认后者的版本会把异常抛给调用方，**表现成「丢了几条事件」**。
  单跑不复现，`-n 8` 整域跑才出来。这正是 AGENTS.md §2「Windows 是行为差异裁决者」
  的那一类。

**我自己断错过一条测试**：以为「有在办任务闸就该关」。规则本来就允许 5 里有 1 个不
合格，所以一个在办时闸仍然开着；边界是**第二个**在办。断错的那版会把一条不存在的
严格性写进测试。

修复后验证：`pytest tests/tooling -n 8` → **513 passed / 2 skipped**（本文件 26 条）·
`ruff check` + `format --check` 干净（745 文件）· `lifecycle_check` 0 finding ·
**并发那条守卫验过会红**（拿掉锁当场丢事件）。

### 轮 2：锁只保护了写，没保护**决定**

判据 3 从 `FAIL` 升到 `PARTIAL`，判据 4 仍 `FAIL`。四条，全部成立：

| # | 机理 | 修法 |
| --- | --- | --- |
| 1 | **`take_next` 的检查与落账不是原子的** —— 两个 `next` 能同时通过检查、选中同一张卡、各自追加 `dispatch`；一条 `stop` 也能插在中间 | 台账锁改**可重入**，新增 `transaction()`，把「读 → 判断 → 写」整段包起来 |
| 2 | `record_retry` 同上 —— 已有一次重试时两个调用都获准 → 累计三次，突破上限 2 | 同上 |
| 3 | 用量汇总把窗口里的记录拼成一张表 → 只要**一个**任务记了，「未知」就整体消失 | 逐个任务列；缺的按任务显示「未知」 |
| 4 | `git log` 查询失败返回空列表 → 报告显示「无回退」 | 返回 `None`，报告显示「**取不到**」—— 「问不到」不是「没有」 |

第 1、2 条是**上一轮修复没修全**的那一半：我给写加了锁，却把「上限还没到吗」
这个判断留在锁外面。锁保护写不保护决定时，每一条上限都只是建议。

三条新守卫**验过会红**：拿掉 `transaction()`，并发发牌与并发重试当场失败。

轮 2 修复后验证：`pytest tests/tooling -n 8` → **517 passed / 2 skipped**（本文件 30 条）·
`ruff check` + `format --check` 干净（745 文件）· `lifecycle_check` 0 finding。
