## 0. 现状（2026-08-22 实测，不是推测）

```
providers/       manual.py · cloud_minimax.py        —— 只有这两个
first_frame_image → ProviderRequest → cloud_minimax  —— 图片→视频通路是真的
depth / parallax / previz                            —— 一行都没有
```

**「图片 → 视频」今天能做，但只有一条路：付费生成整镜。**

## 1. 「白膜」有三种，只有一种值得做

| | 做法 | 判断 |
| --- | --- | --- |
| **A** | 用现有 image-to-video，prompt 写「无纹理灰白模型、单一光源」 | **不做。** 和成片一样贵 —— 白膜的全部意义是便宜，同价即无意义 |
| **B** | 从那张图做**运镜预览**（本地、免费、确定性） | **做。见 §2** |
| **C** | 真 3D 白膜 | **不做。** 需要 3D 引擎，已明确排除（[ui-correction-plan §0.2](../../src/ui-gap-audit/reports/ui-correction-plan.md)） |

## 2. B 分两档，本卡只做 B1

| | 做法 | 依赖 | 能验证 | 不能验证 |
| --- | --- | --- | --- | --- |
| **B1（本卡）** | 对 Keyframe 做**仿射变换 + FFmpeg**（推/拉/摇/移/微晃），由 `运镜` 字段驱动 | **零** —— FFmpeg 已是既有依赖（原 M1 的合成就用它） | 运镜方向、速度、起止构图、时长感 | 遮挡关系、纵深 |
| **B2（另卡）** | 深度估计 → 2.5D 视差 | 一个深度模型（MiDaS / Depth-Anything）——**新依赖，需 ADR** | 上面全部 + 遮挡与纵深 | 真实 3D 视角变化、角色表演 |

**先做 B1 的理由**：零依赖、当天可用，且已能回答绝大部分「运镜对不对」。
B2 的收益是**遮挡**，而遮挡在大多数镜头里不是运镜判断的决定因素。
**不要因为 B2 更完整就跳过 B1** —— 那会把一个当天能用的东西压成一个需要 ADR 的东西。

## 3. 它填的是成本阶梯里缺的那一格

```
Storyboard   草图        便宜    「画面构图对不对」      ← TASK-095 ④
Keyframe     2K 正式图    贵      「画面本身对不对」      ← TASK-095 ⑤
白膜视频      本地免费     零      「运镜对不对」          ← 缺的这格，本卡
Video        整镜生成     最贵    成片                    ← TASK-095 ⑥
```

**注意它比 Keyframe 便宜却排在它后面** —— 因为要拿那张正式图当输入。
成本不单调，但**依赖顺序**是对的。

## 4. 真正的理由不是省钱

**`运镜` 字段在真实项目 60 个镜头里填充率是 `0/60`。**

审计当时归因为「自由文本没人填」，TASK-093 §2.4 的对策是加运镜预设。
**但更根本的原因很可能是：填了也看不见效果。**
创作者写「手持微晃，缓慢前推」，然后什么都不会发生 —— 直到花钱生成整镜。

> **白膜视频让运镜第一次有反馈：写完立刻能看。**
> 这比省钱重要得多，也是本卡真正的验收标准（§7）。

**与 ADR-0075 的关系**：运镜预设给的是**词汇**，本卡给的是**反馈**。
两者互补 —— 预设让人愿意填，反馈让人填得对。

## 5. 交付

1. **`运镜` 文本 → 运动参数**：一个纯函数，把预设词汇（推/拉/摇/移/升降/微晃/环绕）
   与幅度、速度解析成一组关键帧变换。
   **解析不出来的词不要猜**：如实显示「这句运镜还没法预览」，并列出能识别的词。
   （§2.5f 那条：不知道不是放行；§2.5h 第二条：能力缺失时说出真实可做的那件事。）
2. **变换 → 视频**：FFmpeg 对 Keyframe 做仿射/裁切推移，输出与该镜 `时长` 等长的
   静音 MP4。**必须走既有的 FFmpeg 解析路径**（`shutil.which`，fail-closed，
   ADR-0049 第 6 条），不得裸名调用。
3. **落在哪**：向导 ⑤ Keyframe 通过之后、⑥ 批量生视频之前，作为**每镜一个动作**：
   「预览运镜 →」。**不是新的一步** —— 向导仍是五步（ADR-0066 决策 10 的页面集合
   不动，§2.5h 第三条：挂载前先确认这一页的 section 由谁切）。
4. **新 asset kind `motionpreview`**，与 `storyboard` / `keyframe` 同族。
   **它是预览，不是产物**：不参与 QC 的成片判定，不接 `first_frame_image` 那条路。
5. **状态**：`motionPreview` **不新增第七个 stage** —— 它是 Keyframe 的一个附属视图。
   （TASK-092 六个 stage 是唯一真相，§2.4。加第七个会让所有六 stage 的消费者都要改。）

## 6. OUT OF SCOPE

- **B2 深度视差** —— 另卡，需 ADR（新增模型依赖）。
- **真 3D / 逐帧拉片 / 导演台** —— 明确不做。
- **角色表演预览** —— 静态图做不到，不假装。
- **音频对齐** —— 白膜是静音的，配音对齐仍归 TASK-096。
- 任何付费路径改动 —— **本卡全程零花费**，这是它存在的前提。

## 7. 验收标准（按产品负责人的实际问题写）

1. 在 `照见未明rev2` 某一镜写下运镜（或选一个预设），**点一下就能看到那个运动**，
   不花钱、不等云端。
2. 认不出的运镜描述**如实说认不出**，并列出能识别的词 —— 不静默输出一个不动的视频。
3. **运镜字段的填充率在使用后上升** —— 这是本卡真正要验证的假设（§4）。
   链尾在真实项目上记一次填充率，与 `0/60` 对照。**假设错了如实写。**
4. FFmpeg 不可用时 **fail-closed 并说明原因**，不产出空文件。

## 8. 风险分级

**中**：新增派生视图 + 一个新 asset kind + FFmpeg 调用（既有路径）。
**不触及**持久化 schema、身份、付费、并发。→ **1 轮审查**，出 P1 加 1 轮。

**但有两处要按高风险的纪律做**（TASK-097 §2.5 系列买来的）：

- **FFmpeg 调用与文件写入**：走既有解析与围栏，不新建第二条路。
- **「认不出的运镜」那条闸门钉两个方向**（§2.5d）：既证明认不出时不输出，
  也证明认得出时真的输出；**用生产那一份谓词**，不要在测试里另写一个。

## 9. 测试

- 运镜文本 → 参数是**纯函数**，可单测；认不出的词返回明确的「认不出」而非默认值
- FFmpeg 不可用 → fail-closed，**不产出零字节文件**
- 预览时长 == 该镜 `时长` 字段
- `motionpreview` **不参与** QC 的成片判定（守卫测试，对着 §5.4）
- **不新增第七个 stage**（守卫测试：六个 stage 的消费者一个都不用改）
- 变异验证：把解析器改坏，「认不出」那条用例必须转红（§清单方法论节的 habit）

### 10.3 §7.3 那个假设：**本卡没能验证它，原因比结果更有用**

链尾在真实项目上记了填充率，与 `0/60` 对照：

```
照见未明rev2   运镜 0/60 已写     ← 与审计当时一模一样，一条都没多
夜班沉默       运镜 3/3 已写      ← 但这三条在本卡之前就写好了
```

**假设既没被证实也没被推翻，因为这一轮里没有创作者用过它。** 填充率是一个
**人的行为**指标，它只可能在产品负责人真的坐下来写运镜之后才动 —— 实施 Agent
自己往镜头里打字不算数据，那只是把测量对象换成了我自己。

但这一轮**确实**测到了一件比「上升了没有」更要紧的事，而且它是本卡此前没预料到的：

> **`照见未明rev2` 的 60 个镜头对象上，连 `cameraMotion` 这个键都不存在。**
> 那 60 条记录只有 `shotId / sequence / title / description / duration_seconds / slot`
> 六个字段。**不是「有字段但没人填」，是脚本生成器从来没写过这个字段。**

这把 §4 的归因又往前推了一层。审计说「自由文本没人填」，本卡赌的是
「填了也看不见效果」，而实测是**第三种**：那一栏在这个项目里从未存在过。
三条不互斥 —— 反馈（本卡）与预设（ADR-0075）都仍然必要，但真正让 0/60 变成
非零的第一步是**脚本生成器输出这个字段**，那是另一张卡的事（Follow-up F3）。

**下一次怎么才算验证了它**：产品负责人在 `照见未明rev2` 上走一遍 ⑤，
用这张清单的「预览运镜」看几镜，然后再读一次那一行填充率。数字在屏幕上常驻
（`kfl-mbar`），所以那一次不需要再写任何测量代码。

### 10.5 变异验证抓到的三件事（都是真缺陷，都已修）

**一、跨卷 `os.replace` —— 只有真实项目才暴露。**
第一版 `tempfile.mkdtemp(prefix=...)` 用系统临时目录。这台机器仓库在 `D:`、
`TEMP` 在 `C:`，于是 `os.replace` 直接 `OSError`，真实项目三个镜头**全部 502**。
ADR-0049 决策 2 早就写着「原子临时文件始终待在目标目录（同卷）」，而
`server.py` 里另外四处 ffmpeg 端点**本来都传了 `dir=`**，只有新写的这一处漏了。
测试照不出它：`tmp_path` 与被写入的目录在测试里本来就同卷。
修法是补上 `dir=str(d)`，并加**派生守卫**扫这个文件里每一处 `mkdtemp(` 都带
`dir=`（手写清单会漏一项，§2.6.1）。顺带把被咽掉的 `OSError` 原因放回去 ——
一条说不出原因的失败和一条假成功一样贵。

**二、「首帧 ≠ 末帧」这条断言对「画面没动」零区分力。**
实测（夜班沉默三镜）：一段**明写固定机位**的预览，首末帧 PNG 字节**也不相等**
（PSNR 56 dB，肉眼完全相同），而真的在动的两段是 10 dB 与 15 dB。
所以字节断言在「白膜静默输出一个不动的视频」时**照样是绿的** —— 正是本卡要防的
那件事。改成 PSNR 度量，并**两个方向都钉**：会动的 < 30 dB，明写固定的 > 40 dB。
（取首帧与多帧之间的最小值，因为微晃是正弦叠加，首末帧可能刚好都在零点附近。）

**三、资产库那条「每个 kind 都能被筛选找到」的守卫是恒真的。**
它把 `all`（全部）算进筛选集合，而 `all` 对每个 kind 都返回真 —— 于是把「镜头视频」
那条筛选整条删掉，守卫依然全绿。这是 §2.5d「过严的守卫等于没有守卫」的**镜像**：
过松的守卫同样等于没有守卫。而它本来是在保护 `storyboard` / `keyframe`
（TASK-097 批次 4G 新增的两个 kind），也就是说那次保护从一开始就没生效。
现在排除 `all`，并把唯一真实的例外 `derived-frame` **显式列出 + 说明理由**
（Follow-up F1），例外自己也钉住反方向。

### 10.6 两处按高风险纪律做的（§8）

- **FFmpeg 调用与文件写入**：走既有 `shutil.which` 解析 + fail-closed 503、既有

  存在的理由是 §2.5b-2：任何别的调用方（批量、将来的 Skill）都绕不过它。
  测试里**没有**另写等价物。

### 10.8 与卡片的一处偏离：输入分两档，而且**退档要说出来**

§2 / §5.2 写的是「对 **Keyframe** 做仿射变换」。实测：**两个真实项目里
`keyframe` 这个 kind 一张都还没产出过**（它是 TASK-097 批次 4G 才加的）——
`照见未明rev2` 只有 9 张参考图，`夜班沉默` 有 6 张 `shot-image`。
只认关键帧的话，这个功能在**每一个现有真实项目上都是死的**。

所以输入是 `SOURCE_TIERS`：**首选正式关键帧，退一档是这一镜的镜头图片**，
而且界面与 toast 都报出用的是哪一档（真实屏幕上那一列写着「用 镜头图片」）。
静默拿一张镜头图片冒充正式关键帧才是错的；说出来就不是 ——
与 §2.5h 第二条同一条：闸门关着时给「现在真实可做的那件事」。
