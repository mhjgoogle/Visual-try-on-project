# TASK-051A — AI 导演升级为生产控制塔（Production Control Tower）

- 状态：进行中（分镜屏已交付，待截图验收）
- 前置：[TASK-051](TASK-051-production-studio-ui-convergence.md) 第一批视觉方向已批准
- 实施 Agent：单一实施者（AGENTS.md §14）

## 1. 目标

把常驻右栏从「挂在当前镜头上的生成助手」升级为**项目级生产控制塔**：
它应该知道整个项目在发生什么，而不只是当前这一个镜头。

## 2. 严格边界

- **AI 导演不是新的事实来源**。它只读、只经既有 Story / Bible / Episode /
  Scene / Shot / Asset / Generation / Timeline 服务行动。
- **不落第二份生产进度**：生产计划每次渲染都从既有文档重新推导，不缓存、不持久化。
- **不建第二个资产注册表**：资产收件箱是既有 M3 注册表之上的**分类/提案元数据**，
  不铸 id、不搬媒体、不写记录。
- 完整保留既有生成入口行为（Prompt 预览 / 复制 / ChatGPT / Gemini / 导入 /
  溯源记录）。

## 3. 右栏五层

| 层 | 内容 | 来源 |
| --- | --- | --- |
| 当前上下文 | 集·场·镜 / 角色·状态 / 场景地·状态 / 景别·时长·情绪 / **当前画面·视频·配音状态** | 随工作区变化，读 proddoc + bibledoc + 资产注册表 |
| 导演 | 创作观察 + 自然语言指令 + 本模块唯一真实主行动 | 既有 ctx 控制器 |
| 生产计划 | 八个阶段的 ✓ / ● / ○ + 计数 + **唯一「下一步」** | `src/ui/prodplan.js`，实时推导 |
| 资产收件箱 | 已自动归属 / 待确认，逐条提案 + 依据 + 把握度 | `src/ui/assetinbox.js`，实时分类 |
| 生成 | Prompt 预览 / 生成方式 / 导入 / 生成记录 | `src/ui/genentry.js`（未改动） |

### 上下文优先级（§6）

面板形状保持可学习：**当前上下文**与**导演**固定在上方；下方
「生产计划 / 资产收件箱 / 生成」按当下最重要的一项重排并展开，被选中的一项
带强调边框。唯一例外：**当前镜头被阻塞时，阻塞条直接顶到导演之上**——那正是
创作者此刻无法继续的原因。

## 4. 生产计划的推导规则（`prodplan.js`）

八个阶段全部由既有状态判定，没有一个是存下来的：

- **剧本** — 本集 scriptDoc 有已应用版本 = ✓，只有草稿 = ●；
- **设定同步** — 本集每个场景是否都有 `locationRef` 且有 `characterRefs`；
- **分镜** — 本集拥有的镜头数（**按集**，不是项目草稿总数）；
- **画面 / 视频 / 音频** — 本集镜头里各自已有媒体的数量；
- **剪辑** — 本集时间线的 clip 数与 `edited` 标记；
- **成片** — 资产注册表里的 finals。

**阻塞判定**只报可证明缺失的字段：未归入场景 / 场景地未设定 / 场景地缺参考图 /
未设定出场角色 / **角色缺参考图** / 画面内容为空。每条都带「去哪里修」。

**下一步 = 第一个未完成的阶段**，而不是最显眼的阶段。设定同步没做完时，下一步
是「把场景联结到作品设定」而不是「继续生成画面」——因为未联结的场景根本编译不出
一致的 Prompt。这条有单测锁定。

## 5. 资产收件箱的三档分类（`assetinbox.js`）

- **A 确定归属（自动，无需确认）**：领域里**已经**写着归属——可解析的
  `creativeShotId`、角色/场景地参考图引用、场景环境音、剧集 BGM、时间线 clip、
  首帧、或某条 Generation 的结果资产。
- **B 有依据的提案（需确认）**：没有归属，但有**真实证据**——落在某个真实镜头
  槽位上却没记 shotId（把握 80%）；`creativeShotId` 指向已离开草稿的镜头（把握
  50%，只提示不重挂）；M4d 未解析的付费结果（把握 40%）。逐条显示**证据原文**。
- **C 不确定（保留在收件箱）**：既无归属也无证据。**绝不静默挂接、绝不隐藏。**

**外部导入媒体的 AI 识别归类**（从画面推断角色 / 状态 / 场景地 / 变体关系 + 置信度）
**本检查点不实现**：那是一项新的 agent 能力，需另立 ADR。模型上用
`aiAssisted: false` 显式声明，UI 上写明「仅按已有事实归属」，不假装。

## 6. 执行安全（`directorops.js`）

三个运行层级 + 一张能力表，`invoke()` 是唯一入口：

- **OBSERVE**（自动）：读取分析、找缺口、找不一致、确定性归类、编译 Prompt。
- **PLAN**（自动）：排出有序的生产建议。提案不是动作。
- **EXECUTE**：调用**既有**产品动作——导演永远不新开一条写路径。

需要显式确认的 EXECUTE：正典变更（故事 / 作品设定）、资产归属写回、替换当前
生效资产、批量付费生成、破坏性操作、最终渲染。免费且本身已有「提案 → 应用」
门的生成（剧本 / 分镜 / 大纲 / 拆解）不再二次弹窗。

**未知能力一律 fail-closed**（视为需要确认）——这张表以后一定会被扩展。

## 7. 当前实现边界（如实注明）

- 「执行下一步」是**导航 + 定位**：它跳到该做这件事的工作区，并选中第一个
  **未被阻塞**的镜头。批量编排还不存在，所以它不假装跑完了一批。
- 「确认归属」走完确认门后，如实提示写回需要 Gateway 写侧（ADR-0033+），
  本检查点只做提案与确认门，**不写入**。
