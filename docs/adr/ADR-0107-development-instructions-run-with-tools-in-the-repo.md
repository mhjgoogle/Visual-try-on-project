# ADR-0107：开发指令那一轮有工具、在仓库里跑；创作能力那一轮一个字都不动

- 状态：Accepted（2026-09-19，实施 Agent 依 AGENTS.md §1 自行 Accept —— 技术
  架构决策；不涉付费，不涉不可逆动用户数据）
- 关联：[REQ-011](../requirements/REQ-011-say-it-in-the-app-and-it-gets-built.md) ·
  [TASK-160](../tasks/TASK-160-your-word-drives-the-build.md)
- 与 [ADR-0056](ADR-0056-local-ai-runtime-and-film-skills.md) 的关系：
  **决策 2 保持 Accepted，一个字不改。** 本 ADR 不推翻它，而是说清它管的是哪一类
  运行，并为另一类开一条独立的窄路。两条路在代码里是两个执行器条目，不是一个
  带开关的条目。

## 背景

产品负责人 2026-09-19：「那谁启动你去看」→「那能不能我和前端沟通完了。通过我的
指令驱动后端来做」。

当时的答案是「没有人，只有你」。台账里 13 条待处理意见，4 条躺了 21 天、9 条躺了
20 天 —— 它们不是被判断为不做，是根本没人去看。

应用**已经会起 claude 会话**（`dev.request` → `task_type="dev.proposal"` →
`executor="claude-code"`），但那一轮按 ADR-0056 决策 2 是**工具全关、中性工作目录**
的：它只能写一份方案，改不了任何东西。

## ADR-0056 决策 2 为什么存在（它没有错）

原文的理由是具体的，且**今天依然成立**：

> 我们的提示词内嵌**用户撰写的剧本文本**，这正是一个注入面 —— 一段精心构造的
> 剧本可以要求可读文件的执行器去读本机密钥并放进答案里。

创作能力（story-development / script-writer / novel-chapter-writer …）的提示词里
带着他写的故事、大纲、正文。**那些文字是作品，不是指令**，但模型分不开。所以那条
路必须工具全关。

## 决策

### 决策 1：按「提示词里装的是什么」分路，不按「谁在调用」分路

判据不是「哪个窗口发起的」，也不是「跑的是什么能力」，而是**这一轮的提示词里有没有
作品内容**：

| | 创作能力（ADR-0056 决策 2 管这条） | 开发指令（本 ADR 开这条） |
| --- | --- | --- |
| 提示词装什么 | 作品内容：故事核心、大纲、正文、人物、镜头 | **只有他这句话 + 他在哪一页**。作品内容一个字都不带 |
| 工具 | 全关（`--tools ""`） | 开 —— 它要真的改代码 |
| 工作目录 | 中性目录 | 仓库根 |
| 产出 | 一份结构化提案，他确认后由 controller 写进作品 | 一个**可回滚的提交** |
| 谁能发起 | 任何创作页面 | **只有「开发」窗口**（服务端强制） |

两个执行器条目**并存**：`claude-code` 的 `args` 保持 `["-p", "--tools", ""]`
一个字节不动；新增 `claude-dev`，它不带 `--tools ""`，并在仓库根启动。

**不做成一个带开关的条目。** 一个「工具开/关」的布尔值意味着某一天某处会传错它，
而传错的方向是静默的：作品内容 + 工具 = 那条注入面直接成立。两个条目分开，
误用需要写错执行器的名字，而那有守卫。

### 决策 2：作品内容与开发指令之间隔一条守卫，不靠纪律

现有的 `_dev_prompt(ask, page, facts)` **恰恰带着 `_conv_facts`（项目事实）** ——
直接给它加工具，注入面立刻成立。所以开发指令那一轮的提示词组装函数
**不接受任何作品事实参数**，并由测试钉住：

- 它的签名里没有 facts 这一类入参；
- 守卫断言组装出来的提示词里不出现当前项目的故事核心 / 大纲 / 正文片段。

**这是本 ADR 最重要的一条。** 其余几条都是流程，只有这一条是安全。

### 决策 3：那一轮不是「应用在改源码」，是一个完整的开发 Agent 会话

[product-loop 边界 1](../../.claude/skills/product-loop/SKILL.md) 保持成立，只是把
它说得更准：**禁的是应用进程自己写源码**（那会绕开每一道闸），不是「应用不许启动
一个会照常走闸门的开发会话」。

那一轮拿到的指令里明确要求它走 dev-workflow：改动 → 归属测试 → git 原生
pre-commit 闸门（[ADR-0104](ADR-0104-git-native-hook-is-the-authoritative-gate.md)，
它是权威闸门，任何提交都过它）→ 可回滚的提交。

**一道闸都没有被绕开**，这正是这条路可以开的全部理由。

### 决策 4：它的权力到 change 分支为止

不碰 main、不合并、不 force push。合并仍按 AGENTS §22 由人或另一轮显式完成。

理由：merge 的前置条件包含「最终全量通过 + 无未闭合 P1 + 待复审清单为空」
（ADR-0085），那是一整套判断，不该由一句「帮我改个表头」顺带触发。

### 决策 5：默认开着，不设需要他手动打开的开关

AGENTS.md §1：「不要加什么自己改不了自己限制的设置。这样我做什么都不能自动化了。」
「任何需要他去编辑配置文件、点 UI、改环境变量才能推进的机制，一律不得新增。」

所以本条路**不**照搬 ADR-0056 决策 2A 的 `MOTV_RUNTIME_ALLOW_FS_READING_EXECUTORS`
那种运维开关。安全由**代码里的强制**承担，不由一个他要去设的环境变量承担：

1. 只有「开发」窗口能发起（服务端判 `intent`，不是模型自觉）；
2. 提示词里没有作品内容（决策 2 的守卫）；
3. 闸门与测试照旧（决策 3）；
4. 权力到 change 分支为止（决策 4）。

### 决策 6：一次一轮，第二句排队

两个自动 Agent 同时改同一棵共享工作树，是已经付过学费的事故类型
（[TASK-087](../tasks/TASK-087-followup-ledger.md) §5.31：裸 commit 带走别人暂存的
东西；§5.33：`.claude/tmp/` 的固定文件名互相覆盖）。

所以同一时刻只有一轮开发指令在跑；他连说两句，第二句排队并如实告诉他在排队。

## 代价（已接受）

- **无人看管的改动。** 他说一句，一个没人在旁边看的 Agent 会改代码并提交。闸门、
  测试、可回滚提交兜着，但「兜住」不等于「不会做错事」—— 它可能把事情做成他没
  想要的样子。**代价的对冲是可回滚**：每一轮都是一个独立提交，`git revert` 就撤。
- **烧他的订阅额度。** 每一轮都是一次真实的模型调用。对冲是决策 5 的反面：
  **只有他说话才跑**，没有定时、没有轮询、没有后台常驻。
- **他这句话的质量决定结果。** 一句模糊的指令会换回一个模糊的改动。这不是缺陷，
  是这条路的性质；提案回执写成「现在这样 / 改完这样」正是为了让他一眼看出偏差。

## 不做什么

- 不推翻 ADR-0056 决策 2（创作能力那条路一个字不动）；
- 不给 codex 开这条路 —— 它没有真正的无工具模式，而本条路的安全靠的是
  「提示词里没有作品内容」，不是靠沙箱；两者叠加才安全，缺一条就不开；
- 不做定时唤醒（REQ-011「不在范围内」写明了理由）；
- 不让那一轮碰 main（决策 4）。
