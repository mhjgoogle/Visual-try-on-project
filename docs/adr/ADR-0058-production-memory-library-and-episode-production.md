# ADR-0058：生产记忆库、本集制作工作区与溯源创作主干

## 1. 背景

ADR-0054 建立了上游创作工作区（创意 → 故事大纲 → 作品设定 → 分集规划），
ADR-0055 统一了资产登记，ADR-0057 引入了镜头生产状态与审片。到此为止，
一集的制作仍然分散在六个按阶段划分的页面里：

- **剧本在一个页面，分镜在另一个页面。** 创作者问「这一段被拆成了哪些镜头」，
  需要记住剧本内容再切页面比对。剧本与分镜本来是同一件创作行为的两面。
- **镜头看不到自己现在长什么样。** 画面在「画面」页、视频在「视频」页，
  镜头本身只有文字设计。
- **参考图只能逐镜头发现缺失。** 没有任何位置回答「整集需要哪些参考图、
  已经有哪些、哪些被多个镜头共用」。
- **生成的输入是临时拼装的。** 每个调用点各自组装参考图/首帧/Prompt，
  两条路径可以对「输入是什么」产生分歧；手工外部生成几乎不记录任何输入。
- **资产只能按路径/ID 浏览。** 存储管理器回答「磁盘上有什么」，但不回答
  创作者真正的问题：「我以前做过什么，能不能再用一次」。
- **溯源图从 Prompt 开始。** ADR-0052 的图覆盖 Prompt → 生成 → 资产，
  但创作的链条更早开始：剧本 → 场景 → 镜头 → 共享参考 → Prompt。

## 2. 决策

### 决策 1：资产库是「生产记忆库」，不是文件管理器

`资产` 顶层模式渲染视觉优先的资产库（`src/ui/assetlibws.js`）：真实缩略图 /
视频海报 / 音频波形与就地播放；搜索按创作者看得见的词（显示名、原文件名、
标签、以及解析后的角色/场景/镜头/剧集**名称**）；筛选按类型、角色、场景地、
剧集、来源、可复用与标签；Inspector 分 预览 · 信息 · 使用 · 溯源 · 技术细节
五段。

- **`path` / `assetId` / `storageState` 不再是主界面**。它们退到 Inspector
  的「技术细节」折叠区。存储生命周期管理仍归 `存储` 工作区，两者不合并。
- **「使用」完全派生**（`src/workflow/assetusage.js`），从不存储。存储会在
  重新剪辑、切换版本、解绑参考的瞬间产生第二份会漂移的真相，而「这个东西被
  哪里用了」恰恰是不能给出过期答案的问题。
- 使用点按 `(kind, episode, scene, shot, extra)` **去重**：同一个参考图既绑定
  在镜头上、又喂给了做这个镜头图片的那次生成，是一处依赖的两种描述，不是
  两次使用。「被用得多」是创作者判断保留什么的依据，虚高即误导。

### 决策 2：本集制作是一个创作上下文，不是又一个阶段页

新增 `本集制作`（`src/ui/episodews.js`），并置于 `EPISODE_NAV` 首位：

```
剧集剧本 → 场景（含它自己的剧本段落）→ 镜头（含当前画面/视频、已绑定参考）
        → 参考 → Prompt → 生成 → 审片
```

- 场景显示它对应的剧本段落。定位规则是**保守的**：仅当剧本的场景标题数量与
  场景数量一致时按位置对应；否则明说「无法对应」，绝不显示邻近段落。显示错误
  的段落比不显示更糟——它是一个看起来可信的谎言。
- 镜头行显示真实缩略图，展开显示真实 `<video controls>` 播放器。
- 既有的六个阶段工作区**原样保留**：它们是「把一个阶段做完」的地方，
  本集制作是「看见整集」的地方。
- `进入本集` 打开本集制作，`进入本集剧本` 打开剧本——两个入口各自到达其
  文案承诺的位置。

### 决策 3：参考统筹按整集汇总，且永不复制 canonical Asset

新增 `参考统筹`（`src/ui/refplan.js`），对整集回答四件事：已存在 / 缺失 /
被哪些镜头共用 / 建议复用。

- **计划行指向参考的链（key），不是某个版本。** 十个镜头共用「林晚 Ref」是
  一行带十个镜头，不是十行——这正是参考之所以 canonical 的全部理由。
- **「缺失」是提问，不是指令。** 它只陈述「这个镜头所在场景里有这个对象，
  而没有绑定任何该类参考」，它不创建任何东西。创建始终是创作者的动作。
- 「建议复用」在项目里已存在覆盖该对象的参考时出现，动作是**绑定已有链**，
  而不是新建一份副本。

### 决策 4：生成输入集合是一个正式对象

新增 `src/workflow/geninput.js`：`buildInputSet()` 组装
人物/场景/道具/风格参考 · 首帧/尾帧 · Prompt · 镜头与场景上下文 ·
来源/模型/参数/seed；`generationSeedFrom()` 把它变成 Generation 记录种子。

- **每条生成路径产出同一个记录形状**，只有取值不同。
- **不知道的就是 null。** 手工外部生成不上报模型与 seed，图片生成没有首帧，
  这些字段保持 `null` 并在界面上明说「未知（外部生成不上报）」，绝不填一个
  看起来合理的默认值。`seed: 0` 是真实 seed，必须存活。
- **阻塞项逐条列出**（`missingForGeneration`）。一个没有理由的禁用按钮是死路。
- 手工生成回程复用既有唯一写路径 `ctx.media.importShotMedia`，并把输入集合
  冻结进 Generation 记录，因此手工路线第一次拥有与自动路线同等的溯源。

### 决策 5：参考选择器三个入口，临时上传同样登记

镜头的参考选择器提供：已绑定 / 本集推荐（场景里出场的对象已有的参考）/
从资产库选择 / 临时上传。**临时上传不是绕过登记的捷径**：文件走
`ctx.assets.importReference`，成为拥有自己 `ref-…` 链、已声明类型、
已链接到场景对象的真正 Asset，然后才绑定到镜头。系统内不存在产生
orphan media 的路径。

### 决策 6：溯源图补齐创作主干

ADR-0052 的图从 Prompt 开始；本 ADR 将其前延为完整链条：

```
剧本 → 场景 → 镜头 → 共享参考 → Prompt → 生成 → 图片 → 视频 → 音频 → 成片
```

- 新节点类型 `script` / `scene` / `shot`，来自 canonical 文档，因此**与是否
  生成过任何东西无关**：没有图的镜头仍然是真实镜头，显示它就是在说
  「这里还什么都没做」。
- **共享参考只有一个节点**，无论多少镜头绑定它。绑定指向链的当前版本——
  那才是今天发起一次生成会真正收到的东西。画十份副本会说出相反的事实，
  并掩盖「切换链的版本会同时移动全部镜头」。
- 没有剧本文本的剧集**没有** script 节点，而不是一个空节点。
- 场景持有草稿中已不存在的镜头时，节点保留并标注 `dangling`。
- 主干是 `authored`，既不是 `generated` 也不是 `import`。

### 决策 7：过滤不破坏 lineage truth

筛选（全部 / 图片 / 视频 / 音频 / 渲染 / 失败）隐藏节点，**从不改写边**：
被隐藏的中间步骤留下可见的断口，绝不生成一条 A 直达 C 的捷径。

创作主干的保留规则：**当且仅当它下游有节点在过滤后存活时保留**。因此
「图片」仍然显示每一帧属于哪个镜头，而「失败」显示三次失败而不是整集镜头。

剧集选择器与类型筛选是**两个独立控件**，互不替代。

## 3. 后果

### 正面

- 剧本与分镜回到同一个创作上下文；镜头能看见自己当前的样子。
- 参考图的缺口在整集层面一次可见，复用是默认建议而不是靠记忆。
- 手工外部生成第一次拥有完整、诚实的溯源；一条链上手工与自动无差别。
- 资产库回答「我以前做过什么」，而不是「磁盘上有什么」。
- 溯源图从剧本开始，能回答「这一帧为什么长这样」的完整问题。

### 负面 / 成本

- 溯源图的列数增加（主干占据左侧 3 列），宽屏之外需要横向滚动。
- 场景剧本定位是保守的位置匹配；剧本标题风格不一致时会退化为「无法对应」。
  这是有意的取舍：宁可不说，不可说错。
- `prodData()` 增加 `scripts` 只读切片。

### 明确不做

- 不引入 Media API Provider、不接任何付费图像/视频/音频 API。
- 不迁移 asset 的 URL / 项目相对路径 schema。
- 不做 TASK-056 的 `projects.json` 迁移、不做 legacy 清理、不做项目改名/导出。
- 资产库不接管存储生命周期（归档 / 移除字节 / 永久删除仍在 `存储`）。
- 不为参考图发明「自动识别主体」的推断——语义只来自创作者的声明。
