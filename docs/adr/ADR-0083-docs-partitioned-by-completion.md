# ADR-0083：`docs/` 按完成状态分区，总览由目录派生而不是手写

- 状态：Accepted
- 日期：2026-08-23
- 决策者：产品负责人（本条为其明确指示）
- 关联：[ADR-0077](ADR-0077-repository-path-ownership.md)（仓库路径所有权）·
  [ADR-0082](ADR-0082-no-signoff-gate-on-task-cards.md)（状态由 Agent 自己定）·
  [TASK-087](../tasks/active/TASK-087-followup-ledger.md)（欠账总账）

## 1. 背景

产品负责人 2026-08-23：

> 「目前 docs 里面哪些要求是完成的看起来很不清晰。」

同一天的复查给出了代价，不是猜测：

| 实测 | 后果 |
| --- | --- |
| 九张卡挂「进行中」十天 | 代码 2026-08-13 已进基线，标签没跟着改 |
| TASK-052 整张标「待开始」 | 四条里两条早做完；**错标签把另外两条真缺陷藏了十天** |
| TASK-087 §1.1 写「是 3.1/3.2 的硬前置」 | 前置 2026-08-17 就没了，三条欠账白挂六天 |
| TASK-083 标「未开工」 | ADR-A/B/C 全部已定已实施 |
| TASK-075/076/099 标「待复审 / 待闸门」 | 补审 2026-08-16 就做完了 |

**五处全是同一个方向：文档比事实旧。** 根因是状态**只写在文字里**——文字要靠人
记得改，而同一件事实往往记在三四处（任务卡 + `implementation_plan` + 待复审清单
+ TASK-087），改动时只改一处。

## 2. 决策

### 决策 1：**目录即状态**

有「完成 / 未完成」这一维的文档按状态分区：

```
docs/tasks/active/   docs/tasks/done/
docs/design/active/  docs/design/done/
```

**一个文档在哪个目录，就是它的状态。** 卡做完了就 `git mv` 进 `done/`。
文件位置改不动的成本远低于文字，而且 `ls docs/tasks/active/` 就是完整待办清单
——**不需要任何人记得维护它**。

任务卡不得直接躺在 `docs/tasks/` 下：那样它就没有状态了，正是本 ADR 要消除的歧义。

### 决策 2：没有「完成」这一维的文档**不进分区**

ADR、稳定合同、产品规格、架构、路线图留在原地：

- **ADR 是决策，不是任务**——一条 ADR 只要 Accepted 就一直有效，它不会「做完」。
- **合同不会做完**（`creator-system-contract` / 信息架构 / L0–S7 I/O 合同）。

把它们塞进 active/done 会制造第二种假状态。**顺带的好处**：ADR 被代码注释大量引用，
不动它们就不会有一次高风险的全仓链接改写。

### 决策 3：总览是**生成的**，并由测试钉住

`docs/STATUS.md` 由 `.claude/tools/gen_docs_status.py` 从目录结构 + 各文档自己的
状态行生成，`tests/tooling/test_docs_status.py` 在它与目录不一致时**转红**。

**理由直接来自背景那张表**：手写索引一定会漂移。一个「必须记得更新」的索引，
和一个「必须记得更新」的状态行，是同一个缺陷；只有**派生**才不会。
这也是 TASK-087 §7 项 2 那条已有习惯的又一次应用——
**守卫的成员集要派生，不要手写；新成员应当因为存在而进清单。**

### 决策 4：状态行仍然保留，但它只回答「怎么完成的」

目录回答**完成没有**，状态行回答**怎么完成的 / 还差什么**（证据、提交号、
未走过的验收项）。两者分工，不重复承载同一个事实。

## 3. 后果

- **好的**：「还欠什么」= `ls docs/tasks/active/`，不再需要读遍任务卡去推导；
  新文档放错目录会被测试当场抓住；`STATUS.md` 不可能过期。
- **要接受的**：任务完成时多一步 `git mv` + 重新生成。这一步会被测试提醒，
  不依赖记忆。
- **一次性代价（已付）**：127 个文档搬迁 + 全仓 371 处链接改写
  （128 处指向被搬文件 + 243 处被搬文件内部的深度错位）。
  顺带修好 **15 处搬迁之前就断的** ADR slug 链接；改完全仓断链 **0**。
