# ADR-0092：故事开发就是四个入口，章/集不进左栏

- 状态：Accepted
- 日期：2026-08-30
- 决策者：产品负责人 2026-08-30 下发规格并当场划定边界；技术形状由实施 Agent 依
  AGENTS.md §1 自行 Accept（不涉付费、不动用户数据、每一步可逆）
- 关联：[REQ-006](../requirements/REQ-006-agent-can-do-what-the-creator-can-do.md) ·
  [TASK-122](../tasks/done/TASK-122-story-development-four-entries.md) ·
  取代 [ADR-0066](ADR-0066-product-refactor-fixed-ia-review-layers-and-system-contract.md) 决策 10 里的**分组**部分
  （成员集合不变）与 TASK-091 §1.1 关于 `script` 归属的那一条

## 1. 背景

产品负责人 2026-08-30 的原话：

> 「左侧一级导航严格只有 4 个：故事核心 / 故事大纲 / 结构规划 / 正文创作」
> 「不新增一级页面。不新增一级 Tab。不把 Chapter / Episode 放进全局左栏。」
> 「左边那一排信息量太busy了」「整体尽量设计得简约一点，不要出现太多栏」

在这之前，故事开发的左栏是四行入口 + 分组标题 + 统计数字 + **12 个分集平铺成一排**，
`本集剧本` 在「剧集制作」space 的第一行（TASK-091 §1.1，依据是「剧集制作开始的时候
按照图一。写剧本」）。

## 2. 决策

### 决策 1：故事开发的左栏是**四个入口**，且是改名重组，不是新页

| 键 | 新标签 | 旧标签 |
| --- | --- | --- |
| `brief` | 故事核心 | 项目与创意 |
| `story` | 故事大纲 | 故事大纲 |
| `episodes` | 结构规划 | 分集规划 |
| `script` | 正文创作 | 本集剧本（在剧集制作） |

**页面集合仍是十一个**，`PAGES.length === 11` 那条冻结守卫照旧成立；每个键的地址与
历史链接一字未动（TASK-086 给每个键的稳定地址）。ADR-0066 决策 10 冻的是「三空间 /
十一页」这个**闭集**，本 ADR 不动集合，只动**分组与标签** —— 那一层本来就是产品可以
改的，冻结的是「不许无限长出新页」。

### 决策 2：`script` 回到故事开发，作为「正文创作」

TASK-091 §1.1 把它移进剧集制作，依据是他当时的一句话。2026-08-30 的规格把「正文创作」
明确列为故事开发的第四项，并要求「小说创作 / 剧集创作」两个入口、三条路径都从这里走。
**更晚的产品决定覆盖更早的**；剧集制作仍有看板 / 分镜设计 / 镜头制作 / 粗剪审片 /
后期交付五页，它失去的只是一个入口位置，不是一项能力。

### 决策 3：`settings`（人物/关系/世界观）退出左栏，但**仍是一个页面**

他要「其余次级项收起或移除」。这里选**收起**而不是移除：页面、地址、既有跳转全部保留，
只是不占左栏一行（NAV 项上的 `hidden`）。第 3 步把这些内容并进「故事核心」之后，
这一行才真正没有存在的必要 —— 在那之前**没有任何东西变得够不着**（第 13 条）。

### 决策 4：章 / 集**不进全局左栏**，进页内选集器

他点名了这一条。分集行与「进入剧集制作 →」搬进页面顶部；**数据只有一份**
（`shell.episodeRows`），左栏与页面不会各画一份而互相矛盾。

## 3. 代价（已接受）

- 一批把旧 IA 写死的守卫测试要改：「作品设定 is LAST」「本集剧本归剧集制作，且是它的
  第一行」「故事开发's rail ends at 分集规划」「an episode ROW …」。它们**不是为了变绿
  而改**，是因为**规则变了**；每一条的新断言都指回本 ADR，并保留旧规则的出处，
  方便日后回看这次变更的理由。
- 「剧集制作」不再从写剧本开始。这是他这次要的形状，代价写在这里。

## 4. 不做什么

- 不新增一级页面、一级 Tab（他明确禁止，也是 ADR-0066 冻结闭集的用意）。
- 不删除任何既有页面或数据：`settings` 只是隐藏；旧大纲版本、12 集规划、人物关系一条不动。
