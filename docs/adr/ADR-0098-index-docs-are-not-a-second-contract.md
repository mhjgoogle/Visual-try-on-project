# ADR-0098：术语表与范围外记录是索引，不是第二份合同

- 状态：Accepted
- 日期：2026-09-05
- 决策者：实施 Agent 依 AGENTS.md §1 自行 Accept（纯技术文档决策，不涉付费、不动用户数据，
  逐条可逆 —— 删掉一条索引不损失任何规则）
- 关联：[ADR-0087](ADR-0087-document-lifecycle-and-default-agent-context.md)（文档生命周期与
  默认 Agent 上下文，**不动**，本 ADR 在它的三分类里加两份 A 类文档）·
  [ADR-0010](ADR-0010-creation-workspace-boundary.md)（提供「局部范围声明 vs 永久禁止」的判据）·
  [ADR-0097](ADR-0097-one-skill-source-generated-client-entries.md)（同一条纪律在工装侧的实例）·
  [ADR-0077](ADR-0077-repository-path-ownership.md)（仓库路径所有权，**引用不改**）·
  [TASK-133](../tasks/active/TASK-133-glossary-and-out-of-scope-index.md)

## 1. 背景

两个缺口，同一个机理：**当前事实找不到，于是被重新发明。**

**术语没有查询入口。** 仓库里已经散着 80+ 条术语辨析 ——「SkillRun 不是第二份记录」
「推荐 ≠ 绑定」「`taskType` 不得由 `taskName` 推导」「问不到 ≠ 没在跑」—— 全部埋在
1065 行的冻结系统合同与 97 份 ADR 的正文里。它们写得都很准，但**没有一个地方能查**。
代价已经发生过：TASK-097 记录了 `--muted` 这个未定义 CSS 变量的事故（同义词漂移造成），
TASK-128 干脆把它写成了一笔明账：「这是**词表统一问题**，不是接线问题」。

**「决定不做 X」没有落点。** 97 份 ADR 里**没有一份是 Rejected** —— ADR-0087 定义了这个
状态，但从未被使用过，被否掉的方案都埋在各 ADR 内部的方案对比表里。于是同一个提议隔几周
被重新提一遍，每次重新论证一次。

[当前架构合同](../current-architecture.md)治不了这两件事：它被 `lifecycle_check.py` 钉死
≤200 行，且 §7 明列「不回答什么」。术语与范围边界既不在它的职责内，也塞不进去。

## 2. 决策

### 决策 1：它们各回答一种**新问题**，不是第三、四份事实

| 文档 | 回答 |
| --- | --- |
| [current-architecture.md](../current-architecture.md) | **WHAT IS TRUE NOW** —— 模块边界 / 依赖方向 |
| `docs/adr/` | **WHY / HISTORY** —— 当时为什么这么定 |
| [glossary.md](../glossary.md) | **WHAT THINGS ARE CALLED** —— 这个名字指谁、不指谁 |
| [out-of-scope.md](../out-of-scope.md) | **WHAT WE WON'T BUILD** —— 不做什么、裁决写在哪 |

四份文档答四个问题，**没有任何两份答同一个问题** —— 这是它们不会互相漂移的原因。
会漂移的是同一个答案写了两遍。

落点定为 `docs/` 而不是仓库根，因为 ADR-0077 规定根只放项目元数据与治理文件；
文件名避开 `CONTEXT`，因为那个词在本仓库已被占用四次。

### 决策 2：收录判据是「已经发生过」，不是「可能会发生」

- **术语表两闸**（同时成立才收）：① 仓库里指得出一处**已经写下来的**漂移证据，
  条目里写下出处；② 叫错了会**改错代码或改错数据**。纯风格偏好不收。
- **范围外记录只收永久边界**。判据用 ADR-0010 现成的那条裁定：历史任务里的
  「本任务不做 Web UI / 数据库」是**有效的局部范围声明，不构成对未来的永久禁止**。
  任务卡的 `OUT OF SCOPE`、ADR 的「本轮不做」、`Not Decided Here` 一概不收 ——
  今天有 105 份卡带范围排除措辞，收进来会立刻淹掉真正的边界。

「可能会漂移」不可判，会退化成任何人都能往里加一条；「已经写下来过」可判，
而且顺带让每一条自带指针。

### 决策 3：「指过去而不抄」有三条执行方式，两条是物理阻断

这是本决策的承重墙 —— 索引长成第二份合同是这个机制唯一真正的失败模式。

1. **删除测试**（写进两份文档的前言，加条目时自己跑）：把那一条整条删掉，问
   「**有没有任何一条规则因此消失**？」有 → 你在抄合同，把那句话搬回它该在的地方。
2. **禁规范性动词**：定义段 ≤2 行，且不出现 必须 / 不得 / 禁止 / 只能 / 一律 / 应当。
   抄的时候人会本能地写「必须」，而写不出「必须」的时候就只能写指称。
   **这一条由 `lifecycle_check.py` 判**，不靠自觉。
3. **单向叶子**：只有索引指向合同，合同不指回来（唯二的反向指针是两个入口）。

第 3 条与 [ADR-0097](ADR-0097-one-skill-source-generated-client-entries.md) 是**同一条纪律的
两个实例**：有唯一的源、单向派生、派生物不许反向变成源。ADR-0097 那一侧的派生是机器生成
（`.claude/skills/` → `.agents/skills/`），这一侧的派生是人手写但被禁止携带规则。
`.agents/skills/` 的薄入口正是「索引不携带规则」的现成正例：里面只有 name/description、
规范源的路径、以及「先读它再执行」，正文与 references 一个字不搬。

**「派生物会漂」不是假想论证。** 就在本 ADR 落地的同一天，ADR-0097 那条同族守卫
（薄入口与技能源的同步棘轮）**两次拦下它自己的作者** —— 一次是改了 `SKILL.md`，一次是改了
`references/handoff.md` 而入口摘要覆盖整个技能目录。两次都是上一步动作的机械后果，
都不是「谁忘了」。靠人记得的版本，那天下午会漏过去两回。这就是承重墙第 2 条交给机器判、
而不是写进规范让人遵守的理由。

### 决策 4：它们不是引用句柄，也不进 Review Package

引用句柄仍然只有 `CA §N` 与 `REQ-NNN 判据 M`（ADR-0088 决策 1）。
**没有「违反 glossary 第 N 条」这种说法** —— 违反的永远是它指向的那份合同。
审查者的 Review Package 里也不放它：它既不是判据也不是约束，放进去只会变成第五道闸。

这一条断掉的是索引长成合同的**唯一通路**：一份没人能引用的文档，无法变成规则来源。

## 3. 代价（已接受）

- **两份新文档要维护。** 缓解：它们结构上不含合同内容，合同怎么改都波及不到；
  只有**名字本身**变了才要动，那是低频事件，且挂在 dev-workflow 第 9 步的收敛清单上。
- **首版必然不全。** 20 条术语 + 35 条边界不是全集。这是刻意的 —— 按决策 2 的判据，
  收不进来的那些正是「还没有证据说它会漂」的那些。
- **守卫判不了「定义是否正确」。** 它只判形状（有没有 `_Avoid_`、有没有指针、指针的目标在不在、
  定义有没有携带规则）。正确性靠人，办法是 TASK-133 完成判据里那两项一次性人工核对。

## 4. 不做什么

- **不改** [creator-system-contract.md](../design/creator-system-contract.md)（冻结的唯一权威，
  只作为 `_权威_` 指针的目标）、不改任何既有 ADR、不改 ADR-0077 那张路径表。
- **不做**术语表评审这类新流程 —— AGENTS.md §1 明禁新增要人手动操作的机制。
- **不 grep** `_Avoid_` 里列的近义词看谁在用：全仓找「素材」会把每次正常提及都报成漂移，
  守卫天天红然后被关掉，正是 `lifecycle_check.py` 头部注释描述的失败形状。
