# ADR-0105：任务的状态住在卡上，不住在目录里

- 状态：**Accepted**（2026-09-17，产品负责人明确指示；技术形状由实施 Agent 依
  AGENTS.md §1 自行定）
- 决策者：产品负责人 —— 「我希望 folder 不要分 done 和 active 了。这些能在这个仓库
  的任务管理器里面找到现在在进行中的任务。」
- 取代：[ADR-0083](ADR-0083-docs-partitioned-by-completion.md) **决策 1**
  （「卡放在哪个目录就是它的状态」）；ADR-0083 的其余决策（总览由派生而不是手写、
  基础写在卡头）**不动**，而且本 ADR 依赖它们
- 取代（局部）：[ADR-0087](ADR-0087-document-lifecycle-and-default-agent-context.md)
  **决策 2** 里「Change / Task 的状态机 = 三个目录」这一句；三态本身
  （没人在做 → 正在做 → 做完了）**保留**，只是载体从目录换成卡头一行
- 关联：[TASK-150](../tasks/TASK-150-task-state-on-the-card.md)（实施）·
  [TASK-149](../tasks/TASK-149-task-prerequisites-are-machine-readable.md)
  （它的「前置完成」判定跟着换载体）· `.claude/tools/task_status.py`（状态语法的唯一源）

## 背景

ADR-0083 把「做完没有」放进了目录：`backlog/` → `active/` → `done/`。那个决定解决的
是 2026-08-23 的问题 —— 五处手写状态同时过期，一处错标签藏了两条真缺陷十天。
「目录即状态」在当时是对的：目录是仓库里唯一不会跟内容漂移的东西。

它的代价在四周后显出来了：

1. **「在办的有哪些」要靠 `ls`。** 产品负责人要的是一个任务管理器 —— 问一句就有答案，
   而不是记住三个目录名。
2. **三个目录让同一个任务号能长出两张卡而没人发现。** 2026-09-17 一次扫描抓到
   TASK-061 与 TASK-102 各有两份文件（都是审查记录 / 注入证据被当成了卡存进 `done/`）。
3. **搬卡就是改路径。** 每张卡被 `git mv` 一次，指向它的所有链接都要跟着改；
   卡自己向上的相对链接（`../../adr/…`）在 `active/` 与 `done/` 里深度相同，但只要
   有人把卡放错一层就全断。TASK-149 的解析器要判「前置完成了没」，第一版只能写成
   「那张卡在 `done/` 里吗」—— 把一个事实问题变成了一个路径问题。

## 决策

### 1. `docs/tasks/` 是一个平铺目录

没有 `backlog/` `active/` `done/`。一张卡的路径在它整个生命周期里**不变**。

### 2. 状态写在卡头那一行，只有三个词

```
- 状态：进行中 · <原来那一行的全文>
- 状态：完成 · 已验收（产品负责人 2026-08-13 随 ADR-0066 批）
- 状态：待办
```

枚举词 **`待办` / `进行中` / `完成`** 紧跟冒号（允许包在 `**` 里），后面可以接任何散文。
三态与 ADR-0087 决策 2 一一对应：`待办` = 没人在做、`进行中` = 正在做（含「部分完成」）、
`完成` = 做完了 / 已退役。

**状态语法只有一个源**：`.claude/tools/task_status.py`。`gen_docs_status` /
`lifecycle_check` / `agent_harness resume` / `task_graph` / `l5_queue` 全部 import 它，
不各自写正则 —— 五个工具各自认一遍，就会有三个认、两个不认，那正是 ADR-0083 当初
要消灭的「多份真相」换了个地方长出来。

### 3. 没有合法状态行的卡是缺陷，不是空格

`lifecycle_check` 转红；`gen_docs_status` 整体拒绝出数（`CurrentTruthError`）。
理由与 ADR-0101 决策 5 同源：一张读不出状态的卡会在「进行中的有哪些」里**静默消失**，
消失比标错更糟 —— 标错至少还在名单上。

同一个任务号两张卡同样转红：目录不再帮忙区分它们，任务号必须唯一。

### 4. 「任务管理器」= 三个现有入口，不新建

- `python .claude/tools/agent_harness.py resume` —— 谁在哪张卡上 · 哪些卡在办
- [STATUS.md](../STATUS.md)「进行中 · 任务卡」一节 · [WORKSTATUS.md](../WORKSTATUS.md)
  —— 每条需求做到哪了
- `python .claude/tools/l5_queue.py list` —— 已授权、可以自动取的下一项

三样都从卡头状态行**派生**，不存第二份。不建看板、不建数据库
（[范围外记录](../out-of-scope.md)那条边界不重访）。

### 5. 迁移一次做完，链接按位置重算

2026-09-17 一次迁移：149 张卡 `git mv` 进 `docs/tasks/`，每张卡按原目录补枚举
（`backlog/`→待办、`active/`→进行中、`done/`→完成），**原状态行的文字一字不丢**
（枚举词前置，原文跟在 `·` 后）。卡内 396 条相对链接按「旧位置解析 → 新位置重算」
逐条重写，卡外 76 个文件里的 `tasks/(active|backlog|done)/` 折成 `tasks/`。
`test_docs_links` 守全仓链接，迁移后必须 0 断链。

迁移中发现的两组「不是卡的卡」（TASK-061 审查记录、TASK-102 注入证据 ×3）搬进
`docs/reports/` —— 它们是历史证据，本来就归那里（AGENTS §24）。

## 范围

- **`docs/design/active|done/` 不动。** 产品负责人这句说的是任务；设计文档的两态分区
  没有「同一个号两份文件」的问题，也没有任何工具按它判状态。要不要跟进另立卡。
- **不做优先级、不做看板 UI。** 排序归 [TASK-149](../tasks/TASK-149-task-prerequisites-are-machine-readable.md)
  的前置边与里程碑闸；本 ADR 只管「在办的是哪些」这一个问题。

## 代价（已接受）

- **`ls docs/tasks/` 不再直接回答「哪些在办」。** 答案在 `resume` / STATUS.md，
  多一步命令，少三个目录名要记。
- **状态行必须机器可读。** 写卡的人多一个约束：枚举词紧跟冒号。`lifecycle_check`
  会在提交时把写歪的当场指出来，所以这不是靠记性。
- **与未合并分支冲突。** `change/TASK-109-three-pane` 上 54 个提交动过 `docs/tasks/`
  下的卡；本迁移在 `change/TASK-148-l5` 上做，合并时会在路径上冲突。产品负责人
  2026-09-17 明确选了「现在做，冲突由实施 Agent 解」。
- **ADR-0083 决策 1 的历史理由仍然成立**：手写状态会漂。本 ADR 没有回到手写 ——
  状态行是**被守卫读的**，漂了会转红。区别只在载体：目录一次只能表达一个维度，
  卡头一行可以同时表达「做完没有」和「交付了什么」。
