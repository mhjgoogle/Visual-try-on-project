# ADR-0085：merge 到 main 不再是人工闸 —— 前置条件一条不少，只是没人再点头

- 状态：**Accepted**（产品负责人 2026-08-24 下发）
- 依据（原话）：「合并。这个也不需要保留人工。」
- 日期：2026-08-24
- 取代：[AGENTS.md](../../AGENTS.md) §22 里「`merge` 到 main 仍须用户明确要求」，
  以及 [ADR-0079](ADR-0079-auto-push-skill.md) 决策 4 的同一句
  那一段，以及 §1「保留人工闸的只有 merge 到 main 与付费」的前半句
- 相关：[ADR-0079](ADR-0079-auto-push-skill.md)（auto-push 的 Merge Gate 机制）、
  [ADR-0082](ADR-0082-no-signoff-gate-on-task-cards.md)（任务卡不设签字闸）、
  [ADR-0068](ADR-0068-continuous-modification-chain.md)（连续修改链的最终全量）、
  [ADR-0081](ADR-0081-review-by-impact-scope.md)（发布闸门的定义）

## 背景

AGENTS.md §22 一直把 merge 单独留成人工闸，理由写得很清楚：

> 它把整条分支一次性交给所有拉取者，说一句「合并」的成本远小于弄错的成本。

这个理由在**别人也在拉这个仓库**的世界里成立。本仓库不是那个世界：单个产品负责人
＋若干 Agent，`origin` 只有他一个人拉。所以「一次性交给所有拉取者」的实际含义是
「交给他自己」，而他刚刚说了不想再点这一下。

同一位产品负责人此前已经逐个拆掉了别的闸：任务卡签字（ADR-0082）、push
（2026-08-23「我要的就是自动push」）。每一次的理由都是同一个 ——
**在技术问题上停下来问，等于把工作退回给用户**（AGENTS.md §1）。

## 决策

### 决策 1：merge 到 main 不再需要用户明确要求

按 AGENTS.md §1 的判据「错了能不能重来」，merge **能重来**：`git revert -m 1`
把一次合并整个撤掉，历史仍在，没有任何东西被销毁。它和 commit / push 是同一类，
不是和「花钱」同一类。

### 决策 2：**前置条件一条不减，而且现在由 Agent 自己负责证明**

这是本 ADR 最要紧的一句。去掉的是「谁点头」，不是「要满足什么」：

| merge 前必须成立 | 变了吗 |
| --- | --- |
| 用户验收标准满足 + 相关测试通过 + 无未闭合 P1（ADR-0081 的发布闸门） | 不变 |
| **最终全量**（两阶段 pytest + 全量前端 + ruff），ADR-0068 | 不变 |
| [待复审清单](../design/active/pending-codex-rereview.md)无覆盖本分支历史的未闭合项 | 不变，**且更重要** |
| main 已是分支祖先、树干净、Gate 绑定当前 tip | 不变 |

**「更重要」不是修辞。** 以前这条清单还有第二道保险：一个人在合并前会看一眼。
现在没有了。TASK-102 的教训（只查任务卡 verification、没查清单，含未补审修复的历史
被合进 main）在没有人工闸之后**代价更高**，所以 `merge` 保留 `--ledger-checked`
这个显式声明，一步都不省。

### 决策 3：Merge Gate 机制保留，换的是它的**依据**

`set-merge-gate --gate PASS --by "<依据>"` 不删。它有两个与「谁授权」无关的作用：

1. **留痕**：清单里写明这次合并是凭什么放行的；
2. **绑 tip**：Gate 绑在设置时的分支 tip 上，`premerge-sync` 或新提交移动 HEAD
   之后会 `BLOCKED_STALE_GATE`，逼你在**当前** tip 上真的重跑过验证才能继续。

第 2 条是纯机械保护，和人工闸毫无关系，删掉它只会让「验证跑在旧 tip 上」重新变成
可能。**变的只有 `--by` 写什么**：从「用户原话 + 日期」换成「Done 判定 + 最终全量的
结果」。

### 决策 4：还剩下的人工闸只有一个 —— 花钱

AGENTS.md §1「真正必须问的只有一件：付费 / 真实花钱」保持不变，理由也没变：
花的是用户的钱，而他在这件事上有 Agent 没有的信息（预算、这次值不值得）。
ADR-0006 / ADR-0009 的窄授权不得自行扩大。

**「会话权限层拒绝」不是闸**，是外部限制：如实报告一次，不反复问。

## 后果

### 正面

- 一条完整的链（实现 → 验证 → 审查 → 提交 → 推送 → 合并）第一次可以一次跑完，
  不在最后一步停下来等一句话。
- 「规则说要问、实际不问」这种缝不会出现 —— 规则和行为对齐了。

### 代价（已接受）

- **一次错误合并不会再被人拦住。** 兜底从「人看一眼」变成「revert」。
  这正是 §1 判据接受的那种代价：可逆的事直接做，错了重来。
- **待复审清单从「有两道保险」变成「只有一道」**，见决策 2。
- 一次合并会把分支上的**全部**历史交出去，包括别的 Change 叠在同一分支上的提交。
  auto-push 已有的出处检查（`BLOCKED_UNRECORDED_COMMITS`）继续是那道防线，
  它本来就不依赖人工闸。

## 明确不做

- 不删 Merge Gate、不删 `--ledger-checked`、不删最终全量（决策 2 / 3）。
- 不放宽「无未闭合 P1」。
- 不碰付费闸（决策 4）。
- 不允许 force push / 改写远端历史 —— 那**从来不是**人工闸能放行的东西，
  它是禁制（ADR-0079）。
