# ADR-0046: 批量付费生成的总额确认模式（motv 原型）

- Status: Accepted
- Date: 2026-08-07
- 关联: ADR-0041（单镜头付费 Gateway 写路径——本决策是其批量消费形态）、
  ADR-0045（付费图片窄授权）、ADR-0044（原型 scratch 域）

## 背景

ADR-0041 的付费视频生成采用"一次一镜头、逐 digest 确认"以保证消费知情。
用户在实际使用中明确要求"付费也要可以一键生成"。逐镜头弹窗在 8 镜头短剧
下可用性差。

## 决策

1. **一次总额确认替代逐镜头确认**：UI 的「一键批量生成（付费）」在执行前
   弹出一个汇总确认：列出将生成的镜头（跳过已有成片的槽位）、单价与
   **总额**（N × 单价）。用户确认该总额即视为对本批次内每一笔的授权。
2. **逐笔报价校验兜底**：批量执行仍逐镜头走 ADR-0041 的完整 Gateway 两步
   （preflight → submit）；UI 校验**每一笔** preflight 报价必须等于确认时
   使用的单价，且存在任何 blocker 即**立即中止批次**（已完成的不回滚，
   未执行的不再执行），绝不在偏离已确认价格时继续扣费。
3. **成片自动入画布槽位**：付费产物由 coordinator 写入核心 staging（既有
   行为不变）；新增只读桥接端点将该 staging 成片**复制**到
   `data/uploads/<project>/` 的对应槽位（不改核心文件、无新增花费），
   使画布/合成即刻可用。单镜头付费同样走此桥接。
4. 服务器端防重复扣费护栏（任务级 operation 守卫）不变，仍是最后防线。

## 后果

- 8 镜头批量从 16 次弹窗降为 1 次总额确认；
- 消费知情从"逐笔"变为"批次总额 + 逐笔等价校验"，弱化程度经用户明确
  要求并由价格等价校验与既有护栏兜底；
- 批量为顺序同步执行（每镜头约 1–2 分钟），UI 显示逐镜头进度。
