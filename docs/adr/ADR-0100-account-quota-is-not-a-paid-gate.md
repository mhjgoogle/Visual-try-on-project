# ADR-0100：账号额度不是付费闸 —— 判据是「会不会产生按次账单」

- 状态：**Accepted**（2026-09-05，实施 Agent 依 AGENTS.md §1 自行 Accept）。
  **本 ADR 不批准任何新的付费调用**：它做的恰恰相反 —— 把一条**不产生账单**的路
  从付费闸后面放出来，并写清楚放出来的判据，免得下一次有人拿它当「绕开花钱要问」的口子。

  > **但它动的是那道闸本身的判据，所以这一条必须让产品负责人看见。**
  > AGENTS.md §1 写着「涉及付费的 ADR 仍须用户 Accept」。本 ADR 不批准任何新的
  > 付费调用、也不放宽任何既有付费路（ADR-0045 / ADR-0041 一字未动），它只是把
  > 「什么算花钱」写清楚，并给不花钱的那条路**加上**了幂等与「不确定不自动重试」
  > 两条纪律 —— 方向是收紧，不是放宽。即便如此，**判据变更本身已如实上报**，
  > 产品负责人随时可推翻；推翻的代价只是回到「图片自动生成继续停着」，完全可逆。
  > 若发现有人拿本 ADR 当绕开付费闸的依据，那是误用：按决策 1 的表处理 ——
  > **拿不准就按计费处理，fail-closed 回闸后面。**

## 背景

AGENTS.md §1 只保留了一道人工闸：**花钱**。这道闸是对的，但它今天被实现成了
「**外部 Provider 调用**都要闸」——`_agent_image` 与付费视频共用
`--enable-paid` + `AI_VIDEO_WORKFLOW_ENABLE_PAID_COMMANDS=1`，闸后面才谈得上凭据。

产品负责人 2026-09-05 撞上了它的代价：图片自动生成因此**一直停着**，而他手上
就有能出图的账号。他要的不是「批准这次花钱」，是「别再卡住」。

于是要回答一个之前没人问过的问题：**闸的判据到底是什么？**
「调了外部服务」不是判据 —— 本仓库早就在用 `claude-code` / `codex-cli` 两个
跑在他订阅上的外部执行器，它们从来不过闸，因为**多跑一次不产生一笔新账单**。

## 决策

### 1. 闸的判据是「这一次调用会不会产生一笔按次账单」

不是「是不是外部服务」，不是「是不是要凭据」，也不是「是不是 `provider:` 前缀」。

| 这一次调用 | 例子 | 过不过闸 |
| --- | --- | --- |
| **按次计价，产生新账单** | MiniMax image-01 $0.0035/张、Hailuo 视频 $0.28/条 | **过闸**（ADR-0045 / ADR-0041 不变） |
| **消耗他账号里已有的额度**（订阅内 / 免费额度） | `claude-code`、`codex-cli`、Gemini 免费额度出图 | **不过闸** |

理由：闸存在是因为**用户有 Agent 没有的信息**（预算、这次值不值得）。一次不产生
账单的调用没有那个信息差 —— 拿它去问他，就是 AGENTS.md §1 说的「把工作退回给用户」。

### 2. 但「不花钱」不等于「不受约束」，额度是有限资源

不过闸的这条路**照样**遵守两条本来就为付费写的纪律，因为它们防的是
**重复消耗**，而不是重复付款：

- **§5.7 幂等**：同一个意图不得重复提交。重复点击、断线重发落到同一次生成上。
- **§5.8 不确定就不许自动重试**：超时 / 5xx / 连接中断之后，「可能已经消耗了一次
  额度」和「确定没消耗」是两件事，前者一律**不自动重试**，如实说不确定。

额度和钱唯一的区别是**它的单位**。把「反正不花钱」当成「可以随便重试」，
结果是他明天早上发现今天的额度昨晚被一个重试循环烧光了。

### 3. 额度耗尽是一个**具名**的结果，且**禁止**回退到付费路

供应商返回额度耗尽（HTTP 429 / `RESOURCE_EXHAUSTED`）时：

- 界面显示的是「今天的免费额度用完了」，**不是**笼统的「生成失败」（REQ-008 判据 4）；
- **不得**自动改走 ADR-0045 那条按次计费的路。那正好是最坏的一种「贴心」：
  他选这条路就是为了不花钱，而回退发生在他看不见的地方。

要走付费那条，得他自己去点付费那个按钮，那里有价格、有确认 —— 闸还在原处。

### 4. 凭据从**界面**来，不从环境变量来

产品负责人 2026-08-23：「不要加什么自己改不了自己限制的设置。这样我做什么都不能
自动化了。」环境变量 + 启动参数正是那种东西：它要求他离开对话、改命令行、重启服务。

因此：**设置页一个输入框，粘一次即可用，不重启**。存储落在
`APP_DATA_DIR/credentials.json`（应用数据目录，在仓库之外；`credentials.json`
本来也已经在 `.gitignore` 里，两层保险）。读取顺序是**先设置、后环境变量** ——
环境变量保留只是为了 CI 与自动化测试，不是给人用的路径。

**key 只进不出**：任何读接口都只回答「设没设 + 后四位」，永不回显完整 key，
也不写进日志、不进 prompt、不进 Run 记录。

### 5. 这条路**不复用**付费那条的 `--enable-paid` 开关

复用会把两件事重新绑在一起：他为了出图而打开付费开关，然后**付费视频命令也一起
开了**。开关的语义是「允许产生账单」，而这条路的前提正是「不产生账单」。

代价（接受）：多一个能力开关（有没有 key）。但它的语义是自明的 ——
没粘 key 就用不了，粘了就能用。

### 6. 选 Gemini 免费额度，不选 OpenAI，也不爬网页版

他说的是「网页版的 gemini 或者 gpt 的账户，codex 也可以用」。逐条核过：

| 候选 | 结论 |
| --- | --- |
| **Gemini（Google AI Studio 免费额度）** | **选它。** 同一个 Google 账号即可取 key，不要信用卡，免费额度足够日常出图（`gemini-2.5-flash-image` / Nano Banana） |
| OpenAI `gpt-image-1` | 不选：没有免费额度，按张计费 —— 接上去就退回他不要的那条路 |
| Codex CLI / Claude Code CLI | 不选：它们确实跑在他的订阅上，但**是写代码的 agent，出不了图** |
| 爬网页版 Gemini / ChatGPT | 不做：违反那两家使用条款、页面一改就碎、要长期挂一个登录着的浏览器。**而且没必要** —— 同一个账号就能拿到免费额度的 key |
| `gemini` CLI + nanobanana 扩展 | 不选：这台机器上没装，且它背后要的仍是同一个 key —— 多一层依赖，没换来任何东西 |

### 7. 厂商代码不进 `server.py`，进一个可注入 transport 的适配层

`server.py` 已经是 358KB 单体（[TASK-087 §3.6.1](../tasks/active/TASK-087-followup-ledger.md)），
而这次要加的是**一个厂商的报文形状**。它住在自己的模块里，对外只暴露一个纯函数：
拿 prompt 与一个 `transport` 可调用对象，回图片字节或一个具名失败。

于是**不联网也能把它测完**（假 transport），这正是 ADR-0045 那条路没做到、
只能靠真跑一次才知道对不对的地方。

## 后果

**变好的**：图片自动生成不再需要任何人拍板；`provider:` 前缀与付费闸的关系
也第一次被写清楚 —— 之前是靠「大家都知道」在维持。

**变差的 / 已接受**：

- 多一条生成路 = 多一处要说清「这一张是谁出的」。UI 上必须区分三条路
  （手工 / 账号额度 / 付费），否则「这张图花没花钱」会变成猜。
- 依赖一家供应商的免费额度政策。它变了（收窄、取消）我们只会在 429 里看到 ——
  所以决策 3 要求那个失败是**具名**的：政策变化会以「额度用完」的形式浮出来，
  而不是变成一个没人看得懂的 502。
- 决策 1 的判据依赖「我们知道这次调用计不计费」。目录里写了价的就是计费的；
  **拿不准时按计费处理**（fail-closed 到闸后面），不许反过来。
