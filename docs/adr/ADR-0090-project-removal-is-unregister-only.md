# ADR-0090：删除项目 = 只从列表移除，应用永不删他的文件

## 1. 背景

主页没有任何删除路径（`server.py` 里没有项目删除端点，`services/projects.js` 只有增改）。
代价已经发生过一次：产品负责人自己把 `照见未明` 的文件夹删了，界面上那条却一直在 ——
因为账户级注册表还记着它。他的原话是「有一个文件夹我明明已经删除了为什么一直出现」。

所以缺的不是「一个 rmtree 按钮」，而是**「界面里能把这件事了结」**。

## 2. 决策

### 决策 1：「删除项目」= 从列表移除，磁盘上的项目目录一个字节都不动

注册表条目删掉，项目文件夹原样留在磁盘上。这条路径是**纯可逆的** —— 重新打开那个文件夹
就回来了 —— 所以它只需要一次普通确认，不需要惊悚弹窗，也不需要问他任何别的问题。

这同时正面解决他撞到的不一致：界面记着而磁盘上已经没有的项目，现在能在界面里清掉。

### 决策 2：应用**不提供**任何删除文件的路径 —— 那是他自己的事

产品负责人 2026-08-27：「删除前端。后端的文件留下就好了啊。」「后端的文件我可以手动删除。」

所以本 ADR **刻意不做**软删除、不做回收区、不做彻底删除。理由不只是他这么要求，
也因为这是最诚实的分工：一个创作项目里是他的剧本、镜头和真实媒体，应用能给出的最好
承诺是**「我永远不动它们」**，而不是「我们替你放到某个回收目录去」。

一个副作用值得写下来：从列表移除之后，磁盘上那个文件夹仍然存在。这**不是**遗漏 ——
他要的就是这样；界面文案必须把这件事讲明（判据 2），免得他以为文件也一起走了。

### 决策 3：正在打开的项目不能就地移除

先切走或回主页再移除（判据 4）。否则界面会继续对着一个已经不在列表里的项目工作。

### 决策 4：一个端点，fail-closed

```
POST /api/projects/<name>/unregister   → 只改账户级注册表（projects.json）
```

与 `/api/skill/run` 同一个自定义头（CSRF）；未知项目 404；**它没有任何文件系统写操作**，
所以围栏问题在这里不存在 —— 这也是把范围收窄到注册表的额外好处。

本地（demo / 画布）项目住在 `localStorage` 的那份注册表里，由前端自己移除；
真实项目住在服务端注册表里，走这个端点。两者在界面上是同一个动作。

## 3. 后果

- **好的**：界面能了结这件事；应用在任何路径下都不会删他的创作数据；
  「界面记着、磁盘没有」这类不一致有了出口。
- **要接受的**：移除之后磁盘上的文件夹还在，需要他自己清理 —— 界面必须说清楚，
  否则「删了怎么还占着盘」会变成下一个疑问。
- **不做的**：不删文件、不做回收区、不做批量移除、不清 `runs.json` 里该项目的运行历史
  （那是账户级事实，删掉就再也查不出它曾经花过多少钱）。
