# ADR-0084：项目 / 流程模板是 Skill 包机制的第二个 kind，不是第二套

- 状态：**Accepted**（实施 Agent 自行 Accept，2026-08-23）
- 依据：AGENTS.md §1「技术 ADR 由实施 Agent 依本节授权自行 Accept」。本 ADR
  **不涉及付费，也不动用户数据**，因此不需要产品负责人 Accept。它决定的是
  「模板这个东西由什么机制承载」，是纯技术选择；模板长什么样、创作者怎么用，
  仍按 §1 的 UI/UX 规则 —— 先做出可演示的版本再由他看。
- 日期：2026-08-23
- 决策任务：[TASK-083](../tasks/done/TASK-083-phase3-adrs-first.md) ADR-D
- 缺口：GAP-21（[目标流程走查](../../src/ui-gap-audit/reports/target-workflow-walkthrough.md#gap-21--没有拿别人跑通的流程当模板)）
- 相关：[ADR-0067](ADR-0067-product-skill-package.md)（Skill 包三件套 + 三级来源）、
  [ADR-0056](ADR-0056-local-ai-runtime-and-film-skills.md) 决策 6（能力定义不可变）、
  [ADR-0066](ADR-0066-product-refactor-fixed-ia-review-layers-and-system-contract.md)
  决策 6（四条禁令）、[ADR-0053](ADR-0053-project-rooted-studio-storage.md)（项目根）

## 背景

目标产品 T-070：精选画布能以只读打开别人的完整工作流，右上「复制项目」一键变成
自己的起点。我们今天有 21 个 Skill —— 全部是**单步能力**。**「整条流程」这一级
没有任何可复用物**，每个新项目都从空白开始，创作者只能靠记忆重建上一次跑通的顺序。

TASK-083 把这件事挂起来，问的正是本 ADR 要答的那一句：

> 模板导出什么（结构，**不含媒体字节**）、与 Skill 包（ADR-0067 三件套 + 三级来源）
> 的关系 —— **是同一个机制的扩展，还是第二套？**

## 决策

### 决策 1：扩展 ADR-0067 的包机制，**不另起一套**

Skill 包已经解决了四件难事，而它们对模板**逐条同样必要**：

| ADR-0067 已解决的 | 模板为什么也需要 |
| --- | --- |
| 三级来源（项目 → 用户 → 内置）+ 同 id **整体覆盖**，不做字段级合并 | 模板同样要能「这一部作品专用」「这台机器上我的」「产品自带」三级；半个来自内置半个来自项目的流程，没人预测得了它会做什么 |
| `digest` 让版本指向**内容** | 一年后要回答「这个项目是从哪份模板起步的」。`flowVersion` 只回答作者说第几版 |
| 被历史引用过的版本**不得原地覆盖** | 模板一旦被项目引用，改它就是在改历史的解释 |
| 加载 fail-closed，绝不「尽力加载一部分」 | 少了一步的流程跑出来的东西，**看起来和完整的没有区别** —— 与 ADR-0067 决策 7 同一个理由 |

另起一套等于把这四件事再解一遍，还会在产品里造出**两个「创作者拥有的东西」**的
概念，创作者要学两遍，我们要维护两份加载器。

### 决策 2：模板 = `kind: "flow"` 的包，三件套与 Skill 同构

```
<flow-id>/
  manifest.json    身份、version、kind:"flow"、title、适用范围、steps[]、conventions
  flow.md          人读的流程说明：为什么这样排、每一步在等什么、什么时候该停
  seed.json        新项目的结构骨架（空槽位，见决策 3）
```

对应关系是刻意的：`manifest.json` 是机器读的契约，`flow.md` 是要被人读、被人改、
被 diff 审阅的散文，`seed.json` 是结构。这与 ADR-0067 决策 1 里
「Prompt 是散文、输出契约是结构，读者不同」是同一条理由。

`steps[]` 的每一项引用一个能力：`{stepKey, skillId, skillVersion, note}`。
引用的是**版本化的能力**，不是能力的名字 —— 否则模板会随着 Skill 演进悄悄换了含义。

### 决策 3：模板带**结构**，不带**内容**。这是硬边界

| 带 | 不带 |
| --- | --- |
| 步骤顺序与每步的 `(skillId, skillVersion)` | 任何媒体字节 |
| 项目层约定：类型/基调、集数与时长规格、镜头命名规则、构图规范覆盖 | 剧本、角色、世界观、分镜的**内容**（只带它们的空槽位） |
| 结构骨架：几集、每集几场、每场几镜（空的） | Asset Registry / Generation Registry 的任何条目 |
| | 任何 Run 记录 |
| | 具体的 Prompt 文本（除非模板作者显式标为「约定」，如构图规范） |

**为什么这条要写死**：模板是「怎么做」，不是「做出了什么」。把内容带进去，
新项目开局就是别人作品的一份副本 —— 那不是模板，是抄袭形状的东西；而媒体字节
会让一份模板有几个 GB，三级来源里的「用户源」立刻变成一个媒体仓库。

### 决策 4：套用模板**不获得**付费、定稿、锁定、导出中的任何一种

与 ADR-0067 决策 4 同款，理由也同款：**可安装的第三方物件，绝不能因为「装了它」
而获得花钱或定稿的权限**（ADR-0066 决策 6 的四条禁令）。套用模板写的是新项目的
空骨架 —— 它不创建 Asset、不发起任何 Run、不锁定任何东西、不花一分钱。

「按模板把整条流程自动跑完」**明确不做**（见下）：那是自动化，不是模板。

### 决策 5：溯源 —— 新项目记 `createdFrom`

新项目的 canvas 记 `createdFrom: {flowId, flowVersion, flowDigest}`，三个字段一个
不少，理由与 ADR-0067 决策 3 逐字相同：`flowVersion` 回答「作者说这是第几版」，
`flowDigest` 回答「那一版到底是什么」。只有后者能让溯源链闭合。

### 决策 6：`steps[]` 引用了本机没有的能力 → **fail-closed，指名道姓**

加载一份 flow 时，逐条解析 `steps[]` 的 `(skillId, skillVersion)`。缺任何一个 →
**这份模板不可用，并说出缺的是哪一个**；不静默跳过那一步。

跳过一步的流程会安静地少做一件事，而少做的那件事**在结果上看不出来** —— 与
ADR-0067 决策 7 是同一个失效形状。

### 决策 7：位置 —— 与 Skill 包同址同构

| 来源 | 位置 |
| --- | --- |
| 项目 | `<ProjectRoot>/studio/flows/` |
| 用户 | `<应用数据根>/flows/` |
| 内置 | `<RepoRoot>/product-flows/builtin/` |

与 `skills/` 并列而不是嵌在里面：一个 flow 不是一个 skill 的一部分，
两者的 id 空间也必须分开（同名的 `storyboard` skill 与 `storyboard` flow 合法）。
[ADR-0067 补记（2026-08-16）](ADR-0067-product-skill-package.md)「三个来源的目录
不得越出自己的根」**原样适用**，不重新论证。

`<应用数据根>` 的实际位置由 [TASK-056](../tasks/done/TASK-056-app-storage-location.md)
定义（Windows `%LOCALAPPDATA%\motv`，POSIX `$XDG_DATA_HOME/motv`），不再是仓库内。

### 决策 8：「复制项目」不是模板，本 ADR 不定它

T-070 的右上角有两个不同的东西，产品里**不得共用一个词**：

- **模板**（本 ADR）：结构，不含内容，跨项目复用，有版本有 digest。
- **复制项目**：同机全量克隆，**含**内容与媒体，是项目管理动作。

复制项目要解决的是媒体字节怎么办（拷贝？引用？跨根？）—— 与本 ADR 无一处重叠，
留给它自己的卡。混在一起会得到一个「有时带媒体有时不带」的模板，那是最坏的结果。

## 后果

### 正面

- 「整条流程」第一次成为可复用物，创作者不必靠记忆重建上次跑通的顺序。
- 复用了包机制已经付过代价的四件事（三级来源、digest、不可原地覆盖、fail-closed），
  没有第二份加载器。
- 决策 3 的硬边界让模板天然小、天然可分享，且不携带别人的作品。

### 代价

- **多一类可加载物**：启动路径再长一点，且多一类新的失败（flow 引用了缺失的能力）。
  这正是决策 6 要求 fail-closed 的原因。
- **`product-flows/` 是仓库里的又一个顶层目录**（ADR-0077 的路径所有权表要加一行）。
- **模板作者写的 `flow.md` 与 `conventions` 是用户撰写的文本**，会被内联进发给
  执行器的提示词。与 ADR-0067 代价第三条同一个注入面，安全姿态不变
  —— 但**不因为「这是本地文件」就放松**。

## 明确不做

- 不做模板市场、不做远程安装、不做自动更新（与 ADR-0067 一致）。
- 不让模板声明新页面（ADR-0066 决策 1 的封闭集合不变）。
- 不让模板携带媒体字节或任何创作内容（决策 3）。
- 不做「按模板自动跑完整条流程」—— 那是自动化，不是模板，且会直接撞上决策 4。
- 不在本 ADR 里定「复制项目」（决策 8）。
- 不改 Run 合同的任何字段语义。
