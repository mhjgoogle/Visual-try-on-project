# 可复用 AI 短剧生产工作流 WFM1 v0.1

> 定位：供 VS Code 中的 Claude Code、Codex 等编码代理读取的顶层需求与流程架构文档。
> 目标：建立一条与具体剧情解耦、可重复执行、可逐步自动化的 AI 短剧生产流水线。
> 核心原则：AI 生成初稿 → 人工 Checklist 审核 → AI 定向修改 → 人工锁定版本。

本文档定义原 M1 之后的 WFM1 增量需求。原 M1 保持完成状态；本文档须在
`AGENTS.md`、Accepted ADR、`product_spec.md` 与 `architecture.md` 的既有
合同内解释，权威关系见 ADR-0007。

## 0. 项目约束

### 0.1 创作方向

目标是制作能带来精神升华的作品。每部作品必须在创意定稿时声明一个主打载荷，最多增加一个次要载荷。

四种载荷：

1. **人性光辉**：强烈羁绊、自我牺牲、不可逆选择。
2. **放松之笑**：笑点源自人物与情境，排斥纯梗堆砌。
3. **唯美**：画面、光影、构图与意象本身带来审美体验。
4. **精妙叹服**：公平线索、严密推理、悬疑解法的智性快感。

明确排斥：

- 浮于表面的喜剧
- 强行反转的爽剧
- 用说教台词直接表达主题
- 同时承载过多核心情绪，导致作品失焦

### 0.2 形态要求

- 短篇不是长剧的压缩版。
- 每部作品应尽量具备：
  - 单一强概念
  - 开场快速建立
  - 中段明确升级
  - 结尾留下余味
- 默认单集时长：45–60 秒
- 平台：运行时参数
- 画幅：运行时参数
- 默认视觉路线：电影感风格化
- 全写实真人：仅作为预算允许时的升级路径

### 0.3 技术环境

- Windows
- WSL Ubuntu
- VS Code
- Claude Code
- Codex
- GPU：GTX 1660 Ti 6GB
- RAM：16GB
- 本地图像生成：可行，默认 SD1.5 级
- 本地视频生成：不可行
- 视频生成：WFM1 默认使用云端 API；核心架构保持 Provider 中立

### 0.4 预算约束

- 月预算：5000 日元，硬约束
- 主方案必须能在预算内运行
- 超预算能力只能标记为升级路径
- 默认每集软预算：1200 日元
- 默认每集硬预算：1500 日元
- 所有生成任务必须记录：
  - 模型
  - 参数
  - 尝试次数
  - 成本
  - 耗时
  - 结果状态

# 2. 工作流审批状态机

需要人工审核和锁定的创意或生产物采用以下审批状态：

```text
DRAFT
  ↓
REVIEW_NEEDED
  ↓
REVISION
  ↓
APPROVED

任意阶段可进入：
REJECTED
```

规则：

- 未达到 `APPROVED` 的内容，不得作为正式下游输入。
- 已批准内容如需修改，必须创建变更记录。
- 禁止无记录地覆盖已批准版本。
- 所有阶段必须支持断点续做。
- 本审批状态属于独立工作流语义域，不替代、不映射为
  GenerationTask、StepManifest、Provider 或 orchestration 状态。
- 本文只定义审批流程要求；具体持久化结构由 `TASK-014` 及后续批准任务
  或新的 ADR 决定。

# 3. L0 前置流程

## 3.1 L0 总表

| 编号 | 环节 | AI 主要工作 | 人工判断 | 产出物 | 完成判定 |
|---|---|---|---|---|---|
| L0-01 | 灵感捕捉 | 整理碎片想法，提炼冲突、意象和情感 | 判断是否值得继续 | `idea_card_v001.json` | 能说明最吸引人的核心 |
| L0-02 | 强概念提炼 | 生成多个强概念与 logline | 选择或组合，不允许平均折中 | `logline_candidates.md` | 主角、目标、阻力、独特机制清楚 |
| L0-03 | 载荷声明 | 分析四种载荷适配度 | 锁定一主、最多一次 | `load_declaration.json` | 明确观众最终应产生的感受 |
| L0-04 | 短篇适配 | 压缩为开场、升级、转折、余味 | 判断是否为完整短篇 | `shortform_test.md` | 60 秒内发生一次不可逆变化 |
| L0-05 | 可行性判断 | 评估人物、场景、动作、成本与重试 | 判断降复杂度或调整方案 | `feasibility_report.json`、`cost_estimate.json` | P90 成本不超过硬上限 |
| L0-06 | 概念试制 | 制作 3 个代表镜头的低成本方案 | 判断概念、画风、生成性 | `concept_probe/` | 至少一个方案通过内容、视觉、成本检查 |
| L0-07 | 创意定稿 | 汇总确认项与未决项 | 最终签署创意锁定 | `concept_lock_v001.json` | 主载荷、logline、结尾、核心机制锁定 |

## 3.2 四载荷审核 Checklist

### 人性光辉

- 牺牲是否来自人物关系和选择？
- 人物是否付出真实且不可逆的代价？
- 情感是否通过行动呈现，而不是说教？
- 人物的选择是否符合此前建立的人设？

### 放松之笑

- 笑点是否来自人物性格、身份或具体困境？
- 删除流行梗后，场景是否仍然成立？
- 笑点是否推动剧情或关系变化？
- 是否避免纯段子拼接？

### 唯美

- 美感是否服务于情绪与主题？
- 是否存在至少一个可被记住的视觉意象？
- 静音观看时，情绪是否依然可理解？
- 构图、光线、色彩是否统一？

### 精妙叹服

- 解法是否由前文已经出现的信息推出？
- 观众回看时能否找到公平线索？
- 结尾是否重新解释前文，而非临时补规则？
- 反转是否改变理解，而不是只追求惊讶？

# 4. L1 顶层阶段

各阶段的精确逻辑输入、输出、责任主体和 Gate 见
[L0–S7 工作层级输入输出合同](design/workflow-stage-step-io-contract.md)。下表是创作
视角摘要，不代替该合同，也不授权物理路径。

| 阶段 | 名称 | 进入条件 | 核心产出物 | 完成判定 |
|---|---|---|---|---|
| S1 | 叙事设计 | `concept_lock` 已批准 | 故事圣经、节拍表、剧本、连续性表 | 内容完整承载主载荷 |
| S2 | 视听设计 | 剧本结构稳定 | 格式锁定、视觉圣经、角色/场景/声音规范 | 三个代表镜头试制通过 |
| S3 | 生产设计 | 剧本与风格锁定 | 分镜、镜头任务卡、生成路线、预算计划 | 每个镜头都有方法与验收标准 |
| S4 | 素材制造 | 镜头计划批准 | 图片、视频、对白、音乐、音效 | 所有必需素材达到可剪辑状态 |
| S5 | 装配后期 | 核心镜头齐备 | 粗剪、精剪、混音、字幕、调色版本 | 叙事、节奏、技术质量通过 |
| S6 | 质量与发布 | 成片候选完成 | QC 报告、母版、平台包 | 无阻断问题，授权与成本记录完整 |
| S7 | 复盘归档 | 已发布或决定终止 | 数据、复盘、可复用资产 | 经验回流工作流资产库 |

关键规则：

- 平台和画幅允许在 L0 保持 `TBD`。
- 进入 S3 正式分镜前，必须完成 `format_lock.json`。
- S4 允许单镜头返工，但不得无记录地修改上层规则。
- 修改锁定内容时，必须创建 `change_request` 并列出受影响文件。

# 6. 工具链建议

## 6.1 AI 员工分工

| 工作 | 主方案 | 高端模型使用条件 |
|---|---|---|
| 日常剧本初稿与修改 | Claude Sonnet | 不使用高端模型 |
| 核心机制、人物选择、复杂悬疑 | Claude Opus | 仅 L0 定稿与重大逻辑冲突 |
| 工作流架构、结构审查、任务规格 | GPT Thinking | 仅阶段设计与独立终审 |
| 批量反方审查、候选方案 | DeepSeek | 只负责列疑点，不直接批准 |
| 参考图、分镜和成片多模态检查 | Gemini Flash/Pro | 大批量优先 Flash |
| 编码实施 | Claude Code | 高风险模块才升级高端模型 |
| 独立代码审查 | Codex | 不参与原始实施 |

原则：

- 同一个模型不得既创作又独自批准。
- 高端模型只处理会造成大规模返工的问题。
- 日常修改优先使用主力中档模型。
- 批量分类、摘要、格式转换优先使用低成本模型。

## 6.2 生产工具方向

| 环节 | 主方案 | 升级路径 |
|---|---|---|
| 本地图像 | ComfyUI + SD1.5 + ControlNet/IP-Adapter | 云端高质量关键图 |
| 云端图像 | 按量付费的快速图像 API | 高质量图像模型 |
| 视频 | 低成本图生视频 API | 高质量电影级视频 API |
| 配音 | 按字符计费 TTS API | 专业配音或高级情绪模型 |
| 音乐 | 短音乐生成或授权素材 | 定制音乐 |
| 音效 | 授权素材库 + 少量 AI 生成 | 专业声音设计 |
| 自动装配 | FFmpeg | 无 |
| 人工精剪 | DaVinci Resolve 免费版 | Studio 版 |
| 元数据管理 | JSON Manifest + 文件系统 | SQLite |
| 文本与代码版本 | Git | 无 |
| 二进制大文件 | 文件系统 + Manifest | 对象存储 |

本表是生产工具方向建议，不构成 Creation Workspace 技术选型；其中 SQLite、
对象存储等升级路径不得被解释为已决定的工作视窗数据库或部署结构。

# 7. 成本控制模型

## 7.1 单集预算目标

默认目标：

- 成片：45–60 秒
- 镜头数：6–12
- 云端视频生成时长：20–35 秒
- 其余画面使用：
  - 静帧
  - 轻推拉
  - 2.5D
  - 反应镜头
  - 环境镜头
  - 遮挡切换
- 平均每个云端视频镜头：最多 2 次尝试
- 单集规划成本：900–1200 日元
- 单集硬上限：1500 日元

## 7.2 成本红线

以下情况必须停止继续抽卡并回到镜头设计：

- 同一镜头连续失败 2 次
- 当前累计成本超过单镜头预算 80%
- 已发现问题属于构图、动作复杂度或连续性设计
- 更换模型不能解决根因

## 7.3 高端模型 Token 控制

每次提交给高端模型，只提供：

1. 已锁定规则摘要
2. 当前待解决问题
3. 必要证据或冲突
4. 明确输出格式

禁止：

- 直接塞入完整历史对话
- 重复发送已锁定但与当前任务无关的内容
- 用高端模型做格式化、分类、批量摘要
- 无验收标准地让模型自由扩写

# 8. 工作流资产与剧集实例分离

ADR-0001 的 `<project-data-root>` 及其稳定目录是唯一有效的项目目录合同，
WFM1 不替换、不迁移该合同。所有 WFM1 结构化持久化产物继续使用 JSON；
本节中的产物名称是逻辑需求，不自行授权新的落盘路径。

`workflow/` 在 WFM1 中表示“全局复用资产”的概念集合，可包含 schema、
模板、Checklist、prompt、配置和固定自动化职责。它不是本批次强制创建的
物理目录；如后续决定落盘，必须由 `TASK-014` 及后续批准任务或 ADR 明确
位置、所有权和与 ADR-0001 的关系。

分离原则：

- 全局复用资产不得包含具体剧情或单集生成结果；
- 单部作品的输入、状态、媒体和交付物属于调用方选择的项目数据根；
- 项目实例通过显式、可追踪的引用使用复用资产；
- 任何新增目录都不得改变 ADR-0001 的既有路径语义或冻结合同。

| `generate_qc_packet.py` | 生成连续性与技术审核包 |
| `package_release.py` | 按平台规则生成发布文件 |

要求：

- 固定类操作不得依赖人工重复复制。
- 所有脚本必须支持幂等或明确拒绝覆盖。
- 所有写入必须有日志。
- 失败不得破坏已批准资产。
- 所有外部 API 调用必须可追踪。
- 所有生成结果必须记录 Provider、模型、参数和成本。

# 10. 里程碑路线图

## WFM1：60 秒可复用工作流跑通

范围：

- 一个角色
- 一个场景
- 一个主载荷
- 6–10 个镜头
- 不追求多角色复杂互动
- 不追求全片精准口型
- 不追求全写实真人
- 不追求复杂动作和长镜头

通过标准：

- 从创建项目到输出成片跑通
- 所有阶段有明确状态
- 固定步骤可自动执行
- 生成成本不超过 1200 日元
- 支持中断后继续
- 能输出一版可观看成片

## WFM2：第一部满意的正式作品

范围：

- 完整执行 L0–S7
- 8–12 个镜头
- 正式音画
- 主载荷明确成立

通过标准：

- 无阻断 QC 问题
- 单集成本不超过 1500 日元
- 已完成复盘
- 已记录模型表现与返工原因

实施归属：TASK-034 锁定完整 L0–S3；TASK-035 补齐多媒体生成与谱系；既有
TASK-008 在 ADR-0038/0039 下实现音频/字幕；TASK-036 完整化 S4–S7；TASK-037
执行 WFM2 milestone 验收。架构合同由 ADR-0037～0039 裁决。

## WFM3：自动化率提升

目标：

- 自动创建项目
- 自动校验阶段
- 自动生成任务包
- 自动提交 API
- 自动归档生成物
- 自动计算成本
- 自动生成代理预览
- 自动生成 QC 包
- 自动生成发布包

创意判断与最终批准始终保留人工完成。

实施归属：TASK-012 的可审计 QCD 路由由 TASK-038 统一承接；TASK-038 同时建立
自动化职责和 command capability registry，受 ADR-0040 约束。TASK-011 本地
Provider 是可选升级，不是 WFM3 最小通过条件。

# 11. 最容易失败或返工的三个环节

## 11.1 概念同时承载过多载荷

后果：

- 作品失焦
- 60 秒内没有明确体验
- 每种情绪都不够强

早期拦截：

- 强制一主、最多一次
- L0 必须完成载荷声明
- 用 60 秒节拍表验证

## 11.2 人物与画风未锁定就批量生成

后果：

- 人脸漂移
- 服装变化
- 场景不一致
- 大量素材返工

早期拦截：

- S2 必须先完成三个代表镜头
- 未通过视觉试制，不得进入 S4
- 角色、场景、道具必须登记母资产

## 11.3 无限制重试视频

后果：

- 预算耗尽
- 问题根因未解决
- 生成结果越来越随机

早期拦截：

- 每镜头设置尝试上限
- 连续失败 2 次，强制回到镜头设计诊断
- 禁止继续无目的抽卡
- 必须记录失败类型

# 14. 总原则

> 先验证最贵、最难、最能代表作品的部分，再扩大生产。

> 自动化负责重复劳动，AI 负责生成候选，人工负责价值判断和最终定稿。

> 能跑通优先于完美，MVP 优先于完整系统。

> 工作流必须与具体剧情解耦，具体作品永远只是运行时输入。

# 15. 与统一创作工作视窗的关系

未来 Creation Workspace 将观察和运行本工作流，但不是 WFM1 的组成部分或验收
条件。统一需求见
[ai_video_creation_workspace_requirements.md](ai_video_creation_workspace_requirements.md)，
安全边界见 [ADR-0010](adr/ADR-0010-creation-workspace-boundary.md)。
数据 readiness 语义见
[creation_workspace_data_observability_requirements.md](creation_workspace_data_observability_requirements.md)。

WFM1 当前只承担以下前置责任：

- 为项目、阶段、步骤、任务、版本和产物保留稳定可追溯身份；
- 保留输入/输出关系、content digest、Provider/模型/参数、时间和成本证据；
- 继续通过审批、预算、并发、恢复和防覆盖合同执行所有命令；
- 使状态和派生报告可从权威文件/事件读取或重建。

WFM1 不实现工作视窗、Command Gateway、Action Center、实验比较 UI 或跨项目
学习系统，也不为这些未来能力锁定最终 schema。历史任务中的 Web UI/数据库排除
是对应任务的局部范围，不取消该未来产品方向。

工作视窗现已按 TASK-024～033 建立 WFM1 数据基线路线，见 ADR-0030；TASK-033
不是完整产品验收。WFM2/WFM3 完成后由 TASK-039 扩展多媒体与命令能力，最终由
TASK-040 联合验收本文与工作视窗统一需求。任何 Workspace 实施都不得反向扩大
WFM1 或把 Workspace 状态写入 WFM1 核心合同。
