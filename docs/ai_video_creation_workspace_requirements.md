# AI 视频创作工作视窗统一需求

> **状态：Draft（产品方向已确认，实施范围未拆分）。**
> 本文定义核心 AI 视频工作流稳定后的统一创作控制台需求，不表示当前代码已经
> 实现这些能力。当前不分配正式 TASK 编号，不选择最终界面技术，不锁定数据库
> 或持久化 schema。安全边界见
> [ADR-0010](adr/ADR-0010-creation-workspace-boundary.md)，核心数据 readiness 见
> [Creation Workspace 数据可观察性要求](creation_workspace_data_observability_requirements.md)。

## 1. 产品定位

建立一个跨项目统一使用的 AI 视频创作工作视窗（Creation Workspace）。它不是
单纯流程查看器，而是日常创作控制台，用于观察、运行、管理、评价和持续学习：

```text
设定创作目标
→ 运行工作流
→ 观察过程和产物
→ 比较与评价
→ 发现问题
→ 重新运行或创建 Action
→ 确认结果
→ 项目复盘
→ 沉淀经验
→ 应用于下一个项目
```

常规创作操作由工作视窗承载；异常问题形成 Action；代码、Provider、步骤或数据
合同变更仍由 Agent 在正式任务和 ADR 治理下实施。

## 2. 观察层

### 2.1 项目与流程

统一展示所有项目的当前阶段、整体及阶段进度、正在运行的步骤、等待/失败/
阻塞/跳过状态、最近产物、最近问题、累计成本和剩余预算。新项目尚未运行时也
必须由工作流定义显示完整计划，不得只根据已有运行记录拼出不完整流程。

阶段详情展示步骤依赖、输入/输出、运行状态、Provider、模型、运行时间、尝试
次数、预计/实际成本及失败或阻塞原因。

### 2.2 产物谱系

支持从任意产物向上追溯来源、向下追溯消费者：

```text
创意 → 剧本 → 分镜 → 提示词 → 参考图片 → 生成图片
→ 视频提示词 → 生成视频 → 音频与字幕 → 最终成片
```

谱系至少依赖稳定 ref、version、content digest、生产步骤/任务、输入引用和输出
引用；工作视窗不得通过文件名猜测谱系。

### 2.3 提示词版本与结果比较

保留并展示提示词版本链、相对上一版的差异、修改原因、参考图片、模型与参数、
生成批次、全部结果、时间与成本、选中结果，以及该结果后续生成的视频。支持
提示词版本及其图片结果并排比较。

### 2.4 成本观察

展示每次生成的预计/实际成本、累计成本、预算警戒线、硬上限、失败和重试成本，
并按项目、阶段、步骤、镜头、Provider、模型和时间筛选。所有展示值必须标明
权威事实或派生值，且可由成本事件、锁定 FX 和 reservation 重建。

## 3. 运行层

### 3.1 常规操作

当核心工作流已提供相应安全命令时，工作视窗应直接支持：开始、暂停、取消、
重试、用新参数重新运行、从检查点继续、跳过允许跳过的步骤、选择结果、批准、
退回和进入下一阶段。工作视窗不得伪造核心工作流尚未支持的操作。

### 3.2 运行前检查

每个执行命令必须先检查并向用户展示：

- 上游完成情况、输入版本和必要审批；
- 预算、Provider 和模型可用性；
- 相同任务是否已运行或正在运行；
- 是否存在重复付费或未知计费风险；
- 操作绑定的版本、预计费用和受影响的下游步骤。

阻断时返回结构化、可解释原因，不提供绕过审批、预算、版本、并发或恢复合同的
快捷路径。高风险操作必须二次确认。

### 3.3 安全执行边界

```text
Creation Workspace
→ Command Gateway
→ 审批、预算、版本和并发检查
→ Workflow Orchestrator 应用边界
→ Provider
```

工作视窗不得直接调用 Provider，不得直接修改核心业务文件。所有状态变化由
Workflow Orchestrator 应用边界及现有指定写入组件完成。工作视窗关闭后，已提交
的核心工作流仍须独立运行和恢复。

## 4. 管理层

### 4.1 问题反馈与 Action

用户可从阶段、步骤、提示词、图片、视频、音频、成片、成本事件或错误事件创建
反馈。系统自动带入项目、阶段、步骤、任务、Provider/模型和对象版本上下文。

Action 必须绑定目标对象的 `ref + version + content_digest`，并保留问题、处理者、
执行记录、新旧产物、成本变化和验证结果。目标版本漂移时 Action 自动失效或要求
重新绑定，不得让 Agent 或执行系统作用于错误版本。

### 4.2 Action Center

统一展示 `pending`、`in_progress`、`waiting_for_user`、`completed`、`blocked`、
`cancelled`、`stale`。Action 状态是独立管理语义，不替代工作流审批、
GenerationTask、Manifest、Provider 或 Orchestrator 状态。

闭环为：发现问题 → 创建反馈/Action → Agent 或执行系统处理 → 返回新版本 →
用户验证 → 确认解决或继续修改。

## 5. 评价层

### 5.1 创作目标

项目开始时记录表达意图、目标观众、叙事目标、风格/情绪目标、质量底线、成本/
交付目标、禁止问题和项目成功标准。评价必须回到这些目标，而不是只比较技术指标。

### 5.2 质量评价与创作决定

按产物类型记录角色/场景/风格一致性、构图、画面质量、动作自然度、镜头连续性、
叙事清晰度、情绪感染力、声音/字幕质量和成本效率。保留用户评分、AI 辅助评分、
问题标签、修改建议、是否通过、选择或放弃原因；最终判断始终由用户确认。

### 5.3 实验比较

支持比较提示词版本、模型、参数、参考图片、生成批次和后期方案，并记录修改内容、
原因、预期改善、实际结果、增量时间/成本和复用价值。重要创作决定必须可追溯，
包括选择、放弃、改提示词、换模型、重做和接受不完美结果的原因。

## 6. 学习层

### 6.1 项目复盘

项目完成后从权威运行、成本、评价和 Action 记录派生：耗时/返工最多的步骤、重复
问题、提示词成功率、模型稳定性和成本效率、Action 效果、未解决问题，以及下个
项目应继续、停止或尝试的事项。

### 6.2 跨项目指标

观察首次通过率、平均返工次数、制作时间、项目/单镜头成本、质量评分、重复问题、
提示词模板成功率和 Action 解决率。指标必须有稳定定义、时间范围和来源，不得把
派生报告变成第二事实来源。

### 6.3 经验沉淀与推荐

可复用知识包括有效/失败提示词模式、模型参数组合、角色一致性方案、镜头设计模式、
质量 Checklist、常见问题与解法、预算模板和工作流模板。新项目可推荐类似项目、
模板、Provider/模型、风险、预算和检查项，但必须说明历史证据，不自动替代用户
创作决定。

## 7. 可靠性与安全原则

- 工作视窗关闭不影响核心工作流运行和恢复；
- 工作视窗不直接写核心业务文件、不直接调用 Provider；
- 命令只经 Command Gateway 和 Workflow Orchestrator 应用边界执行；
- Provider 继续只返回结构化结果，不写业务状态；
- 防止重复运行、重复付费和对未知计费状态自动重提；
- 高风险操作二次确认，运行前展示输入、预计费用和下游影响；
- 可视化 projection、索引或缓存损坏时可从权威业务数据重建；
- 凭据不得进入浏览器持久化、业务文件、日志、异常或 Action；
- 所有可修改参数必须由核心命令合同显式允许，不提供任意文件编辑入口。

## 8. 当前阶段与建设顺序

核心 AI 视频工作流尚未完成。当前只要求正在设计的核心产物保留稳定标识、版本、
digest、输入/输出关系、Provider/模型/参数、时间、成本、评价和问题关联能力；这不
授权提前实现 UI、数据库、Action schema 或通用事件平台。

当前不设置正式任务编号，不锁定最终界面技术和数据结构。

### 8.1 核心工作流 readiness gate

进入任何工作视窗实施任务前，至少满足：

- TASK-018～023 已完成并通过 WFM1 milestone review；
- 项目未运行时也能从权威定义获得完整计划；
- 版本、谱系、运行、成本、评价和问题满足
  [数据可观察性要求](creation_workspace_data_observability_requirements.md)；
- 删除测试 projection 后可以从权威数据确定性重建；
- 统一 query 语义可以定义，而不需要读取 Agent 对话、解析自由日志或猜文件名；
- 仍未满足的字段明确标为 `unavailable/legacy`，不存在伪造补值。

readiness gate 只证明核心数据足以被观察，不表示 Command Gateway、Action 或 UI
已经设计完成。

### 8.2 后续建设顺序

核心工作流通过 readiness gate 后，再按以下顺序形成任务卡和必要 ADR：

```text
核心工作流和 Orchestrator
→ 统一运行命令和状态契约
→ 只读观察窗口
→ 提示词、图片和视频版本观察
→ 评价与实验比较
→ Action Center
→ Command Gateway
→ 工作视窗直接运行
→ 项目复盘与跨项目学习
```

每一阶段优先复用已有 CLI/app service、审批、预算、QCD、digest、恢复和防覆盖
能力，不为界面重写核心工作流。在 Command Gateway 可用前，工作视窗阶段只能
提供只读观察；反馈、评价或 Action 的写入仍须通过当时已批准的 CLI/app service，
不得由界面直写文件。

## 9. 当前明确不决定

- Web、桌面、VS Code 扩展或其它界面形态；
- 前端框架、后端框架、部署方式和通信协议；
- 是否使用数据库、搜索索引、消息队列或后台 worker；
- Command Gateway、Action、评价、实验、谱系和知识库的最终 schema/API；
- pause/cancel/skip 的精确状态转换和厂商取消计费语义；
- 工作视窗建设任务编号、里程碑名称和验收批次。
