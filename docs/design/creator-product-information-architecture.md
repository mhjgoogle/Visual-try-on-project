## 1. 一级导航（封闭集合）

```
┌─────────────────────────────────────────────────────────────────┐
│  ▣ 项目名 ▾            故事开发 │ 剧集制作 │ 资产库        ⚙ 设置 │
└─────────────────────────────────────────────────────────────────┘
```

| 空间 | 一句话 | 对象层级 |
| --- | --- | --- |
| 故事开发 | 把故事写出来 | Project → 故事核心 → 大纲节点 → 结构规划行 → 章/集正文 |
| 剧集制作 | 把这一集做出来 | Episode → Scene → Shot → Artifact |
| 资产库 | 我有什么可以复用 | Asset（跨集、跨阶段） |

- **⚙ 设置**不是第四个空间，`route key` 是 `projectsettings`（**不得复用
  `settings`** —— 那是「作品设定」的正式 key）。分区：项目信息 / 体检 / 成片规格 /
  预算与限制 / 存储与诊断 / 能力目录。
- 三个空间之外**不存在**任何一级入口。

## 2. 全站骨架：恰好三栏（REQ-004）

**每一页都是三栏，列数不随页面变化**：

```
┌──────────┬────────────────────────┬──────────────┐
│ 左：控制  │  中：工作区              │ 右：与 Agent  │
│ 与选择    │                        │ 的对话        │
│          │                        │ ┌──────────┐ │
│ 页面导航  │                        │ │ 消息流    │ │
│ 选择器    │                        │ ├──────────┤ │
│ 检查器    │                        │ │ 输入框    │ │
└──────────┴────────────────────────┴──────────────┘
```

- 右栏**只有对话**，形态对标 Claude Code：可滚动消息流 + 固定在底部的输入框。
  没有面板堆叠、没有全局悬浮球、没有每个字段旁的魔法棒。
- **对话按页面分开**（REQ-004 v3）：换页 = 换一条对话线，各自保存自己的历史。
- 右栏有两个 tab：**作品**（改这部作品）与**开发**（改这个软件）。
  服务端禁止「开发」窗口写作品文件（[ADR-0089](../adr/ADR-0089-conversational-agent-write-path.md)）。
- Agent 每轮携带**当前页面 locator + 页面地图**，所以它知道创作者此刻站在哪一页、
  选中哪一集哪一镜（当前架构合同 `CA §6`）。

## 4. 页面职责

### ① 故事核心 `brief`

- **一篇大文章，一个大编辑器。** 立意、主角、冲突、世界规则、人物关系，
  连类型/基调也写在这里。
- 形态（小说 / 剧集）不替创作者默认。
- 成片规格与预算在本页**只读**，唯一编辑入口是 ⚙ 项目设置。
- 合并自：旧「项目与创意」「创意简报」。

### ② 故事大纲 `story`

- 像普通文本一样写，系统自动给每段一个**稳定编号**（`§1`、`§2`…）。
  改错别字、中间插段落，其余节点 id 一个不变 —— 结构规划的引用因此不会集体断掉。
- 日常编辑**不产生版本**；点「定稿」才存一版，历史默认收起，可查看 / 恢复 / 手动删。

### ③ 结构规划 `episodes`

- **固定九列的表**，每行可引用第 ② 步的大纲节点。
- 三个入口（分区）：结构表 · **角色设计** · **场景设计**。后两者读写的是**既有的**
  人物 / 场景地数据 —— 「基础财产」的意思正是这个：写小说、做剧集用的是同一份，
  不许在这里另开一份。
- 合并自：旧「分集规划」+ 旧「作品设定」的人物 / 场景部分。

### ④ 正文创作 `script`

- 先选**小说创作**或**剧集创作**，设 Planned Chapters / Episodes；
  章/集用**页内选择器**（不进全局左栏）。
- 二级 Brief + 大编辑器 + Copy（手工兜底：复制 Prompt → 外部跑 → 粘回，
  走同一道输出契约与确认门）。
- **通往「剧集制作」的入口只在这里。**

### ⑥ 制作画布 `board`（剧集制作的唯一默认入口）

一屏三样（TASK-124）：

1. **一条流水线** —— 剧本 → 设定同步 → 分镜 → 画面 → 视频 → 音频 → 剪辑 → 成片，
   每段带数。数据来自既有的 `productionPlan`，不另算一份。
2. **一排镜头卡** —— 一镜一张：缩略图、走到哪、卡住的原因、**一个**主按钮「下一步：…」。
   点它 = 选中这一镜 + 跳到那一页。
3. **一句下一步** —— 整集此刻最该做的那件事。

**硬要求**：每个异常项都必须能直接跳到对应对象（镜头 / 资产 / 任务）——
一个不能被点开的异常只是抱怨。

### ⑦ 分镜设计 `storyboard`

- 三栏列表，**不使用节点图**：场景列表 · 镜头列表 · 镜头卡。
- 镜头卡字段：镜头描述 / 景别·角度·运镜 / 台词与计划时长 / 人物·场景·道具 /
  参考素材（只读摘要）/ 首帧要求 / 视频要求。
- **3D 导演台**（分区）：一镜一份 blocking —— 场地、时长、演员起止站位与朝向、
  道具、机位起落幅。俯视图拖着摆，时间线可播放，可**录白膜**（登记为
  `motionpreview`，**不参与成片判定**）。

### ⑧ 镜头制作 `shotwork`

四步，顺序即分区：`① 准备输入 → ② 制作主画面 → ③ 制作视频 → ④ 对比候选并选定`。

- **每个任务必须显示**：状态 · 耗时 · 成本 · 失败原因 · **重试** · **真实取消**
  （取消传递到后台任务，不是清空前端状态）。
- ④ 的「选为最终版本」= 检查层 1 的定稿动作。

### ⑨ 粗剪审片 `cutreview`

- 上=播放器（整集连播）· 中=镜头条 · 下=问题列表 · 右=粗剪版本条。
- 必须支持：自动生成粗剪 · 整集播放 · 顺序与时长调整 · 问题标记 ·
  **问题定位到镜头** · 退回重做 · 版本管理 · **用户确认整集审片通过**。
- Agent 在这里输出的是**问题列表**，永不直接改剪辑。

### ⑩ 后期交付 `delivery`

七个分区：时间线 · 配音 · 环境音/音效/音乐 · 字幕 · 成片预览 · **交付质检** · 导出及导出记录。

- 字幕无 ASR 时显示 `not available`，**绝不伪造听写**。
- **明确不做**：不是 Premiere / DaVinci 的替代品。

### ⑪ 资产库 `assets`

- 一个页面，条件筛选：对象类 / 媒体类 / 范围 / 状态 / 已保存筛选。
- **抽屉形态**：镜头制作的「添加参考」打开的是同一个组件的抽屉模式。
  一份实现，两个触发点。

## 5. 流程与三个检查层

```
 1 创建项目
 2 设置成片规格、预算与限制        ⚙ 项目设置
 3 写故事核心                      ① 故事核心
 4 写故事大纲（自动节点编号）      ② 故事大纲
 5 填结构规划九列表 + 角色/场景    ③ 结构规划
 6 写章/集正文                     ④ 正文创作            [进入剧集制作的唯一出口]
 7 看这一集现在该做什么            ⑥ 制作画布
 8 拆场景与镜头、设计每一镜        ⑦ 分镜设计
 9 摆位与白膜预演（可选）          ⑦ 分镜设计 · 3D 导演台
10 绑参考 → 主画面 → 视频          ⑧ 镜头制作 ①②③
11 单镜头对比与定稿                ⑧ 镜头制作 ④        [检查层 1 · 用户确认]
12 整集粗剪与审片                  ⑨ 粗剪审片           [检查层 2 · 用户确认]
13 后期制作                        ⑩ 后期交付
14 交付质检                        ⑩ 后期交付           [检查层 3]
15 导出成片                        ⑩ 后期交付           [用户确认]
```

### 5.1 三个检查层（互不重叠）

| 层 | 页面 | 对象 | 检查什么 | 产出 |
| --- | --- | --- | --- | --- |
| 1 · 单镜头定稿 | ⑧ 镜头制作 ④ | 同一 Shot 的多个候选 | 人物 / 动作 / 构图 / 时长 / 画面异常 | 该 Shot 的 `confirmed` 版本 |
| 2 · 整集粗剪审片 | ⑨ 粗剪审片 | 由已定稿镜头组成的 Rough Cut | 剧情、节奏、衔接、连续性、缺镜 | Episode 的 `ReviewDecision` |
| 3 · 交付质检 | ⑩ 后期交付 | 一个 Delivery 候选 | 音画同步 / 字幕 / 音量 / 黑帧 / 缺帧 / 规格 / 素材权限 | QC Report（`blocking` / `warning` / `info`）|

层 1 不判剧情节奏（那是层 2）；层 2 不判音量字幕编码（那是层 3）；
层 3 发现「这场戏不好看」应回落到层 2。

### 5.2 五道门槛

| # | 门槛 | 规则 |
| --- | --- | --- |
| G1 | 测试粗剪 vs 正式审片 | 镜头未全部定稿：只能生成**测试粗剪**，不可提交正式整集审片 |
| G2 | 画面锁定 | 整集粗剪审片 `passed` 后，才可锁定画面剪辑并进入**正式**声音与字幕制作 |
| G3 | 结构变更回退 | 后期修改影响镜头结构 → 整集审片状态自动回落 `needs_rereview`，画面锁定解除 |
| G4 | 阻断导出 | 存在 open 的 `blocking` 交付问题时不可正式导出。**没跑过质检 = 未知，不是通过** |
| G5 | 版本非破坏 | 每次粗剪、每次导出**创建新版本**；禁止静默覆盖 |

**Delivery 生命周期**：候选 → 质检 → 用户确认导出 → Final 版本。

> **当前缺口（2026-09-04 实测）**：`render` 路径今天把合成结果**直接登记为 Final**
> （`assetlib.addFinal`，`kind: "final"`），G4 因此不是导出的真实前置条件。
> 这条与本节冲突的是**实现**，不是本节 —— 闭合它是切片 3，挂在
> [TASK-074](../tasks/active/TASK-074-delivery-migration-and-legacy-retirement.md)。
> 在闭合之前这一行必须留在这里：当前事实文档说了不算数，比没写更糟。

## 6. Agent 协作方式

### 6.1 一句自然语言 → 一个能力

创作者只面对**三个用户能力**（故事开发 / 剧集制作 / 故事审读）。选哪个内部专业
能力由**服务端确定性 resolver** 决定，模型无权指定 `skillId`；一轮最多起一个
（[ADR-0091](../adr/ADR-0091-three-user-capabilities-and-a-server-side-resolver.md)）。
材料不够时**说明缺什么并且不启动**。

### 6.2 Agent 读什么、能做什么

前端 Agent 读五样东西，来源各有唯一负责人，改页面时必须同步 —— 逐条见
[当前架构合同 §6](../current-architecture.md#6-agent-读什么改页面之前先看这一节)。

**他能点的 = 它能做的**：界面动作与 Agent 动作调用**同一组执行函数**
（`src/workflow/convactions.js`），不存在「Agent 专用的一份」。

> **当前缺口**：UI 事件入口与 Agent 动作仍是**两套手工登记**，没有「每个可逆 UI
> command 都自动出现在 Agent registry」的穷尽性合同。闭合它是切片 4。

### 6.3 双向回路

Agent 给的方案钉在「开发」窗口标题栏下面（不是塞进消息流顶端 —— 那等于没画），
带完整正文与同意 / 拒绝 / 修改意见三个按钮；拍板走**服务端确定性端点**，
不经过模型（模型忘了给动作，创作者的话就白说一次）。

### 6.4 不可用就说不可用

- runtime 不可用 / 必要输入缺失 / 输出不符合契约 → 显示 `unavailable` 并说明原因，
  **不显示成一个会假装工作的按钮**。
- 每个 AI 动作都有**手工兜底**：复制任务 Prompt → 外部跑 → 粘回 → 走同一道输出
  契约与确认门。手工兜底的 Run 状态是 `awaiting_input`（「等你交结果」），
  不是「运行中」—— 机器在忙和等人交作业是两件事。

## 8. 用户与 Agent 的权限边界

### 8.1 Agent 可以自动执行

分析现有输入（只读）· 检查缺失与冲突 · 生成草稿（落 `draft`）· 生成建议
（落 `suggested`）· 生成候选（落 `candidate`，**不改 active 指针**）·
执行不产生外部费用的检查 · 标记质量问题（产出 `ReviewIssue`，不产出 `ReviewDecision`）。

若会消耗**付费**能力，则一律落入下一节。

### 8.2 必须由用户确认

锁定大纲/正文 · 覆盖用户修改过的内容（二次确认 + 差异预览）· 删除镜头或资产 ·
修改正式绑定关系 · **使用付费生成能力（显式确认 + 金额预览）** · 批量重新生成 ·
将候选设为最终版本 · 通过单镜头定稿 · 通过整集审片 · 忽略非阻断质量问题 ·
锁定粗剪 · **导出或发布成片**。

### 8.3 四条禁令

**Agent 不得静默覆盖 · 不得静默定稿 · 不得静默付费 · 不得替用户完成审美决策。**

系统层的执行方式（不是 UI 层的约定）见[创作者系统合同](creator-system-contract.md) §5.3：
`actions.allowedAt` 在 `suggest` 级别下拒绝一切 AI origin 的写动作，
Command Gateway 对高风险 Command 要求 `confirmation`。

## 9. 每加一个入口先回答三个问题

1. 它是否就是当前画布的「下一步」？是 → 放进当前卡片，不新建导航。
2. 它是否只是解释「这个结果怎么来的」？是 → 进生成记录 / 诊断，不占主路径。
3. 它是否与 Agent 能执行的同一 command 共用登记和实现？否 → **不能交付**。
