# 产品需求与界面简洁性收敛审查

- 状态：**当前整改依据（2026-09-04）**
- 性质：当前事实 + 可执行改进清单；不是历史流水账，也不是等待产品签字的闸门
- 关闭条件：本文“必须先闭合”全部完成且真实 Connected Project 验收通过后，提炼仍有效的
  合同到需求/当前架构，把本文移入 `docs/design/done/`
- 审查对象：分支 `change/TASK-109-three-pane`、基线提交 `180d09cfd645` 加当前工作树；
  重点是 Creator Studio（`mockups/motv-workspace/`）与它接入的工作流

## 1. 结论先行

**这个仓库已经有可靠的工作流底座，也已经走在正确的界面收敛方向上；但还不能说
“完整满足了最终实际使用需求”，也不能说界面已经整体简洁。**

目前最准确的产品定位是：

> 一个安全、可续跑、可版本化的核心工作流，加上一套功能较完整但仍标为
> **non-production prototype** 的 Creator Studio。

已经成立的部分：三栏骨架、首页项目管理、分页对话、作品/开发双窗口、自然语言能力
路由、故事开发四入口、剧集制作单画布入口，以及“不静默覆盖、缺事实就说不知道”的
底线。尚未闭合的部分集中在五处：

1. 长任务仍有同步旧路径，刷新后的运行恢复没有完整接到前端；
2. “出成片”仍可能把候选结果直接当成 Final，G4 审片闸门没有成为真正的导出前置条件；
3. “Agent 能做创作者能做的事”有一批动作实现，但缺少单一能力登记点和穷尽性证明；
4. 制作画布很简洁，深入后却重新出现旧制作台、工作区下拉、向导、溯源等多套导航；
5. 当前架构引用的 IA、若干 active 任务卡与真实代码互相矛盾，会继续把后续实现带回旧方向。

因此建议停止继续增加新页面和新面板，先用 5 个垂直切片把“能从头做到尾、刷新不丢、
状态不说谎、只有一条主路”闭合。

### 总体判断

- **核心工作流/安全性：基本满足。** Provider 中立、断点续跑、版本化输出、路径边界、
  付费关闭与失败如实返回是这套程序最扎实的部分。
- **已确认的近期 UI 需求：大部分主体已实现。** REQ-004～007 不是“没做”，而是其中
  两条关键承诺还缺端到端闭环：运行恢复、Agent 操作面全覆盖。
- **最终产品目标：尚未满足。** 用户还不能只沿一条简单路径，稳定地从真实项目走到
  经过审片的 Final。

## 4. 界面是否简洁好用

### 做对了的地方

1. 顶层只保留“故事开发 / 剧集制作 / 资产库”，认知入口比旧 11 阶段模型清楚。
2. 故事开发收成“故事核心 / 故事大纲 / 结构规划 / 正文创作”四项；剧集制作默认只露出
   “制作画布”。这是正确的信息架构方向。
3. 三栏位置稳定；Agent 始终在右侧，不再把“如何与 Agent 协作”散落成六个折叠面板。
4. 制作画布把集、当前阶段、下一动作和关键缺口放在一张卡上，比逐页寻找入口更接近
   创作者的任务心智。
5. 未知、缺媒体、不可用和未落地状态多数会明确说出来，没有用占位成功掩盖失败。

### 仍然不简洁的地方

| 问题 | 用户成本 | 具体修改意见 |
| --- | --- | --- |
| 默认入口简单，深入后恢复旧导航 | 用户必须同时理解“画布下一步、制作向导、工作区下拉、旧制作台、完整溯源” | 只保留画布的主路径；深层页用“返回本集画布 + 当前步骤”导航。`workbench` 内容并入镜头制作，`provenance` 并入诊断/生成记录；旧 route 只做重定向，不再成为独立产品面 |
| 右栏三块区域争高度 | 有待处理提案时，真正的对话历史反而最难看见 | 只钉住最新一条未决提案；其余以一行“还有 N 条”进入历史。输入框只占内容所需高度；给消息流设置可用高度下限 |
| 三栏只有桌面宽屏假设 | 1280px 或系统缩放后，中间工作区容易被两侧固定宽度夹窄 | 保留三栏语义，但提供“专注工作区”开关：左/右变为可唤回抽屉；明确支持的最小视口并做 125%/150% Windows 缩放验收 |
| 页面和能力描述分散 | 改一个页面名或能力，要同步导航、page map、事实采集、Agent action、Skill 输入、上游标签，多处测试各自绿也可能彼此不一致 | 落地“一份 Surface Manifest”：页面身份、标签、路由、选择上下文、可用 command、事实读取器和能力输入都从一处派生 |
| 缺少完整无障碍合同 | 图标按钮、弹层、焦点返回、键盘操作是否可用靠人工碰运气 | 所有弹层补 `role=dialog`、可访问名称、focus trap/return；纯图标按钮补 `aria-label`；主要路径只用键盘能完成；加入 axe smoke test |
| 画布坏了时可编辑但不保存 | 用户以为自己在工作，刷新后才发现全部丢失 | 保留 fail-closed，但页面顶部必须常驻错误条，禁用提交，并明确“当前改动不会保存”；对应 TASK-087 §6.10 |
| “生成记录”有文案承诺但入口不一致 | 用户被指向一个到不了的地方 | 选定唯一生成记录面：显示 Skill/版本/Runtime/Executor/Model/来源链；其余同名区只链接过去；对应 TASK-087 §5.13 |
| 审片只能通过/撤销，不能提出问题 | 用户发现问题却无法在同一闭环中留下问题并触发行动 | 把已有 `issue()` 接成明确的“提出问题”动作，进入 Feedback → Action；对应 TASK-087 §5.9 |

### 界面收敛原则

后续每加一个入口，都应先回答三个问题：

1. 它是否就是当前画布的“下一步”？如果是，放在当前卡片，不新建导航。
2. 它是否只是解释“这个结果怎么来的”？如果是，进入生成记录/诊断，不占主路径。
3. 它是否与 Agent 能执行的同一 command 共用登记和实现？如果不是，不能交付。

## 5. 必须先闭合的修改

下面按用户完成任务的阻塞顺序排序，不按代码层拆分。

### A. 长任务统一为异步、可刷新恢复

**已有承载：** [TASK-106](../../tasks/active/TASK-106-frontend-run-path-and-legacy-endpoint-retirement.md)

### C. 用一个 Surface/Command Manifest 兑现 Agent 操作面相等

要做：

完成判据：新增一个可逆 UI command 时，不额外编辑 Agent 白名单就自动可用；合同测试证明

要做：
