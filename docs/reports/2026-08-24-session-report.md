## 3. 这一轮最值得看的一条

本轮修掉的缺陷里最大的一族是**「守卫在它要守的东西消失时变绿」**（fail-open）。
它最难自己发现，因为**它表现为绿**。

最能说明问题的一次：TASK-074 那张「八条边界都有归属」的表原来**只查文件在不在**。
把它加严成「必须找得到那个具名测试」之后，**立刻抓到我自己写错的三条归属** ——
我指的三个文件里根本没有对应的测试。fail-open 守卫的真实代价就在这里：
**它连「登记本身是错的」都盖住了**。

所以本轮每加一道守卫都做**变异验证**（把缺陷人为放回去，确认守卫真的变红）。
**做了 20 次，其中 7 次第一轮活了下来** —— 每一次都是「我的守卫比它自己声称的弱」，
逐条补测试后才转红。三种形状：

- **测试描述了规矩却没断言它**（音频那条「片段绑不了批准就整步不通过」，
  我写了注释、写了 `assert.notEqual`，就是没断言真正的结论）；
- **走的是更早返回的那条路**（「集数出界补一个数」——我的用例在 JSON 读不出来时
  就 return 了，根本没到那一行）；
- **只看事后残留，没看过程中的窗口**（暂存目录建在扫描面里，`finally` 清理后
  事后看起来一样干净）。

**审查抓不到这一族**，因为它们表现为绿。只有变异能。

### 真跑之后暴露了两个真缺陷，都修了

- **版本号会倒退。** 删掉中间某一版后，新成片落回一个**低于当前最高版本**的号，
  而按「最高版本 = 当前成片」认产物的下游会把**刚做出来的那一版**当成旧结果。
  前端 G5 明明写着「版本只前进」，两条规则相反。
  **我最初把这个当「现状」钉进了测试**，还写了「往哪边统一需要一次判断」——
  codex 指出那不是两种都成立的设计，是缺陷。**把缺陷钉成期望值，是最不该做的
  一种「如实报告」。**
- **畸形文件名能把合成永久打死。** media/ 是创作者可控的写入面；一个
  `final-cut-v².mp4` 会让**每一次**合成都 500，删不掉就一直 500。
