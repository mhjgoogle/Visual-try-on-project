# REQ-006：对话里的 Agent 能做创作者能做的事，并且能把意见带回给开发

- 状态：CONFIRMED
- 来源：产品负责人 2026-08-29
- 相关 Change：[TASK-114](../tasks/done/TASK-114-agent-action-registry-and-feedback-loop.md)
- 相关 ADR：[ADR-0089](../adr/ADR-0089-conversational-agent-write-path.md)（对话式写路径，
  本 REQ 落在它的决策 2b/3 之上）

## 他说的原话

> 「我希望前端的对话框可以修改前端页面的设定好的和用户共同完成的内容。所以前端的
> agent 要做到可以定位现在所在页面的位置等。还有就是可以给后端反馈意见。比如页面
> 不合适了把意见收集起来。你再后端接收到反馈以后提出修改方案。」

> 「用户能够操作的前端的agent都应该可以操作。」

## 判据

1. **Agent 的可操作面 = 创作者的可操作面。** 界面上他自己能点的动作，Agent 都能做；
   做出来的结果与他自己点完全一致（同样的函数、同样的版本语义、同样的撤销方式）。
   判据不是「支持了几种编辑」，而是**加一个界面动作时，Agent 是否自动跟上** ——
   所以必须有一处**单一登记点**，而不是提示词、白名单、落地各写一份。
2. **它知道自己在哪。** 每一轮都带上他此刻的位置（空间 · 页面 / 当前分集 / 选中的镜头）
   以及**这一页能做什么**；他说「这个」「这一页」时不需要再解释一遍。
3. **能落的一定落，落不下的一定说。** 屏幕上「它说要改」与「已经改了」永远分开；
   没落下的要有出口，落下的要说清成了第几版。
4. **意见有去处。** 他说「这个页面不合适」时，那不是对作品的改动，而是对**应用**的
   意见 —— 要被收集起来，并且**后端的开发 Agent 真的读得到**，据此提修改方案。
5. **可逆是前提，不是事后补救。** 能自动做的都是可逆动作（写成新版本、旧版一字不动）；
   不可逆的（删除、绑定剧集身份）与花钱的，仍然由他自己点。

## 不在范围内

- 删除类动作自动化（第 13 条：不静默删用户的东西）
- 付费/生成类动作自动化（AGENTS.md §1：花钱是唯一必须问的事）
- 「确认分集规划」这类会绑定实体身份、反悔不干净的闸门
- 一个把意见变成任务卡的自动流水线：**读取**是自动的，**要不要做、怎么做**仍然是
  开发时的判断

## 验收（TASK-114 交付时实测）

- 说「把故事大纲的一句话故事改成 X」→ 文档里出现 `大纲 v2`（`origin: developed`，
  来历记着他那句话），`v1` 一字未动
- 说「这个页面版本太多了，我只想看最新版。这条是对应用的意见」→ 意见进台账，
  屏幕回「已记下这条意见（#1）」；后端 `python .claude/tools/read_feedback.py`
  读得到「说的是 / 他要的是 / 在哪个项目哪一页」
