## v1 — CONFIRMED（2026-09-14）

### 他说的原话

> 「我希望这个app能先完成 AI 小说自动创作工作流，再将小说内容连接到视频生产流程。」

这是一句 **Milestone 级**的话（AGENTS.md §1 前三层归产品负责人）：它重新指定了
当前交付面的顺序 —— 先长出「写小说」这条完整的链，再把它接到已经存在的视频线上。

### 用户真正需要什么

**一个想法进去，一本小说出来，然后这本小说能被拍成片。**

他不是要一个「有 AI 按钮的写作软件」。他要的是这条链**自己会往前走**：他给方向、
看结果、不满意就改，而不是自己坐在四个大文本框前把故事核心、大纲、结构、正文
一个字一个字敲出来。写完之后，这本小说不是一个死文件 —— 它是视频生产的上游，
接着往下就是分集、剧本、拆解、资产、分镜。

### 为什么现在做不到（2026-09-14 实测代码）

产品的骨架已经在：故事开发四入口、`FORMS = ["novel", "episode"]`、章节的版本与
「不静默覆盖」都实现了。**缺的是小说那一侧的能力，以及两侧之间那道真实的门。**

| # | 断点 | 证据 |
| --- | --- | --- |
| 1 | 小说模式下 AI 写不了正文 | `mockups/motv-workspace/src/app.js` `proposeScript`：`work.form !== "episode"` 直接返回错误 |
| 2 | 没有写小说的能力包 | `product-skills/builtin/` 28 个 Skill 全是影视向；`script-writer` 产出的是可拍剧本，不是章节正文 |
| 3 | 「→ 进入剧集创作」是假入口 | `src/ui/draftws.js`：只发 `data-form="episode"`，一个字都不转换 |
| 4 | 三类用户能力没有小说的落点 | `product-skills/user-capabilities.json`：「制作这一集」的 scope 是 `episode` / `shot` |

### 一个可观察的验收例子

他在一个空项目里说：「帮我写一本关于深海考古队发现一座会说话的城市的小说，12 章。」

- 故事核心、大纲、结构规划依次被写出来，每一步他都看得到、能改、能退回上一版；
- 到正文创作，形态是**小说**，Planned Chapters 是 12；
- 他说「接着往下写」，第 1 章正文出现 —— 是叙述、描写和对话混排的**小说**，
  不是「场景 1 · 内景 · 潜水舱 —— 白天」这种剧本格式；
- 他让它一直写到第 5 章，中途改了第 3 章的一段，第 4、5 章接着他改过的写；
- 12 章写完，他说「把它做成剧集」，得到一份「第几集对应第几章到第几章」的提案；
- 他确认后进入剧集创作，**小说正文一个字没被动过**，接着就是剧本 → 拆解 →
  资产 → 分镜，走的是已经存在的那条视频线。

### 验收判据

1. **小说模式下「写这一章」真的会写。** 当前打开哪一章就写哪一章；一章都没打开时
   说清楚要先打开哪一章，**不猜**（现在是直接拒绝）。
2. **写出来的是小说，不是剧本。** 章节正文是叙述 / 描写 / 对话混排的散文，
   由一个专门的能力包产出，不复用 `script-writer`。
3. **每一步都能让 AI 做，也都能被他改。** 故事核心 → 大纲 → 结构规划 → 章节正文，
   四步都有「让 AI 来」的路径；产出一律是提案，照旧过 schema、照旧版本化、
   照旧可退回（不推翻 REQ-007 判据 3）。
4. **能连着往下写，也能停。** 他可以让它从当前进度连续写若干章；中途可停、可改，
   **已经写下的不会被重跑覆盖**（AGENTS.md §11/§12 断点续跑 + §13 不静默覆盖）。
5. **一本小说能变成一部剧集。** 产出「哪一集对应哪几章」的分集提案，他确认后
   进入剧集创作；转换是**加法**，原小说正文与版本历史一个字不动。
6. **转过去之后接的是已有的视频线。** 剧本 → 拆解 → 基础资产 → 分镜 → 生成，
   **不为小说另建一条平行生产链**，不新增一级或二级页面（ADR-0066 闭集不动）。
7. **不花钱的步骤自动跑，花钱的照旧停在闸前。** 文本创作走本地订阅运行时；
   任何图片 / 视频生成仍受 AGENTS.md §1 与付费门约束，不因「自动工作流」被带进去。

### 本次边界与必要假设

**假设（我定的，可逆，不满意就改）**：「自动」= **每一步一键 + 能连着跑 + 人随时
可以插手**，不是「按一次键出一整本书、中途不可干预」。理由：后者与第 13 条
「不静默覆盖」直接冲突，而且他在第 3 章就发现方向不对时，前面那次全自动等于全废。
这个假设先做出来给他看，他要真正的一键成书再改。

**不在范围内**：

- 小说的导出格式（epub / txt / 排版）—— 本需求到「小说在产品里成立」为止；
- 多人协作、连载发布、读者反馈这类小说平台能力；
- 新的一级 / 二级页面（ADR-0066 十一页闭集不重访）；
- 为小说新建第二套故事真相（Story Bible 副本）—— 小说与剧集读写同一份故事数据；
- 付费生成能力的自动化（AGENTS.md §1：花钱是唯一必须问的事）。
