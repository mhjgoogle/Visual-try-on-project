# REQ-004：全站统一三栏 —— 左控制/选择 · 中工作区 · 右 Agent 对话

- 状态：CONFIRMED
- 相关 Change：TASK-109

## v1 — CONFIRMED（2026-08-27）（superseded by v2）

- 来源：产品负责人 2026-08-27 —— 「AI导演哪个板块变成像 claudecode 一样的对话框
  就好了」「所有页面分割三个板块就好了。不然太乱了。左边控制和选择，中间工作区。
  右边和 agent 的对话框。」

- 用户真正需要什么：**界面骨架在每一页都一样**，且右边那一栏是一个真正的对话框
  （像 Claude Code 那样：上面是对话流，底部是输入框），而不是一叠折叠面板。
  他要的是「换页时不用重新找东西」，以及「跟 Agent 说话」这件事有一个固定的地方。

- 为什么：现在列数按空间变 —— `#production` 基础是 3 栏（`200px / 1fr /
  280–340px`），而剧集制作是 **4 栏**（`152px / 316px / 1fr / 300–340px`），
  资产库又是 3 栏。骨架每页一变，创作者每换一页就要重新定位；右栏又是
  「常驻会话 + 这一镜怎么办 + 当前状态 + 导演观察 + 能力 + 生成」六段折叠面板堆叠，
  于是「跟 Agent 说话」没有一个稳定的位置。

- 验收判据（产品视角，非测试清单）：
  1. 每个页面都是**恰好三栏**，列数不随页面变化；
  2. 左栏只承担**控制与选择**（页面导航 + 选择器/检查器）；
  3. 中栏是**工作区**；
  4. 右栏是**与 Agent 的对话**：输入框固定在底部，上方是可滚动的对话流；
  5. **现有能力不得因为布局变化而消失** —— 面板可以搬家、可以折叠，不能不见
     （批次 A 的教训：一次性替换是能力静默消失的方式）；
  6. Agent 的回复与执行步骤在对话流里**逐步可见**（依赖读取运行状态的机制，
     即 TASK-106 记着的那个缺口）。

## v2 — CONFIRMED（2026-08-27）· supersedes v1

- 来源：产品负责人 2026-08-27 —— 「AI导演台不需要了。根本用不上。直接给我做一个
  像现在一样的对话框。能和你对话。你直接在后台收集信息修改行不行」

- 相对 v1 的 delta（只写变化）：

  1. **v1 判据 5 作废**：右栏的「AI 导演台」（这一镜怎么办 / 当前状态 / 导演观察 /
     能力 / 生成 六段折叠面板）**不再需要保留**。产品负责人明确说用不上 ——
     「面板不许消失」这条是我按迁移纪律加的保守判据，不是他的要求。
  2. **右栏 = 一个对话框，别无其它**：形态对标他现在正在用的 Claude Code 对话 ——
     消息流 + 输入框，没有面板堆叠。
  3. **对话的另一端是能干活的 Agent**（新增判据）：他在框里说一句话，Agent
     **自己去后台收集需要的信息**（项目状态、文档、资产、运行记录），然后
     **自己把改动做掉**，并在对话里说明做了什么 —— 不是「把结构化表单填对才肯跑」。
     这与现状相反：今天的会话明文拒绝把散文送进 Prompt（「你写的文字不会进入这次
     运行的 Prompt」），因为 Skill 的输入是声明式的。
  4. v1 判据 1–4（三栏骨架、左控制/选择、中工作区、右对话+输入固定在底）**不变**。

- 为什么：v1 我把「不许删面板」当成了硬判据，于是右栏成了「对话框 + 六段面板」的
  混合体 —— 而他要的是对话本身。他从没用过那六段面板。
