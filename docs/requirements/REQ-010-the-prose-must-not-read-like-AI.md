## v1 — CONFIRMED（2026-09-18）

### 他说的原话

> 「帮我找些去AI味的写小说的skill给装上」

### 用户真正需要什么

**他要的不是「多一个能力」，是产出别一眼就能看出是机器写的。** 这条需求的位置很清楚：
REQ-009 交付的是「一个想法进去、一本小说出来」这条链；链通了之后，下一个会让他放弃这个
产品的东西就是**文字本身的味道** —— 章节能自动写出来，但读两段就知道不是人写的，那这条
链的产物就没有用。

### 为什么现在做不到（2026-09-18 实测，证据是真模型的真产出）

不是凭印象。用应用自己的执行器把 `novel-chapter-writer` v2 的真实提示词跑在真 claude 上，
拿回 2362 字的一章（TASK-152 §7 的那次走查），逐条数出来：

| 形状 | 实测 | 例子 |
| --- | --- | --- |
| **三短句排比** | 61 段里 **27 处** | 「她把手收回来，攥成拳，再松开，掌心是潮的。」 |
| **明喻** | 10 处 | 「像那一格从来没有人在上面写过字」「像已经在这个温度里待了很多年」 |
| **「不是 X，是 Y」对举** | 2 处 | 「不是路灯，是……」「不是被戳穿的那种变，是……」 |
| **段落长度单一** | 平均 38 字，几乎没有长段 | 整章都是同一个短促节奏 |

**这一章本身不差**（结尾落在对话与动作上，没有升华段）—— 问题是**节奏被压成一个模式**：
句子长度、段落长度、修辞密度全都不变。人写的小说不是这样：有长有短，有铺陈也有急刹。

公开资料里关于「AI 味」的共识与这三条互补，也一并采纳：**用具象细节代替空泛形容词**、
**一句话只说一件事**、**用动作暗示情绪而不是直接点明**（见本文件末尾的参考）。

### 一个可观察的验收例子

他在小说项目里看完 AI 写的第 3 章，觉得「太像 AI 写的」，于是在对话里说：

> 「这一章太有 AI 味了，改一下」

- 应用**选中的是去味的那个能力**，不是重写一章的小说家（他不想要一章新的，他要这一章变好）；
- 拿回来的是**这一章去味后的正文** + **改了哪几处、为什么**的清单；
- 他点「用它」→ 正文落回第 3 章，**原来那一版先存成历史**，不满意可以退回去；
- 读起来：段落有长有短，情绪靠动作与细节透出来，而不是靠「……得让人心慌」这类直陈。

### 验收判据

1. **有一个专门去味的能力**，它读的是**这一章已有的正文**，产出**同一章的去味版**，
   而不是另写一章。
2. **它说得出改了什么**：每一处改动带「原来那句 / 现在这句 / 为什么」，让他能判断这次改动
   是不是把味道改没了、也把味道之外的东西改掉了。
3. **落回原处，可退回**：走既有的正文写路径 —— 覆盖前自动存一版，历史可恢复
   （不推翻 REQ-007 判据 3 / AGENTS.md §13）。
4. **说「写这一章」仍然是写新的**：去味能力不得抢走创作类的路由；说「改一改这一章的文字」
   才落到它。
5. **写的时候就少带味**：`novel-chapter-writer` 的提示词把上面实测的三条写成硬约束
   （节奏要有变化、明喻克制、不用「不是 X 是 Y」对举、结尾不升华）。
6. **剧集那一侧不受影响**：这条需求只管小说正文；剧本有它自己的 `script-doctor`。

### 本次边界与必要假设

**假设（我定的，可逆，不满意就改）**：

- 「AI 味」按上面那张实测表定义 —— **可数的形状**，不是「感觉不对」。这样它才能被写进
  提示词、被 reviewCriteria 检验、被他当场指出对错。
- 去味是**一次整章重写**（保留情节、人物、信息，只换写法），不是逐句标注。理由：他要的是
  能用的那一版；想看逐条理由，改动清单里有。
- **不做自动判分**（比如「AI 味 78 分」）。一个算出来的分数会立刻变成新的优化目标，而它
  度量的只是我列得出来的那几种形状。

**不在范围内**：

- 剧本 / 分集 / 大纲的去味（只做小说正文这一步）；
- 「学他的文风」（需要他的样本与一套个人风格档案，是另一条需求）；
- 任何自动判分或 AI 检测率指标。
