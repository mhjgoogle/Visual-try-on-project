# REQ-011：在应用里说一句，它就被做出来

- 状态：CONFIRMED
- 相关 Change：TASK-160
- 相关 ADR：[ADR-0107](../adr/ADR-0107-development-instructions-run-with-tools-in-the-repo.md)
  （开发指令那一轮有工具、在仓库里跑；创作能力那一轮**一个字都不动**）
- 姊妹需求：[REQ-006](REQ-006-agent-can-do-what-the-creator-can-do.md) 判据 4/6/7
  管的是**意见去得了**（他提的话进得了台账）；这一条管的是**指令回得来**
  （他提的话变得成改动）。两条合起来才是一条闭合的回路。

## v1 — CONFIRMED（2026-09-19）

### 他说的原话

> 「那谁启动你去看」
> 「那能不能我和前端沟通完了。通过我的指令驱动后端来做」

### 他为什么问这个

我告诉他「我不常驻，你提意见时我可能没在跑」。他立刻问到了要害：**谁来叫醒开发**。

答案当时是「没有人，只有你」。证据在台账里：**13 条待处理意见，4 条躺了 21 天、
9 条躺了 20 天**。它们不是被判断为不做，是根本没人去看 —— REQ-006 判据 4
「意见有去处」在纸面上成立，在事实上不成立，因为「去处」的另一头没有人。

### 用户真正需要什么

**他在应用里说完一句话，就能看到它被真的做出来并上线，不必自己去开一个开发会话。**

不是「更快地写出一份方案」—— 那个已经有了（`dev.request`）。是**真的改**：
代码改了、测试跑了、提交进去了、他刷新页面看到的就是新的。

### 一个可观察的验收例子

他在「开发」窗口说：「结构规划的表头「主要人物」改成「登场人物」。」

- 应用立刻回一句「已交给开发，正在做」，并在提案里出现一条占位；
- 几分钟后那条占位变成「做完了：结构规划表头现在写着「登场人物」，正文简报里
  那块跟着改了；字段和数据一个字节没动。提交 `a1b2c3d`。」；
- 他刷新页面，表头就是「登场人物」；
- 仓库里有一个可回滚的提交，跑过测试、过了 git 闸门。

### 验收判据

1. **说一句就动起来。** 他在「开发」窗口说一句要求，应用起一轮**真的会改仓库**的
   开发；屏幕上立刻有「正在做」，不必他去别处开会话。
2. **只有「开发」窗口能触发。** 作品窗口里说同样的话不会启动它 —— **服务端强制**，
   不是模型自觉（与 REQ-007 判据 4 同一道闸，方向相反）。
3. **作品内容一个字都不进它的提示词。** 它拿到的只有他这句话和他在哪一页。
   故事、大纲、正文、人物一概不带 —— 那是注入面，理由见 ADR-0107。
4. **一道闸都不少，越界要被发现。** 那一轮走完整的开发流程：改动 → 测试 →
   git 提交闸门 → 可回滚的提交；指令上要求它不碰 main、不合并、不 force push。

   > **订正（2026-09-19，codex 轮 1 的 BLOCKING）。** 原文写的是「它**不碰** main」，
   > 那是一句做不到的承诺：那一轮握着仓库写权限，能 checkout、能 push、能改钩子。
   > 真正成立的判据是 —— **每一轮结束都核对分支与 main 有没有被动过，动了就在
   > 他眼前逐条说出来**（起跑前记快照，落地时比对）；核对不了就说「没核实过」，
   > 不说「没问题」。硬隔离（一个会话一棵 worktree）是 TASK-143 的事。
5. **做完要说人话。** 结果作为提案回到他的「开发」窗口，写的是**他在屏幕上看得到
   的变化**（现在这样 / 改完这样 / 什么不变），外加那个提交的短 hash。
6. **失败必须说出来，而且不许顺口说「仓库没事」。** 跑挂了、超时了、闸门拦了，
   都要如实写进那条提案并说清原因；**绝不能停在「正在做」**，那在屏幕上与
   「它把我晾着」无法区分。**失败那一轮到底有没有动过仓库，要去真的看一眼再说**
   —— 超时打断的是进程，不是它已经做过的事（codex 轮 1 的 BLOCKING：原实现
   写死一句「仓库没有被改动」，那是编的）。
7. **不花他没同意的钱。** 这一轮走本地订阅额度，且**只有他说话才跑** ——
   没有定时轮询、没有后台常驻。

### 本次边界与必要假设

**假设（我定的，可逆）**：一次只跑一轮。他连说两句，第二句排队而不是并发开两个
会话去改同一棵树 —— 两个自动 Agent 同时改一个共享工作树，是已经付过学费的那类
事故（TASK-087 §5.31）。

**不在范围内**：

- **合并到 main** —— 这一轮只在 change 分支上提交推送。合并仍按 AGENTS §22 走；
- **定时 / 轮询唤醒** —— 他明确要的是「我的指令驱动」，不是「它自己醒」。
  定时唤醒会在他没用的时候持续烧配额，换来的只是把「躺 20 天」变成「躺 12 小时」；
- **让应用进程自己改源码** —— 边界没变：改动仍然由一个完整的开发 Agent 会话执行，
  那一轮该走的测试、闸门、提交一样不少（ADR-0107 决策 1）；
- **付费 API** —— 本地订阅额度，AGENTS §1 的付费闸不动。
